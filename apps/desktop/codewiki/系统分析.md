# 整体布局与样式系统分析

> 本文档基于 `apps/desktop` 当前代码（Electron + React 19 + Tailwind CSS v4 + shadcn/ui）整理，
> 描述桌面端实际布局框架、响应式策略、主题令牌、排版与样式组织方式。
> 文档与代码现状保持一致；如代码演进，请同步更新本文。

---

## 1. 总体架构

### 1.1 渲染端入口链

```
renderer/src/main.tsx
  └─ <App />                                // App.tsx
      ├─ <TooltipProvider delayDuration={200}>
      ├─ <HashRouter>                       // 桌面端使用 HashRouter
      │   └─ <Routes>
      │       └─ <Route element={<RootLayout />}>   // 布局壳，唯一根布局
      │           ├─ <Route index element={<ChatPage />} />          // /  → 聊天（默认）
      │           ├─ <Route path="/home" element={<HomePage />} />   // /home  → 欢迎页
      │           └─ <Route path="/workspace" element={<WorkspacePage />} /> // /workspace → 工作区
```

关键点：

- **根布局唯一**：`RootLayout`（`src/renderer/src/layouts/RootLayout.tsx`）是唯一布局壳，
  通过 `<Outlet />` 渲染子路由。已不存在 `MainLayout` / `GlobalHotkeys` / `useInit()`。
- **快捷键收敛**：键盘快捷键统一由 `useKeyboardShortcuts` hook（`src/renderer/src/hooks/useKeyboardShortcuts.ts`）管理，
  在 `RootLayout` 内注册（⌘/Ctrl+B 切换右面板、⌘/Ctrl+N 新建任务，输入态不拦截）。
- **App 启动职责**：主题初始化（`useAppStore.initTheme`）、平台探测（IPC → `platformAtom` → `<html data-platform>`）、
  全屏态订阅（→ `<html data-fullscreen>`）、API baseURL 恢复、认证引导、macOS 原生菜单动作转发。

### 1.2 布局相关代码分层

| 层 | 职责 | 关键文件 |
|---|---|---|
| `layouts/` | 布局壳与标题栏 | `RootLayout.tsx`、`TitleBar.tsx`、`MacTitleBar.tsx` |
| `platform/` | 平台差异化逻辑与 CSS 变量 | `useResponsiveLayout.ts`、`usePanelToggle.ts`、`layout-tokens.css` |
| `components/sidebar` / `context-panel` / `layout` | 三大区域内容与通用组件 | `Sidebar.tsx`、`ContextPanel.tsx`、`Drawer.tsx` |

## 2. 区域划分（布局框架）

### 2.1 窗口视觉模型

```
┌────────────────────────────────────────────────────────────┐
│ TitleBar（absolute 覆盖窗口顶部；macOS 左区透明）                 │  ← z-20
├───────────┬────────────────────────────────────────────────┤
│           │  ┌──────────────────┬─────────────────────────┐ │
│ Sidebar   │  │ 中栏白色圆角卡片   │ 右栏白色圆角卡片           │ │
│（灰底，    │  │ ChatHeader        │ ContextPanel            │ │
│ 贴左/顶/底） │  │ + Outlet          │ （任务流水线）             │ │
│           │  └──────────────────┴─────────────────────────┘ │
│           │  ↑ 卡片四周 5px 灰色沟渠（透显 bg-sidebar）           │
└───────────┴────────────────────────────────────────────────┘
```

实现要点（与 `RootLayout.tsx` 一致）：

> ⚠️ 注意：`RootLayout.tsx` 头部块注释仍残留「6px」「6px 沟渠」「ResizableHandle 宽 6px」等历史口径，
> 实际代码已统一为 **5px（卡片四周）** 与 **1px（ResizableHandle）**。本节描述以代码实际取值为准，
> 待后续清理头部注释。

- **窗口底色始终为 `bg-sidebar`（灰色）**，作为沟渠/边框色。
- **Sidebar 是 absolute 定位的普通 div**，非 ResizablePanel：
  `absolute top-0 left-0 bottom-0 bg-sidebar`，
  `style={{ width: sidebarVisible ? 262 : 0, paddingTop: sidebarVisible ? 'var(--titlebar-h)' : 0 }}`，
  以 CSS 宽度 0↔262px 切换显隐（`transition-[width] duration-200`），标题栏高度仅展开时生效。
- **白色卡片容器 absolute 定位**：`top:5px; right:5px; bottom:5px; left: sidebarVisible ? calc(262px + 5px) : 5px`。
- **可拖拽仅中栏与右栏**：`ResizablePanelGroup autoSaveId="pioneering-main-layout-2p-${platform}"`
  内始终渲染 `center` 与 `context-panel` 两个 Panel，右栏 `collapsible collapsedSize={0}` 实现折叠。
- **ResizableHandle 宽 1px 透明**（`w-px bg-transparent hover:bg-primary/40 transition-colors shrink-0 rounded-sm`），
  hover 显 `bg-primary/40` 高亮线。**非历史注释中的 6px**。
- **每个 Panel 内部包裹白色圆角卡片**：`bg-background shadow-sm ring-1 ring-black/5 dark:ring-white/5`，
  圆角由 `style={{ borderRadius: 6 }}` 设置（即 `rounded-[6px]`）。

### 2.2 三大区域职责

| 区域 | 组件 | 职责 |
|---|---|---|
| 左栏 Sidebar | `Sidebar.tsx` | 品牌栏 + 导航（助理/技能/插件/自动化/更多，placeholder）+ 任务/空间分组 + 会话列表（`ConversationList`）+ 账户区（主题切换/设置/登录态） |
| 中栏 | 白卡片内 `ChatHeader`（内联于 RootLayout）+ `<Outlet />` | 顶部会话标题栏（搜索/分享/历史/右面板开关），下方渲染路由页面（默认 `ChatPage` → `ChatArea`） |
| 右栏 ContextPanel | `ContextPanel.tsx` | 「任务流水线」：header（标题 + 阶段徽章 + 收起）+ body（`TaskPipeline` 时间轴）+ `ArtifactPanel`；阶段由 `derivePhase` 推导（error > executing > thinking > done > idle） |

### 2.3 顶部标题栏（TitleBar）

`TitleBar.tsx` absolute 覆盖顶部（`top-0 z-20`，高度 `var(--titlebar-h)`），按平台分支：

| 平台 | 行为 |
|---|---|
| macOS | 仅左区：`left-0 bg-transparent pointer-events-none`，渲染 `MacTitleBar`；右侧由原生红绿灯占位（`--traffic-light-w: 72px`） |
| Windows / Linux | `inset-x-0 bg-sidebar pointer-events-auto`，渲染内联应用菜单（基于 `shared/menu-template`）+ 右侧自绘 `WindowControls` |

- **窗口拖拽不用 `-webkit-app-region`**（避免拦截点击），改由纯 IPC 鼠标事件：`windowApi.startDrag / moveDrag / endDrag`。
- macOS 下白色卡片空白区也可拖拽：`RootLayout` 的 `handleCardMouseDown`（仅 `isMac`），排除按钮/输入框。

## 3. 布局模式（三栏 / 覆盖抽屉）

### 3.1 双模式切换

`useResponsiveLayout`（`platform/useResponsiveLayout.ts`）按窗口宽度决定：

```ts
const mode: LayoutMode = width < breakpoint ? 'overlay' : 'three-column'
```

- **`three-column`（≥ 断点，默认）**：左 Sidebar + 中卡片 + 右卡片三栏，两 Panel 可拖拽。
- **`overlay`（< 断点）**：单白色卡片全宽，Sidebar / ContextPanel 转 `Drawer`：
  - 卡片容器 `p-[5px]`，`paddingTop: isMac ? '5px' : 'var(--titlebar-h)'`（Win/Linux 避让标题栏）。
    macOS 即使全屏也用 `5px`（红绿灯隐藏后 `MacTitleBar` 仍占位但 `bg-transparent pointer-events-none`，无需避让）；
    Win/Linux 全屏仍需避让标题栏（`--titlebar-h` 在全屏态保持 48px 不变）。
  - Win/Linux 且侧边栏折叠时显示 `TopBarActions`（展开侧边栏 / 新建任务 / 展开右面板），macOS 由 `MacTitleBar` 承担。
  - `<Drawer open={sidebarVisible} side="left" />`、`<Drawer open={contextPanelVisible} side="right" />`。

### 3.2 面板开关统一入口 `usePanelToggle`

`platform/usePanelToggle.ts` 跨模式统一开关逻辑：

- 内部调用 `useResponsiveLayout()` 取 `mode`，消费 `sidebarVisibleAtom` / `contextPanelVisibleAtom`。
- **三栏模式**：`contextPanelVisible` → `contextRef.current.expand() / collapse()` 驱动右栏；
  侧边栏由 atom → CSS 宽度控制（不驱动 ResizablePanel）。
- **覆盖模式**：仅翻转 atom，由 `Drawer` 读取。
- 返回 `{ contextRef, toggleSidebar, toggleContext, mode }`，其中 `mode` **透传自 `useResponsiveLayout()`** 而非内部派生；
  toggle 经 `useCallback` 稳定引用（`toggleSidebar` 仅翻转 atom，不直接调用 ResizablePanel API）。

### 3.3 Drawer 组件

`components/layout/Drawer.tsx` 轻量覆盖抽屉（无第三方依赖）：

- 遮罩层 `fixed inset-0 z-40 bg-black/40`。
- 面板 `fixed bottom-0 z-50`，`top: var(--titlebar-h)`（自标题栏下沿开始），宽 320px，`transform` 过渡滑入滑出。
- `open` 时监听 `Escape` 关闭。

## 4. 尺寸令牌

### 4.1 布局常量

| 常量 | 值 | 用途 |
|---|---|---|
| `SIDEBAR_WIDTH`（RootLayout 内联） | 262px | 侧边栏展开宽度 |
| `LAYOUT_BREAKPOINT_MAC` | 980 | macOS 三栏/覆盖断点 |
| `LAYOUT_BREAKPOINT_DEFAULT` | 1080 | Win/Linux 三栏/覆盖断点 |
| `CONVERSATION_ROW_HEIGHT` | 34 | 会话列表虚拟化行高 |
| `CONVERSATION_LIST_OVERSCAN` | 8 | 会话列表 overscan |

### 4.2 平台布局令牌（`platform/layout-tokens.css`）

由 `<html data-platform="mac|windows|linux">` 驱动，组件层只消费语义变量：

| 变量 | 默认 | macOS | Windows | Linux | 说明 |
|---|---|---|---|---|---|
| `--titlebar-h` | 48px | 48px | 48px | 48px | 标题栏高度 |
| `--titlebar-leading` | 0 | 0 | 8px | 4px | 标题栏左端留白 |
| `--titlebar-trailing` | 0 | 0 | 0 | 0 | 标题栏右端留白 |
| `--traffic-light-w` | 0 | 72px（全屏 0） | 0 | 0 | 红绿灯占位宽度 |
| `--radius-control` | 8px | 6px | 8px | 6px | 控件圆角 |
| `--scrollbar-size` | 10px | 6px | 12px | 12px | 滚动条粗细 |
| `--density` | 1 | 0.96 | 1 | 1 | 整体缩放密度 |

- macOS 全屏 `[data-fullscreen='true']` 将 `--traffic-light-w` 置 0（其余令牌不变，`--titlebar-leading` 仍为 0、`--titlebar-h` 仍为 48px）。
- `data-platform` / `data-fullscreen` 由 `App.tsx` 在启动与全屏态变化时写入 `<html>`。

### 4.3 内容列宽令牌（`components/chat/input/pro-input.css`）

```css
:root {
  --chat-col-max: 880px; /* 中间栏统一列宽：内容展示区 / 输入区 / 欢迎页共用 */
}
```

- `.pro-input-inner`：`max-width: var(--chat-col-max); margin: 0 auto` 居中。
- `.pro-input-area`：`container-type: inline-size`，供子元素按容器宽度响应式适配。

## 5. 响应式断点

- **断点来源**：`useResponsiveLayout` 按平台读取 `LAYOUT_BREAKPOINT_MAC(980)` / `LAYOUT_BREAKPOINT_DEFAULT(1080)`。
  Win/Linux 无原生边框，在更宽处才退化为覆盖布局。
- **resize 合并**：`window.resize` 经 `requestAnimationFrame` 合并，避免拖拽窗口时整树频繁重渲染；
  卸载时 `cancelAnimationFrame` 清理。
- **布局切换语义**：`width < breakpoint → overlay`（抽屉），否则 `three-column`。
- 页面内另有少量 Tailwind 断点（如 HomePage 功能卡片 `md:grid-cols-2`）。

## 6. 主题色彩

### 6.1 令牌体系（`index.css`）

shadcn/ui 语义令牌 + Tailwind v4 CSS-first 配置：

- 头部 `@import url('https://fonts.googleapis.com/css2?family=Public+Sans:wght@300;400;500;600;700;800&display=swap')`
  同步拉取 Google Fonts；离线/无外网环境下字体加载失败会回退到系统字体栈（不影响布局，但首屏可能字体闪烁）。
- `@import "tailwindcss"`；`@theme inline` 将 CSS 变量映射为工具类
  （`--color-background`、`--color-primary`、`--color-sidebar` 等），组件直接使用 `bg-background` 等。
- `:root` **亮色**（New York 风格 · Neutral base · Small radius）：
  - `--radius: 0.375rem`，圆角阶梯 `--radius-sm~4xl` 派生。
  - 主色为 oklch 中性灰：`--primary: oklch(0.205 0 0)`、`--muted: oklch(0.97 0 0)` 等。
  - **Sidebar 特殊**：亮色 `--sidebar: #e5e7eb`（hex），其余 oklch。
- `.dark` **暗色**（oklch 深灰背景 + 亮前景），`@custom-variant dark (&:is(.dark *))`。
- 明暗切换由 `useAppStore` 管理，主题模式支持 `light / dark / system`。

### 6.2 圆角与高亮

- 卡片圆角统一 `rounded-[6px]`；控件圆角用 `--radius-control`。
- 输入卡片 `.pro-input-card`：`border-radius: 20px`（web 端风格移植）。
- `.chat-markdown` 与 `.artifact-view` 共用 GitHub Light/Dark 两套 hljs 配色，集中维护于 `index.css`。

## 7. 字体排版

### 7.1 字体栈（按平台条件覆盖）

- 默认（无 `data-platform` 覆盖时）：`'Public Sans', ui-sans-serif, system-ui, sans-serif`（Google Fonts 拉取）。
- `[data-platform='mac']`：`-apple-system, BlinkMacSystemFont, 'SF Pro Text', 'Public Sans', ui-sans-serif, system-ui, sans-serif`
  （`Public Sans` 作为第 4 顺位回退，mac 优先用系统字体）。
- `[data-platform='windows']`：`'Segoe UI', 'Public Sans', ui-sans-serif, system-ui, sans-serif`（`Public Sans` 第 2 顺位）。
- `[data-platform='linux']`：与默认一致（`'Public Sans', ui-sans-serif, system-ui, sans-serif`）。

定义于 `@theme inline` 的 `--font-family-sans`，`body` 消费，`font-sans` 工具类同步生效。

### 7.2 字号层级（对话区 `.chat-markdown`）

| 元素 | 字号 / 行高 | 备注 |
|---|---|---|
| 正文 `p` | 15px / 1.75 | `my-2.5` |
| `h1` | text-xl semibold | `mt-5 mb-2.5` |
| `h2` | text-lg semibold | `mt-4 mb-2` |
| `h3/h4` | 15px semibold | `mt-3.5 mb-1.5` |
| 行内代码 `code` | 0.85em，`bg-muted` | 与代码块区分 |
| 代码块 | 13px / 1.65 | Consolas/Monaco/Menlo 栈，`tab-size: 4` |
| 列表 `ul/ol` | `space-y-1.5 pl-5` | list-disc / list-decimal |

- 会话标题（ChatHeader）：16px `font-semibold`；表格：text-sm，`th` semibold。

## 9. 样式组织

| 文件 | 职责 |
|---|---|
| `renderer/src/index.css` | 入口：Google Fonts `@import`、Tailwind v4、主题令牌（亮/暗）、`.chat-markdown`、hljs 配色、平台字体、滚动条隐藏 |
| `renderer/src/platform/layout-tokens.css` | 平台布局令牌（`data-platform` / `data-fullscreen` 驱动） |
| `renderer/src/components/chat/input/pro-input.css` | 输入框 web/pro 视觉规范 + `--chat-col-max` |
| 组件内联 Tailwind 类 | 局部布局与视觉（`cn()` 合并） |
| `components/ui/` | shadcn 基础组件自带样式 |

约定：

- 组件层不硬编码平台值，一律消费语义 CSS 变量或 `usePlatform()`。
- 主题只消费语义令牌，无字面量颜色（除 hljs 高亮与 sidebar 底色）。
- 全局样式（markdown 排版、高亮）收口 `index.css`。

4. **删旧分支**：观察期无问题后，删除 `MessageList` 硬分支、3 个 legacy 滚动 `useEffect`、及 `messageScroller` 系列子配置（`scrollLastAnchor`/`scrollAnchorTurns`/`scrollJumpButton`）。
5. **清理死代码**：删除未接入的 `contextCompression`、纯 dev 的 `devStressMessages`/`devStressCount`；`mermaidPreview` 作为 kill switch **永久保留**，不纳入收敛。

### 问题 4：流式渲染 O(n²) 字符串拼接

- **现象**：流式消息处理中，流式文本/工具调用的累积曾依赖 `chatStore` 内的逐条拼接；
  `buildTraceFromContentBlocks`（现已外移至 `services/trace-builder.ts`）为历史消息重建 Trace 树时
  采用从 `contentBlocks` 全量重建的策略，但该函数仅在加载历史消息时调用一次（非流式热路径），
  实际流式热路径已由 `services/stream-handler.ts` 的 rAF 批量刷新 + Trace 树增量构建承担。
- **风险**：若历史消息量大或 `buildTraceFromContentBlocks` 被误用于流式热路径，单次全量重建会有性能损耗；
  旧实现中 `chatStore` 的流式文本追加若回退为逐条 `concat` 整个历史，长会话下主线程占用攀升。
- **建议**：保持 `stream-handler.ts` 的 rAF 批量刷新 + Trace 树增量构建能力，避免每次事件全量重建；
  确认 `buildTraceFromContentBlocks` 仅用于历史加载（冷路径），不进入流式热路径；
  字符串累积统一走分段缓冲而非反复 concat 整个历史。
