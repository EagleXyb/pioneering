# 桌面端（apps/desktop）整体布局与样式系统分析

> 本文档聚焦 `apps/desktop` 渲染端（`src/renderer/src`）的**整体页面布局框架**与**样式系统**，梳理各布局组件的层级关系、嵌套结构、定位尺寸、布局模式、响应式断点、主题色彩、字体排版、间距规范与样式组织方式。

---

## 1. 总体架构与渲染树

桌面端是基于 Electron + React + TypeScript 的应用。主渲染入口为 `App.tsx`，它根据 `useInit()` 的加载状态决定显示加载屏还是主应用。主应用的布局根节点是 `RootLayout`：

```
App.tsx
└─ RootLayout                      // 整体布局框架（三栏 + 顶栏）
   ├─ GlobalHotkeys                // 全局快捷键（逻辑组件，无 UI）
   ├─ TitleBar                     // 顶部自定义标题栏（可隐藏）
   └─ ResizablePanelGroup (horizontal)  // 三栏可拖拽容器
      ├─ Sidebar          (Panel, 固定，不可拖拽)
      ├─ MainContent      (Panel, 主内容区)  ← 路由出口
      └─ ContextPanel     (Panel, 可拖拽缩放)
```

- `RootLayout` 由 `MainLayout` 调用，但布局根与顶栏、三栏容器都集中在 `RootLayout` 中组合。
- 顶栏（TitleBar）与三栏区域是**上下堆叠**（`RootLayout` 根容器为纵向 `flex` / `h-screen` 的纵向分段）。
- 三栏区域使用 shadcn/ui 的 `ResizablePanelGroup` 实现，是**水平方向**的可拖拽面板组。

## 2. 整体页面布局框架（区域划分）

### 2.1 区域构成

| 区域 | 组件 | 位置 | 布局模式 | 尺寸 / 定位 |
|------|------|------|----------|--------------|
| 顶栏 | `TitleBar` | 顶部 | Flexbox（横向） | 高度由 `--titlebar-h` 令牌控制；`position` 取决于窗口控制叠加模式（`overlay` 时为绝对定位覆盖，否则为正常流占位） |
| 侧边栏 | `Sidebar` | 左侧 | Flexbox（纵向） | 宽度由 `SIDEBAR_WIDTH`（逻辑常量）驱动，通过 `ResizablePanel` 的 `defaultSize`/`minSize` 固定，且 `resizable={false}`（不可拖拽）；折叠时宽度收为 0 |
| 主内容区 | `MainContent` | 中部 | Flexbox（纵向） | 路由出口，承载 `HomePage` / `ChatPage` / `WorkspacePage`；内部进一步分栏 |
| 上下文面板 | `ContextPanel` | 右侧 | Flexbox（纵向） | 通过 `ResizablePanel` 可拖拽，有 `minSize`/`defaultSize`；窄屏时退化为 `Drawer` 抽屉 |

### 2.2 三栏的嵌套关系

`RootLayout` 内使用：

```tsx
<ResizablePanelGroup direction="horizontal">
  <ResizablePanel /* Sidebar */ resizable={false} ... />
  <ResizablePanel /* MainContent = Outlet 路由出口 */ />
  <ResizablePanel /* ContextPanel */ />
</ResizablePanelGroup>
```

- **Sidebar**：`resizable={false}`，因此虽然形式上在一个 Panel 内，但用户无法拖拽改变其宽度，宽度由 `SIDEBAR_WIDTH` 常量换算为百分比后写入 `defaultSize`。
- **主内容区**：承载 React Router 的 `<Outlet/>`，即当前页面的实际内容（`HomePage` / `ChatPage` / `WorkspacePage`）。
- **ContextPanel**：唯一 `resizable` 的右栏，可在用户拖拽时被缩放。

### 2.3 主内容区内部（页面级布局）

三个页面各自有独立的内部分栏策略：

- **ChatPage**：采用 `ResizablePanelGroup direction="horizontal"`，分为「会话列表（窄）/ 会话详情（主）」两栏；会话详情内部 `ChatArea` 为纵向 Flex（`flex flex-col h-full`），顶部消息区 `flex-1 overflow-hidden` + 底部输入区。
- **WorkspacePage**：采用 `ResizablePanelGroup direction="horizontal"`，分为「左侧文件树 / 右侧文档预览」两栏。
- **HomePage（欢迎页）**：纵向 Flex 居中布局（`flex flex-col items-center justify-center`）。

## 3. 布局模式与定位方式

### 3.1 布局技术栈

- **Tailwind CSS v4**：通过 `@import "tailwindcss";` 引入，项目**无 `tailwind.config.js`**（采用 v4 的 CSS-first 配置，主题与令牌直接写在 CSS 中）。
- **shadcn/ui 组件库**：`ResizablePanelGroup / ResizablePanel`（基于 `react-resizable-panels`）用于可拖拽分栏；`Button`、`Drawer`、`ScrollArea` 等用于基础 UI。
- **CSS Flexbox** 是绝大多数局部布局的基石（侧边栏、顶栏、聊天区、欢迎页均为 flex 纵向/横向排列）。
- **Grid** 使用较少，主要出现在个别卡片网格（如欢迎页快捷卡片）。

### 3.2 定位方式

- 顶栏在 `windowControlsOverlay` 模式下使用**绝对定位**（覆盖在内容之上，并为内容预留 `--titlebar-h` 的 padding）；普通模式下为**正常文档流**占位。
- 抽屉（`Drawer`）从右侧滑入，使用 `translateX` + `fixed`/overlay 定位覆盖主内容。
- 其他区域均为**文档流 + flex 比例分配**，无绝对定位堆叠（除顶栏覆盖态与抽屉）。

## 4. 维度与尺寸令牌（自定义 CSS 变量）

布局尺寸集中在 `src/platform/layout-tokens.css`（通过 `index.css` 以 `@import './platform/layout-tokens.css';` 引入），并配合若干逻辑常量。

### 4.1 布局令牌（`layout-tokens.css`）

| 变量 | 用途 | 备注 |
|------|------|------|
| `--titlebar-h` | 自定义标题栏高度 | 顶栏高度基准，覆盖态下也作为内容顶部 padding |
| `--workspace-area-w` | 工作区可用宽度 | 工作区相关计算 |
| `--workspace-area-h` | 工作区可用高度 | 工作区相关计算 |
| `--welcome-gap` | 欢迎页区块间距 | HomePage 内部间距 |

> 备注：`--titlebar-h` 在 `TitleBar.tsx` 中被引用为 `var(--titlebar-h)`，作为顶栏高度与内容偏移基准；`--workspace-area-w/h` 用于工作区画布/预览的尺寸计算；`--welcome-gap` 控制欢迎页卡片间距。

### 4.2 逻辑常量（代码侧，非 CSS）

- `SIDEBAR_WIDTH`：侧边栏固定宽度（像素），在 `RootLayout` 中换算为百分比写入 ResizablePanel 的 `defaultSize`。
- 聊天列宽令牌 `--chat-col-max: 880px`：定义于 `src/components/chat/input/pro-input.css`，作为**中间栏内容统一列宽**（消息区、输入区、欢迎页共用），通过 `max-w-[var(--chat-col-max)]` 居中约束，不强制对齐其他端。

### 4.3 典型尺寸取值

- 三栏由 `minSize` / `defaultSize`（百分比）控制；侧边栏 `resizable={false}` 固定；ContextPanel 有 `minSize` 下限。
- 聊天区内部内容列最大宽 **880px** 并水平居中（`mx-auto`）。
- 顶栏高度 = `--titlebar-h`。
- 间距规范见第 8 节（间距工具类）。

## 5. 响应式断点设置

响应式逻辑集中在 `src/platform/useResponsiveLayout.ts`，**不依赖 Tailwind 断点**，而是基于 `window.innerWidth` 与平台相关常量进行比较。

### 5.1 断点常量

断点阈值定义在 `src/lib/constants.ts` 的 `LAYOUT_BREAKPOINT_*` 系列：

- `LAYOUT_BREAKPOINT_MAC`：macOS 平台下的布局断点宽度。
- `LAYOUT_BREAKPOINT_DEFAULT`：默认（Windows 等）平台下的布局断点宽度。

（具体像素值在 `constants.ts` 中；不同平台使用不同阈值以适配 macOS 与 Windows 的窗口/标题栏差异。）

### 5.2 响应式策略（useResponsiveLayout）

`useResponsiveLayout` 返回一组布尔状态，驱动「内嵌面板 vs 抽屉」的切换：

- `sidebarVisible`：是否以内嵌方式显示侧边栏（窄屏时侧边栏折叠为 0 宽或被隐藏）。
- `contextVisible`：是否以内嵌方式显示上下文面板。
- `isDrawerOpen` / `openDrawer` / `closeDrawer`：窄屏下将 ContextPanel 以 `Drawer` 抽屉形式呈现的开关。

**行为规则（概括）**：

1. 当窗口宽度 ≥ 对应平台断点 → 三栏以内嵌 `ResizablePanelGroup` 形式并排显示。
2. 当窗口宽度 < 断点 → 侧边栏折叠（宽度收为 0，`sidebarVisible` 为 false）和/或 ContextPanel 不再内嵌，改为通过 `Drawer` 从右侧覆盖弹出（`isDrawerOpen` 控制）。
3. 监听 `resize` 事件动态更新上述状态，保证拖拽窗口缩放时布局实时重排。

### 5.3 局部响应式类

在组件层面也使用 Tailwind 的响应式前缀：

- 欢迎页标题 `text-3xl sm:text-4xl`（sm 断点放大）。
- 部分内边距/对齐使用 `sm:` 前缀微调。

## 6. 主题色彩体系

主题系统基于 **shadcn/ui + CSS 变量（HSL 通道）**，在 `index.css` 中定义，支持**明/暗双主题**。

### 6.1 主题切换机制

```css
@custom-variant dark (&:is(.dark *));
```

- 暗色主题通过在根元素上添加 `.dark` 类启用；`@custom-variant dark` 让 `dark:` 修饰符在 `.dark` 作用域内生效。
- 亮色为默认（`:root` 定义），暗色在 `.dark` 选择器下覆盖同名变量。

### 6.2 色彩令牌（HSL 通道变量）

定义在 `:root` 与 `.dark` 中，遵循 shadcn 约定（`* { @apply border-border bg-background text-foreground; }`）：

| 令牌 | 语义 | 常见取值（亮/暗） |
|------|------|-------------------|
| `--background` / `--foreground` | 页面背景 / 前景文字 | 亮：白底深字；暗：深底浅字 |
| `--card` / `--card-foreground` | 卡片背景 / 文字 | 用于卡片容器 |
| `--popover` / `--popover-foreground` | 弹层背景 / 文字 | 下拉、弹窗 |
| `--primary` / `--primary-foreground` | 主色 / 主色文字 | 主要操作按钮 |
| `--secondary` / `--secondary-foreground` | 次要色 | 次要按钮/区块 |
| `--muted` / `--muted-foreground` | 弱化背景 / 弱化文字 | 占位、说明文字 |
| `--accent` / `--accent-foreground` | 强调色 | hover/高亮 |
| `--destructive` / `--destructive-foreground` | 危险/报错色 | 删除、错误 |
| `--border` | 边框色 | 分隔线 |
| `--input` | 输入框边框 | 输入控件 |
| `--ring` | 焦点环色 | focus 态 |
| `--radius` | 圆角基准 | 控件圆角（`rounded-lg` 等基于此） |

> 这些令牌均为 **HSL 三通道数值**（如 `222 47% 11%`），配合 Tailwind 的 `bg-background`、`text-foreground`、`border-border` 等工具类使用，实现主题无关的组件着色。

## 7. 字体排版规则

### 7.1 字体引入

`index.css` 首行引入 Google Fonts：

```css
@import url('https://fonts.googleapis.com/css2?family=Public+Sans:wght@300;400;500;600;700;800&display=swap');
```

- 全站使用 **Public Sans**，字重范围 300–800。
- 系统字体栈作为回退（Tailwind 默认 `font-sans`）。

### 7.2 排版规范

- 应用基础字号约 `14px`（`text-sm` 为默认基调），通过 `font-sans` 应用 Public Sans。
- 标题层级示例：欢迎页主标题 `text-3xl sm:text-4xl font-bold tracking-tight`（大号加粗、收紧字距）。
- 字重使用 `font-medium`（500）、`font-semibold`（600）、`font-bold`（700）区分层级。
- 行内代码、说明文字使用 `muted-foreground` 弱化色。

## 8. 组件间距规范

间距以 **Tailwind 间距刻度**（基于 4px 单位，`p-4=16px`、`gap-2=8px` 等）为主，无独立间距令牌。典型用法：

- 聊天区消息与输入区之间靠 `flex-1` 自适应撑开，输入区内边距由 `pro-input.css` 的 `.pro-input-outer` / `.pro-input-inner` 控制。
- 欢迎页主块：`px-6 py-12`、`gap-8`（外层），卡片网格 `gap-3`/`gap-4`。
- 侧边栏内部采用 `flex flex-col`，区块间使用 `gap-*` 与 `px-*` / `py-*`。
- `--welcome-gap`（自定义令牌）专门用于欢迎页区块间距。

> 间距规范统一由 Tailwind 的 padding/margin/gap 工具类承载，未额外定义 `--space-*` 变量。

## 9. 样式组织与管理方式

样式采用 **「Tailwind 工具类为主 + 少量作用域 CSS + 集中令牌」** 的混合组织模式：

### 9.1 分层结构

1. **全局基础层 `index.css`**
   - `@import` 字体、Tailwind、布局令牌。
   - 定义主题 HSL 变量（`:root` / `.dark`）。
   - `@layer base`：`* { @apply ... }` 应用默认 border/bg/text；`body` 基础样式。
   - 全局工具类：如 `.scrollbar-thin`、`.main-content`、`.main-content--welcome`、`.sidebar-content`、`.context-panel-content` 等语义化容器类（用于统一某类区域的滚动条、背景、内边距）。

2. **布局令牌层 `platform/layout-tokens.css`**
   - 与布局尺寸/定位强相关的 CSS 变量（`--titlebar-h`、`--workspace-area-w/h`、`--welcome-gap` 等）。

3. **组件级 CSS**
   - 例：`components/chat/input/pro-input.css`——为输入区定义 `.pro-input-outer` / `.pro-input-inner` 等带作用域的类，并声明 `--chat-col-max: 880px` 列宽令牌（供消息区、输入区、欢迎页共享）。

4. **内联样式 / 动态样式**
   - `RootLayout` 中根据 `sidebarVisible` 用内联 `style` 动态设置侧边栏面板宽度（百分比）。
   - `TitleBar` 根据 `windowControlsOverlay` 动态设置顶栏高度与内容 padding。

### 9.2 组件样式编写惯例

- 绝大多数组件直接在 JSX 中写 **Tailwind 原子类**（如 `flex flex-col h-full items-center justify-center`）。
- 需要复用或涉及复杂伪类/变量时，才抽离到局部 `.css` 文件或 `index.css` 的全局类。
- 主题色统一通过语义令牌类（`bg-background`、`text-muted-foreground` 等）引用，避免硬编码颜色。

### 9.3 状态/布局驱动

- 布局形态（三栏 / 折叠 / 抽屉）由 `useResponsiveLayout` 的响应式状态驱动，而非纯 CSS 媒体查询。
- 面板拖拽缩放由 `react-resizable-panels` 运行时管理，状态持久化由库自身处理。

## 11. 布局层级关系速览（嵌套图）

```
RootLayout (纵向：顶栏 + 三栏区)
│
├─ TitleBar (横向 Flex, h = --titlebar-h, 可覆盖/可隐藏)
│
└─ ResizablePanelGroup (horizontal)
   │
   ├─ Panel[Sidebar]            resizable=false, 固定宽(SIDEBAR_WIDTH), 可折叠为0
   │     └─ Sidebar → .sidebar-content (纵向 Flex)
   │
   ├─ Panel[MainContent]        → <Outlet/> 路由出口
   │     ├─ HomePage      (纵向 Flex 居中, max-w 880 列)
   │     ├─ ChatPage      (ResizablePanelGroup horizontal: 列表 | 详情)
   │     │     └─ ChatArea (纵向 Flex: 消息 flex-1 | 输入区)
   │     │           └─ max-w-[--chat-col-max]=880 居中列
   │     └─ WorkspacePage (ResizablePanelGroup horizontal: 文件树 | 预览)
   │
   └─ Panel[ContextPanel]       resizable=true, minSize 下限
         └─ ContextPanel → .context-panel-content (纵向 Flex)
             窄屏时退化为 Drawer 抽屉覆盖
```

> 总结：桌面端采用「**顶栏 + 三栏可拖拽面板组**」的整体框架，侧边栏固定不可拖拽、主内容区为路由出口、右栏可拖拽并在窄屏退化为抽屉；样式以 Tailwind v4 工具类为主、shadcn HSL 主题令牌与自定义布局令牌为补充，响应式由 `useResponsiveLayout` 的窗口宽度比较驱动而非纯 CSS 媒体查询。
