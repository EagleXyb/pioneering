## 三、与原型的有意偏离

| 项 | 原型做法 | 本项目做法 | 原因 |
|---|---|---|---|
| 页面背景 | `bg-{dark,light}-{1920,mobile}.jpg` + `.page__scrim` 渐变遮罩 | 纯色 `--nova-bg` + 左下粒子星云 | **决策 1**：保留现有品牌动效；星云为 WebGL2 零依赖实现（不引入 three.js），已做静态单帧 / ResizeObserver / reduced-motion / 上下文丢失降级；浅色主题另走 normal 混合（见「4.5」） |
| 登录页主题 | `theme.js` 自管 `localStorage['nova-login-theme']`，默认深色 | 复用全局 `ThemeProvider`（key `theme`，三档 system/light/dark） | **决策 2**：避免「登录页固定深色 → 工作台浅色」的主题跳变；顶栏按钮调用 `setTheme` |
| 验证码面板 | 完整实现（手机号 + 6 位码 + 60s 倒计时） | 维持占位提示 | **决策 3**：后端无验证码端点，见未实现清单 |
| 「记住登录状态 7 天」 | 文案含 7 天 | 「记住登录状态」 | **决策 4**：实际语义是 token 存储位置切换（access 2h / refresh 30d），7 天无实现 |
| 锁定提示展示 | 立即被倒计时覆盖（`startLockTicker()` 首帧同步执行） | 先展示「连续失败 5 次，账号已锁定 15 分钟…」1 秒，再由倒计时接管 | 原型 ticker 会瞬间覆盖刚设置的多信息提示，用户无法读到 |
| 卡片 `backdrop-filter` | 无降级 | 补 `@supports not (...)` 分支，退化为接近不透明底色 | 兼容旧 Firefox / 部分国产内核 |
| 移动端背景 | 切换为 `bg-*-mobile.jpg` | `<768` 隐藏星云 | 移动端表单优先，避免氛围层与卡片争夺视觉焦点 |
| 图标实现 | 全部内联 SVG | 品牌 / 合规 / 能力 / 证书 / 字段 / 状态图标沿用原型内联 SVG 转录；无新增 lucide 图标 | 严格还原原型轮廓比例 |
| 顶栏导航 | 帮助中心 / 开发者文档 Docs | 同原型（移除了改造前多出的「API 文档」项） | 对齐原型；原设计中的「开发者文档」与「Docs」为同一项 |
| 输入中清横幅 | 输入时不清理表单级横幅 | 输入时清除（`setFormError('')`） | 保留改造前的可用性行为：修正输入后旧错误不应继续挂着 |
| 账号 / 密码格式校验 | 账号强制「11 位手机号」或「企业邮箱」；密码要求 ≥8 位并给出强度提示 | 账号与密码**均只做必填校验**，不按格式拦截；label / placeholder 改回「用户名 / 邮箱」 | 与后端契约不一致：`POST /auth/login` 只按 `users.username` 精确匹配（不查 `email` / `phone`），用户名是合法账号，按原型拦截会把后端实际支持的登录方式挡在门外；后端 `RegisterRequestSchema.password` 为 `min(6)`，8 位门槛会让系统内 6–7 位密码的账号无法登录。账号是否存在、密码是否正确一律交由后端 bcrypt 比对判定 |

#### 4.4.1 视口高度适配（本次修复）

**缺陷现象**：矮且宽的窗口（如 1366×768）下，页面底部合规区被截断，且无法滚动到。

**根因**：`.pageContainer` 只设了 `min-height: 100dvh` 而没有高度上限。内容高于视口时容器随之增高并溢出 `#root` 的 `overflow: hidden` 被裁掉——1366×768 实测容器 943px / 视口 768px，溢出 175px 全部不可达；`overflow-y: auto` 因容器自身高度不受限而永不触发。

**修复**：
1. `.pageContainer` 改为 `height: 100%`（锁定在 `#root` 内，即视口高度）+ 保留 `min-height: 100dvh`（移动端地址栏伸缩兜底）。超出内容由外壳自身滚动，任何分辨率下底部合规区均可达。
2. `.stage` 由 `flex: 1 1 auto` + `min-height: 0` 改为 `flex: 1 0 auto`：内容高于视口时主区不压缩，避免品牌区与卡片互相挤压变形，改由外壳滚动。
3. 新增视口**高度**断点（原实现只有宽度断点）。断点按**浏览器视口高度**而非屏幕分辨率定标——1080p 屏幕全屏浏览时视口只有约 950px（地址栏 / 书签栏占用），若按屏幕高度设阈值会漏判：
   - `max-height: 1000px`：收紧品牌区 / 表单区上下留白与卡片内边距（覆盖 1080p 全屏、1440×900、1536×864）
   - `max-height: 820px`：进一步收紧并压缩顶栏 / 底栏高度（覆盖 1366×768、1280×800、900p 全屏）
   - `max-width: 767px and max-height: 1000px`：移动端矮屏，顶部留白 100px → 32px，并压缩合规区内边距

#### 4.4.2 高分辨率与高 DPI（DPR）适配

**结论：布局全部适配、矢量元素不会变虚；唯一会发虚的是星云 Canvas，已修复。**

各分辨率 / DPR 组合实测（1 个 CSS 像素对应的渲染表现）：

| 场景 | DPR | 视口（逻辑） | 溢出 | 卡片 | 星云 Canvas 缓冲宽 |
|---|---|---|---|---|---|
| 1080p@1x | 1 | 1920×1080 | 0 | 424×679 | 1190（= CSS 宽 × 1） |
| 2K@1x | 1 | 2560×1440 | 0 | 424×679 | 1587 |
| 3.5K 带鱼屏@1x | 1 | 3440×1440 | 0 | 424×679 | 2133 |
| 4K@1x | 1 | 3840×2160 | 0 | 424×679 | 2381 |
| 4K@2x | 2 | 3840×2160 | 0 | 424×679 | 4762（= CSS 宽 × 2） |
| 2K@2x | 2 | 2560×1440 | 0 | 424×679 | 3174 |
| 4K@300% 缩放 | 3 | 1280×720 | 19px | 424×583 | 2382（= CSS 宽 × 3，修复后） |
| 1920 逻辑@3x | 3 | 1920×1080 | 0 | 424×679 | 3570（= CSS 宽 × 3，修复后） |
| 8K@1x | 1 | 7680×4320 | 0 | 424×679 | 4762 |

**为什么不会「被放大变虚」**：

1. **登录页无任何位图资源**——品牌标识、能力/证书/字段图标全部是内联 SVG，背景是纯色 + Canvas 星云，不存在位图被拉伸放大的情形。
2. **所有尺寸用 CSS `px`**，浏览器按设备 DPR 做矢量光栅化：DPR=2 时 1 CSS px → 2 物理像素渲染，文字与 SVG 在高 DPI 屏上**更清晰**而不是更模糊。
3. **卡片尺寸恒定**：424×679（桌面）/ 350×604（移动端），不随分辨率放大。1920 / 2560 / 3440 / 3840 / 7680 五档宽度下卡片与输入框尺寸完全一致，只是周围留白变多。
4. **无半像素布局偏移**：实测各场景输入框左边界小数部分均为 `0.000`，边框不会因落到半像素而虚化。

**唯一发虚点及修复**：`ParticleGalaxy` 的 `dpr` prop 默认值为 `2`，内部换算为 `ratio = Math.min(dpr, devicePixelRatio)`。因此 DPR ≥ 3 的设备（4K 开 300% 缩放、高分 Android）只会按 2x 渲染再放大显示——实测 1920 逻辑宽 @3x 的缓冲宽为 2380（应为 3570），星云边缘发虚。现已在 `AuthLayout` 显式传入 `dpr={3}`，覆盖桌面与移动端的最高 DPR；缓冲区尺寸 = **容器 CSS 尺寸 × ratio**，而容器只占视口的 62%×80%，提高上限不会增大显存占用（粒子几何约 3.6MB，泛光 FBO 为 1/2 与 1/4 分辨率）。WebGL2 实测：1512×800 视口 @3x → 容器 937×640 CSS → 缓冲 2811×1920，`gl.getError()` 为 0。

**关于非整数缩放（Windows 125% / 150%）**：`--nova` 令牌中的 `1.5px` 输入框描边、`-0.8px` 字距等在半像素比下由浏览器抗锯齿渲染，属平台级现象（所有网页一致），数值取自原型设计稿，不做改动。实测 1536×864 @1.25x / @1.5x 布局与整数场景一致。

**关于超宽屏（≥2560）**：按原型设定「品牌区 : 表单区 = 52.1 : 47.9」等比分配，未设 `max-width` 上限，因此 4K 全屏下品牌叙事与卡片之间留白较大（原型即如此设计）。不破版、不溢出；若需收紧可后续加 `max-width` 限宽，属产品决策。

#### 4.4.3 深色主题下的浏览器自动填充与 color-scheme

**缺陷现象**：深色主题下，浏览器保存的账号 / 密码被自动填充后，输入框出现**浅色（白）底**、填入文字转为深色，登录凭据几乎不可见（账号框「白底白字」、密码框白底）。

**根因（两项叠加）**：

1. `.pageContainer` 未声明 `color-scheme` —— 浏览器按浅色方案渲染 UA 控件与自动填充（原型 `styles/tokens.css` 中是有 `color-scheme: dark/light` 声明的，转译时遗漏）；
2. Chrome / Edge 的自动填充以 UA 内部 `!important` 样式给输入框强加浅色底与深色文字，常规 `background-color` / `color` **无法覆盖**。

**修复**：

1. 三处令牌块补充 `color-scheme`：浅色块 `color-scheme: light`、`[data-theme="dark"]` 块与系统深色兜底块 `color-scheme: dark`。仅声明在 `.pageContainer` 子树内，不外溢到工作台（`:root` 实测仍为 `normal`）。
2. `login.module.css` 的 `.fieldInput` 与 `auth.module.css` 的 `.formInput` 增加 `:-webkit-autofill`（含 `:hover` / `:focus` / `:active`）覆盖：
   - `box-shadow: 0 0 0 1000px var(--nova-input-bg) inset` 填充输入框底色；`.formInput` 侧加 `!important` 以压过既有的 focus 环，焦点态改由 `border-color` 体现；
   - `-webkit-text-fill-color: var(--nova-text)` 指定填充文字颜色；
   - `caret-color: var(--nova-text)` 指定光标颜色。

**验证**：真实 `:-webkit-autofill` 伪类在无痕浏览器中无法自然触发，故以「注入等效 UA 白底样式」复现——得到与反馈截图一致的白底白字；再叠加本次覆盖规则后，输入框恢复为 `#0b0818` 深色底 + 白色文字，与深色主题一致。

#### 4.5 粒子星云的实现（WebGL2 渲染后端，2026-10-15 重写）

**背景**：原实现是 950 个粒子在 Canvas 2D 上逐帧 `arc() + fill()`，靠 `globalCompositeOperation='lighter'` 与一个径向渐变模拟辉光。它能表达的是"2D 旋涡"，缺少真 3D 倾角、透视、尘埃雾、软边光斑与泛光，与设计参考的"螺旋星系照片"存在量级差距。本次按参考实现（对数螺旋星系，静态单帧渲染）重写渲染后端。

**技术选型**：**WebGL2 手写（零依赖），不引入 three.js**。参考实现用 `three` + `EffectComposer` / `UnrealBloomPass` 实现的部分（`three.module.js` ≈ 600KB min），在登录页这个首屏入口不划算；而所需能力收敛为 5 个 shader 程序 + 1 条 FBO 链、约 500 行即可闭合。

**渲染管线（与参考实现逐模块对应）**：

| # | 步骤 | 实现要点 |
|---|---|---|
| ① | 点精灵 | `gl_PointSize = aSize · PR · (K / gl_Position.w)`，近大远小；片元 `pow(smoothstep(0.5, 0, d), uSoft)` 软边 + `discard`；预乘输出 |
| ② | 三层粒子 | 恒星（`soft=2.2`，核球提亮 + 1.2% 亮星）/ 尘埃（`soft=1.4`，9~33px 大柔光斑、亮度 0.006~0.02）/ 背景深空星（`soft=2.6`，半径 900~1600 球壳） |
| ③ | 分布算法 | 对数螺旋 `θ = armOff + ln(1+0.55r)·(1.15/(spin·10))` + 近似高斯散布（`spread = 0.25·(0.1+0.9r/R)`）；半径幂律 `pow(rnd,1.5|1.7)·R`；`haloRatio` 弥散晕填充臂间；盘厚度 `exp(-r/0.45R)` 中心鼓边缘薄 |
| ④ | 亮核 | 3 层 billboard sprite（40 / 18 / 8，y 压缩 0.72，不透明度 0.48 × `glow` 系数），256×256 canvas 径向渐变纹理（sRGB→线性在片元中做） |
| ⑤ | 泛光 | 亮度阈值提取（`smooth` 软过渡）→ 两级可分离高斯（1/2 与 1/4 分辨率，σ=2 的 9 tap）→ 合成时按 0.65 / 1.0 权重叠加 |
| ⑥ | 合成调色 | 曝光 → smoothstep 暗角 → `c/(c+0.85)·1.85` 柔和压缩（保住紫调不过曝）→ gamma 2.2；输出**保持预乘一致** |

**相机与取景**：沿用参考实现的 `fov 35° / 俯角 42° / 盘半径 100 / 厚度 3.2`，但相机距离改为**按容器宽高比反解**——相机空间竖直半高上界为 `R·sin e + h·cos e`、水平最大投影为 `(R·cot/aspect)/√(d² − (R·cos e)²)`，两式分别解出所需距离取较大者。实测 7 档宽高比（0.5 ~ 3.2）下星系**既不裁切也不缩成一小团**（水平占比 0.33~0.98、竖直占比 0.38~0.94），写进 `galaxyRenderer.test.ts` 作为回归基线。

**主题分支（`palette` + `composite`）**：

| | 深色 | 浅色 |
|---|---|---|
| 混合 | 加法（`ONE, ONE`）+ 预乘 | normal（`ONE, ONE_MINUS_SRC_ALPHA`） |
| 色带 | 亮核白 → 紫 → 蓝紫 → 边缘暗紫（参考实现原值） | 深紫 → 紫 → 亮紫 → 淡紫（整体压暗一档） |
| 泛光 | 阈值 0.22 / 强度 1.1 / 开启 HDR 色调压缩 | **关闭**（尘埃斑本身即柔边光斑，再叠泛光会糊成大团白晕） |
| 尘埃 | 亮度原值 | `dustBoost = 3`（透明底 + 预乘合成下，单斑 alpha ≈ 0.006 时肉眼看到的其实是页面底色） |
| 背景深空星 | 2200 颗冷白点 | 不生成（浅色页面没有"深空"语境，白点会突兀） |

**关键修复（浅色主题"白雾"）**：合成阶段最初直接对 FBO 里的**预乘色**做 gamma 校正，导致低 alpha 区域的 rgb 被抬到远大于 alpha，浏览器按预乘合成时浮出一层白雾。现改为 `straight = premultiplied / alpha` → 曝光 / 压缩 / gamma 全部在非预乘空间 → 最后乘回 alpha，预乘关系始终一致。

**性能与降级**：
- **静态单帧**：默认 `static`，只渲染一帧（参考实现即静态），登录页不常驻 `rAF`，滚动/输入期间零 GPU 开销；`resize` 才重渲。需要动效可传 `static={false}` + `spin`。
- **几何生成**：`AuthLayout` 传 `count={45000}`。星云层只占视口 62%×80%（约全屏面积的 1/3），45000 即等效参考实现全屏 90000 的密度；三层按 90000:26000:2200 比例派生，生成耗时实测约 40ms（90000 时为 83ms），几何数据 ≈ 3.6MB。
- **`<768px` 不挂载**（见 4.4 表格 #21）；`prefers-reduced-motion: reduce` 时强制静止单帧。
- **降级链**：无 WebGL2 → 构造抛错 → 组件捕获后静默不渲染（页面纯色底不受影响）；`EXT_color_buffer_float` 缺失 → 泛光 FBO 退化为 RGBA8；`webglcontextlost` → `preventDefault` 并重建全部 GL 资源（StrictMode 双挂载复用同一上下文，`dispose` 不调用 `loseContext`）。
- **点尺寸上限**：读取 `ALIASED_POINT_SIZE_RANGE` 并 clamp（部分移动 GPU 上限仅 64px）；尘埃层 DPR 上限限 2，降低填充率。

**验证**：`npx tsc -b` 0 错误；`npx vitest run` 473/473 通过（含新增 31 个几何/渲染器用例）；playwright 实测 1512×800 @1x/@3x 双主题截图、375×812 下 `canvas` 节点不存在（不挂载生效）、`gl.getError() === 0`。

## 六、后续优化建议

1. **账号多态登录**（#4）优先级最高：原型与现有前端文案均承诺「账号 / 手机 / 邮箱」，但后端只认 `username`。建议先跑存量数据重复度统计，再决定唯一索引方案。
2. **锁定前移到服务端**（#5）：当前前端计数不具备安全意义，仅作 UI 反馈。
3. **品牌名与备案信息**（#13、#14）属于上线阻塞项。
4. **验证码 / SSO**（#1、#2）建议合并为「扩展登录方式」独立迭代，避免与登录页视觉维护耦合。
