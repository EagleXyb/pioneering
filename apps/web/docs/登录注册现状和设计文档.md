# Web 端登录注册页面现状分析与设计文档

> 评估范围：`src/pages/auth/` 目录下的 [Login.tsx](../src/pages/auth/Login.tsx)、[Register.tsx](../src/pages/auth/Register.tsx)、[AuthLayout.tsx](../src/pages/auth/AuthLayout.tsx)、[ForgotPassword.tsx](../src/pages/auth/ForgotPassword.tsx)、[auth.module.css](../src/pages/auth/auth.module.css)，以及配套的 [useAuth.ts](../src/hooks/useAuth.ts)、[store/auth.ts](../src/store/auth.ts)、[api/auth-api.ts](../src/api/auth-api.ts)、[styles/tokens.css](../src/styles/tokens.css)、[index.css](../src/index.css)。

## 一、设计理念

### 优点
- **双面板分屏范式成熟**：[AuthLayout.tsx#L19-L57](../src/pages/auth/AuthLayout.tsx#L19-L57) 采用"左品牌 + 右表单"的 SaaS 标准布局，登录/注册/忘记密码三页共享头部，体现品牌一致性。
- **品牌符号清晰**：[AuthLayout.tsx#L24-L26](../src/pages/auth/AuthLayout.tsx#L24-L26) "创"字 Logo + "创路Agent" 名称定位明确，与项目多模式 Agent 产品调性吻合。
- **状态/逻辑分层清晰**：UI（`AuthLayout`）—Hook（`useAuth`）—Store（`useAuthStore`）—API（`auth-api`）四层解耦，符合项目工程约定。

### 缺点
- **主标题断句违反中文语感**：[AuthLayout.tsx#L27-L28](../src/pages/auth/AuthLayout.tsx#L27-L28) 将"构建未来的数字智能助手"拆为"构建未来的数字"+"智能助手"两行，"未来的数字"语义断裂，建议改为"构建未来的"+"数字智能助手"或"构建未来数字智能助手"。
- **品牌面板内容与产品功能脱节**：未呈现多模式（Chat/Pro/Task）核心卖点，仅靠"3D 立方体 + 圆形"几何装饰（[auth.module.css#L80-L153](../src/pages/auth/auth.module.css#L80-L153)）显得抽象单薄。
- **缺少场景化视觉**：无产品截图、插画或动态预览，难以让用户在登录阶段感知产品价值。
- **"创路"品牌识别弱化**：仅 logo 字 + 名称，缺少 slogan 或价值主张副标。

### 改进方向
- 修正主标题断句；在品牌面板加入"多模式 Agent / 工作流编排 / 任务自动化"等核心特性卡片轮播或静态插图。
- 引入 slogan（如"让创造更高效"），强化品牌记忆。

## 二、视觉表现

### 优点
- **品牌色统一**：[auth.module.css#L13](../src/pages/auth/auth.module.css#L13) 蓝色渐变 `#E8F5FF → #A6CCF2 → #73A6E6` 与 `tokens.css` 中 `--accent-blue: #3b82f6` 主色系一致。
- **字体层级清晰**：48px 主标题 → 26px 品牌名 → 22px 卡片标题 → 18px 副标题 → 14px 正文，对比合理。
- **毛玻璃卡片**：[auth.module.css#L168-L178](../src/pages/auth/auth.module.css#L168-L178) `backdrop-filter: blur(20px)` + 半透明白底，视觉层次现代。
- **语义化颜色编码**：密码强度用红/橙/绿三色（[auth.module.css#L394-L404](../src/pages/auth/auth.module.css#L394-L404)），符合用户认知。

### 缺点
- **大量硬编码颜色未走 token**：`#1E293B`、`#475569`、`#64748B`、`#94A3B8`、`#E6EDFA`、`#F7FAFF`、`#EDF2FC`、`#334155` 等散落于 [auth.module.css](../src/pages/auth/auth.module.css)，违反项目 memory 中"第三方类型集中、设计令牌统一"的工程约定。
- **暗色模式完全未适配**：[tokens.css#L55-L90](../src/styles/tokens.css#L55-L90) 定义了完整暗色主题，但 auth 页面的 `brandPanel`/`formPanel`/`authCard` 仍使用浅色渐变与硬编码深色文字，切换主题后会"半亮半暗"。
- **阴影未走 token**：`box-shadow: 0 4px 12px rgba(37, 99, 235, 0.3)` 等多处硬编码，与 `--shadow-sm/md/lg` 体系并行。
- **3D 装饰用绝对像素定位**：[auth.module.css#L81-L88](../src/pages/auth/auth.module.css#L81-L88) `right: 215px; top: 366px;` 在不同视窗尺寸下会与文案重叠或溢出。
- **TDesign 默认样式覆盖不彻底**：[auth.module.css#L249-L262](../src/pages/auth/auth.module.css#L249-L262) 用 `:global` 覆盖 `.t-form__item` 间距，但 label 字色、input focus 边框等仍为 TDesign 默认蓝（`#0052D9`），与品牌蓝 `#3b82f6` 冲突。

### 改进方向
- 将所有硬编码颜色替换为 token，必要时扩展 `tokens.css`（如新增 `--auth-brand-bg`、`--auth-form-bg`）。
- 为 auth 页面锁定亮色主题或补齐暗色变量；至少 `:root[data-theme="dark"] .brandPanel` 等覆盖样式。
- 装饰容器改用 `top: 50%; left: 50%; transform: translate(-50%, -50%)` 居中，配合 `max-width` 约束。
- 通过 `--td-brand-color` 等 TDesign CSS 变量覆盖，统一组件品牌色。

## 三、用户体验

### 优点
- **Tab 切换流畅**：[Login.tsx#L50-L57](../src/pages/auth/Login.tsx#L50-L57) 使用 `NavLink` + `isActive` 状态切换，路由驱动，刷新可保持。
- **密码强度实时反馈**：[Register.tsx#L21-L34](../src/pages/auth/Register.tsx#L21-L34) `calcPasswordStrength` 计算 + 3 段进度条 + 文字标签，引导用户设置强密码。
- **密码匹配即时提示**：[Register.tsx#L197-L208](../src/pages/auth/Register.tsx#L197-L208) 确认密码输入即显示"一致/不一致"，配以红绿圆点。
- **验证规则完备**：[Register.tsx#L70-L91](../src/pages/auth/Register.tsx#L70-L91) 涵盖 required/min/email/自定义 validator。
- **登录回跳**：[useAuth.ts#L27-L29](../src/hooks/useAuth.ts#L27-L29) 通过 `location.state.from` 实现登录后回跳原路径，符合访问控制 UX。
- **持久化策略符合项目约束**：[store/auth.ts#L35-L38](../src/store/auth.ts#L35-L38) + [useAuth.ts#L19](../src/hooks/useAuth.ts#L19) 注释清晰说明 `rememberMe` 决定 localStorage/sessionStorage，与 memory 中"rememberMe 标志支持持久化"约束一致。

### 缺点
- **密码可见性切换缺失**：[Login.tsx#L78-L85](../src/pages/auth/Login.tsx#L78-L85) 与 [Register.tsx#L132-L141](../src/pages/auth/Register.tsx#L132-L141) 密码框 `type="password"` 无法切换为明文，长密码输入易出错。
- **密码强度算法过简**：[Register.tsx#L21-L27](../src/pages/auth/Register.tsx#L21-L27) 只检查长度+大小写+数字+符号，未检测常见弱密码字典、用户名/邮箱子串、连续字符。
- **缺少邮箱/用户名可用性实时校验**：用户填完提交才知道是否被占用，应 debounce 500ms 查询 `/auth/check`。
- **错误反馈不一致**：[Login.tsx#L28](../src/pages/auth/Login.tsx#L28) 成功用 `MessagePlugin.success` toast，失败却用 [Login.tsx#L102](../src/pages/auth/Login.tsx#L102) 内联 `.errorText`，体验割裂。
- **错误提示无障碍缺陷**：[Login.tsx#L102](../src/pages/auth/Login.tsx#L102) `<div className={styles.errorText}>` 无 `role="alert"` / `aria-live="assertive"`，屏幕阅读器无法即时播报。
- **缺少 autoComplete 属性**：所有 Input 均未设置 `autoComplete="username|email|current-password|new-password"`，浏览器密码管理器无法识别上下文。
- **忘记密码页是占位**：[ForgotPassword.tsx#L15-L34](../src/pages/auth/ForgotPassword.tsx#L15-L34) 仅显示"功能开发中"，用户点进去后只能返回，体验断裂。
- **无第三方登录**：缺少 GitHub/Google/微信等入口，现代 SaaS 标配。
- **无图形/行为验证码**：登录/注册接口存在被刷风险，缺少 hCaptcha/Turnstile 等防护。
- **loading 时未禁用输入框**：[Register.tsx#L39-L67](../src/pages/auth/Register.tsx#L39-L67) 提交期间用户仍可修改表单，可能引发竞态。
- **注册成功后无邮箱验证环节**：[Register.tsx#L56-L58](../src/pages/auth/Register.tsx#L56-L58) 直接 `navigate('/chat')`，缺少"激活邮件已发送"提示。
- **TDesign 内联样式 + 内部样式双重验证规则**：[Register.tsx#L83-L90](../src/pages/auth/Register.tsx#L83-L90) `confirmPassword` 同时用 Form rule 和手动 `confirmPassword.length > 0` 提示，逻辑重复。

### 改进方向
- 密码框添加 `suffixIcon` 切换可见性。
- 密码强度算法升级：引入 `zxcvbn` 库或自实现常见密码黑名单 + 用户名子串检测。
- 邮箱/用户名 debounce 实时校验。
- 统一反馈：成功/失败都用内联（带图标 + 重试按钮）或都用 toast。
- 错误提示加 `role="alert" aria-live="assertive"`。
- Input 补全 `autoComplete` 属性。
- 实现忘记密码最小流程（邮箱输入 → 后端发送重置链接 → 提示检查邮箱）。
- 加图形验证码（推荐 Cloudflare Turnstile，无感体验好）。
- loading 时整体表单 `disabled` 或加遮罩。

## 四、布局结构

### 优点
- **左右比例合理**：[auth.module.css#L11-L21](../src/pages/auth/auth.module.css#L11-L21) + [auth.module.css#L156-L165](../src/pages/auth/auth.module.css#L156-L165) `64.6% / 35.4%` 分栏，品牌侧留足视觉空间，表单侧紧凑。
- **卡片居中 + 宽度限制**：[auth.module.css#L168-L178](../src/pages/auth/auth.module.css#L168-L178) `max-width: 420px` 保证可读性。
- **三档响应式断点**：[auth.module.css#L498-L527](../src/pages/auth/auth.module.css#L498-L527) 1024px / 768px / 480px 分级适配。
- **labelAlign="top"** 适配窄屏垂直排版。

### 缺点
- **比例固定无中间档**：在 1366px 笔记本上 64.6% 品牌面板会显得过宽，表单卡被挤压；缺少 1280-1440px 中等屏适配。
- **1024px 断点装饰位置仍溢出**：[auth.module.css#L509-L512](../src/pages/auth/auth.module.css#L509-L512) 仅 `scale(0.7)` 但 `right: 50px` 仍可能溢出 `brandPanel`。
- **768px 完全隐藏品牌面板**：[auth.module.css#L516-L527](../src/pages/auth/auth.module.css#L516-L527) 平板竖屏失去品牌曝光，应保留精简 banner（80px 高，Logo + slogan）。
- **按钮高度不一致**：[Login.tsx#L111](../src/pages/auth/Login.tsx#L111) 登录按钮 `height: 40, borderRadius: 3`，[Register.tsx#L220](../src/pages/auth/Register.tsx#L220) 注册按钮 `height: 48, borderRadius: 8`，同一套页面两套规格。
- **decorContainer 用绝对像素**：[auth.module.css#L83-L84](../src/pages/auth/auth.module.css#L83-L84) `right: 215px; top: 366px`，视窗高度 < 800px 时会与文案重叠。
- **超宽屏未限制**：无 `max-width: 1920px; margin: 0 auto`，4K 屏上 `brandPanel` 内容会过度拉伸。
- **底部链接用 button 而非 Link**：[Login.tsx#L120-L122](../src/pages/auth/Login.tsx#L120-L122) 与 [Register.tsx#L229-L231](../src/pages/auth/Register.tsx#L229-L231) 用 `<button onClick={() => navigate(...)}>`，丢失右键"新窗口打开"、SEO 爬虫可索引性、Cmd+Click 等浏览器原生能力。
- **卡片宽度未用 clamp**：`max-width: 420px` 在 320px 屏会贴边，应用 `clamp(320px, 90vw, 420px)`。
- **Tab 高度容器 44 / 按钮 38 不齐**：[auth.module.css#L201-L241](../src/pages/auth/auth.module.css#L201-L241) 容器 `height: 44` 但 active 按钮 `height: 38`，非 active 用 `flex: 1` 自适应，导致切换时高度跳动。
- **Tab 圆角三层不一致**：容器 `border-radius: 4`、按钮 `border-radius: 6`、active `border-radius: 3`，视觉杂乱。

### 改进方向
- 中等屏（1280-1440px）增加 `55% / 45%` 比例档。
- 768px 改为可折叠品牌 banner（高度 80px，保留 Logo + slogan）。
- decorContainer 改相对定位 + 百分比 + transform 居中。
- 统一 Login/Register 按钮规格（建议 48px 高、8px 圆角）。
- 底部链接改用 `Link`/`NavLink`，保留原生浏览器能力。
- 添加 `max-width: 1920px; margin: 0 auto` 限制超宽屏。
- 卡片宽度改用 `clamp(320px, 90vw, 420px)`。
- 统一 Tab 容器/按钮/active 圆角与高度。

## 五、样式细节

### 优点
- **输入框热区合理**：[Login.tsx#L73](../src/pages/auth/Login.tsx#L73) 等 `size="large"` + `height: 48` 提升点击体验。
- **过渡动画**：[auth.module.css#L217](../src/pages/auth/auth.module.css#L217) + [auth.module.css#L236](../src/pages/auth/auth.module.css#L236) Tab 与按钮 `transition: all 0.3s ease`；[auth.module.css#L280-L293](../src/pages/auth/auth.module.css#L280-L293) `.submitBtn` 有 hover 上浮 + 阴影增强。
- **密码强度条平滑过渡**：[auth.module.css#L391](../src/pages/auth/auth.module.css#L391) `transition: background 0.3s`。
- **毛玻璃卡片**：[auth.module.css#L172-L173](../src/pages/auth/auth.module.css#L172-L173) `backdrop-filter: blur(20px)` 现代感强。

### 缺点
- **死代码**：[auth.module.css#L265-L293](../src/pages/auth/auth.module.css#L265-L293) `.submitBtn` 类定义完善（含 hover/active/disabled），但 [Login.tsx#L105-L114](../src/pages/auth/Login.tsx#L105-L114) 与 [Register.tsx#L214-L223](../src/pages/auth/Register.tsx#L214-L223) 都用 TDesign `Button` + 内联 style，未使用该类。同理 `.divider/.dividerLine/.dividerText`（[auth.module.css#L313-L330](../src/pages/auth/auth.module.css#L313-L330)）、`.loading`（[auth.module.css#L481-L495](../src/pages/auth/auth.module.css#L481-L495)）均未使用。
- **重复定义**：`.passwordStrength` 与 `.confirmHint` 在文件中被定义两次（[auth.module.css#L332-L338](../src/pages/auth/auth.module.css#L332-L338) + [auth.module.css#L378-L384](../src/pages/auth/auth.module.css#L378-L384)），后者覆盖前者，需合并。
- **输入框内联样式重复**：[Login.tsx#L73](../src/pages/auth/Login.tsx#L73) + [Register.tsx](../src/pages/auth/Register.tsx) 共 7 处 `style={{ height: 48 }}`，应抽为 `.formInput` 类。
- **focus 状态未自定义**：依赖 TDesign 默认 focus 蓝色边框（`#0052D9`），与品牌 `--accent-blue: #3b82f6` 不一致。
- **错误提示无动画**：[auth.module.css#L304-L310](../src/pages/auth/auth.module.css#L304-L310) `.errorText` 直接显示，无 fade-in/shake 反馈。
- **按钮 hover 上浮幅度过小**：[auth.module.css#L281](../src/pages/auth/auth.module.css#L281) `translateY(-1px)` 几乎不可感知，建议 2-3px。
- **按钮文字手动加空格**：[Login.tsx#L113](../src/pages/auth/Login.tsx#L113) "登 录"、[Register.tsx#L222](../src/pages/auth/Register.tsx#L222) "注 册"，loading 时切换为"登录中..."/"注册中..."空格消失，按钮宽度抖动。
- **backdrop-filter 兼容性**：[auth.module.css#L172-L173](../src/pages/auth/auth.module.css#L172-L173) 未提供 `@supports` fallback，Firefox 旧版与 IE 会显示为半透明白底几乎不可见。
- **Tab 切换无滑动指示器**：active 状态用 `box-shadow` 突变，缺少 transform 滑动动画，与原型 V1.3 的现代感定位不符。
- **卡片/表单无进入动画**：页面切换时无 `fadeInUp` 或 stagger 动画，体验生硬。
- **TDesign Form 间距覆盖风险**：[auth.module.css#L249-L251](../src/pages/auth/auth.module.css#L249-L251) `:global(.t-form__item) { margin-bottom: 16px }` 覆盖 TDesign 默认 24px，可能破坏 TDesign 内部布局计算（如总高度估算）。
- **密码强度条固定宽度**：[auth.module.css#L387](../src/pages/auth/auth.module.css#L387) `width: 60px`，在 320px 窄屏会与文字挤压，应 `flex: 1`。
- **无骨架屏**：登录/注册加载时无视觉占位。
- **`overflow: hidden` 全局副作用**：[index.css#L10](../src/index.css#L10) `html, body, #root { overflow: hidden }` 影响整个应用，auth 页面在小屏（如 360x640）可能因 `min-height: 100vh` + 卡片 padding 溢出而无法滚动。

### 改进方向
- 清理死代码：`.submitBtn` / `.divider*` / `.loading` 全部移除。
- 合并重复定义的 `.passwordStrength` / `.confirmHint`。
- 抽取公共 `.formInput` / `.submitButton` 类替代内联 style。
- 自定义 focus：`border-color: var(--accent-blue); box-shadow: 0 0 0 3px rgba(59, 130, 246, 0.12)`。
- 错误提示加 `@keyframes shake` 或 `fadeIn`。
- 按钮 hover 幅度改 `translateY(-2px)`。
- 用 `letter-spacing: 0.3em` 替代手动空格，loading 时文字宽度稳定。
- `@supports not (backdrop-filter: blur(20px))` 提供 `background: rgba(255, 255, 255, 0.85)` fallback。
- Tab 改为滑动指示器（绝对定位 + transform）。
- 添加 `@keyframes fadeInUp` 给 `authCard` 进入动画。
- 密码强度条改 `flex: 1`。
- 全局 `overflow: hidden` 改为应用级（如 AppShell 内部），auth 容器允许 `overflow-y: auto`。

## 六、总结与改进优先级

| 优先级 | 维度 | 关键问题 | 影响面 |
|---|---|---|---|
| **P0** | 样式细节 | 死代码 + 重复定义 + 按钮规格不一致 | 维护成本、视觉一致性 |
| **P0** | 用户体验 | 缺少 autoComplete / 密码可见性切换 / 错误无障碍 | 可用性、可达性 |
| **P1** | 视觉表现 | 暗色模式未适配 + 大量硬编码颜色 | 主题一致性 |
| **P1** | 布局结构 | 中等屏比例 + 超宽屏未限制 + 链接用 button | 响应式、SEO |
| **P2** | 用户体验 | 忘记密码占位 + 无验证码 + 无第三方登录 | 功能完整性、安全性 |
| **P2** | 设计理念 | 主标题断句 + 品牌面板内容单薄 | 品牌识别 |
| **P3** | 样式细节 | 进入动画 + 滑动指示器 + 骨架屏 | 体验精致度 |
