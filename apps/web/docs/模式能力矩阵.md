> 来源：《三模式Agent能力分层实施方案》第 1.1 节 / 附录 A。
> 本文件是三模式（chat / pro / task）的**能力边界硬约束**，作为所有 PR 的审查基准。
> 任何 PR 若导致本矩阵某项变化，必须在 PR 描述中显式说明并获得评审确认。
>
> **状态：已按 W0–W5 更新到最终实现（2026-10-07），39 个任务全部完成**。
> D6 已于 2026-10-07 授权落地（schema 所有权移交 TS 侧），T5.5（run 实体落库 / 执行轨迹回放）已完成。

## 2. PR 审查清单（模式边界，最高优先）

| # | 检查项 | chat | pro | task |
|---|---|---|---|---|
| 1 | 是否请求 `/agent/*` | ❌ 必须否 | ✅ | ✅ |
| 2 | 是否挂 HITL 卡 | ❌ 必须否 | ✅ | ✅ |
| 3 | 是否挂工具 / 来源 / Artifact 入口 | ❌ 必须否 | ✅ | ✅ |
| 4 | 是否出现 plan 相关 UI | ❌ 必须否 | ❌ 必须否 | ✅ |
| 5 | 是否引 `@pioneering/*` 依赖 | ❌ 必须否 | ✅ | ✅ |
| 6 | 「深度思考」语义 | 原生 reasoning | **不加此开关**，明示「ReAct 推理过程」 | 同 pro |

**审查规则**

- 以上任一行不满足 → PR 直接驳回，不进入功能细节评审。
- chat 栈硬约束：不挂 HITL、不挂工具、不引任何 `@pioneering/*` 依赖；其「深度思考」是 DeepSeek 原生 `reasoning_content`，与 Agent 的多轮工具 ReAct 是不同产品语义，UI 文案必须区分。
- pro/task 之间也不得互相渗透：pro 不出现 plan 相关字段与 UI。
- 命名约定：AG-UI 事件载荷为 **snake_case**（`session_id` / `tool_calls`），REST 请求体为 **camelCase**（`sessionId` / `modifiedArgs`）。
