## 1. 现状分析：提示词注入机制与组装流程

### 1.1 提示词三层组装模型

当前 Agent 的 system prompt 采用「**外部传入 + Skill 片段聚合 + 节点内动态注入上下文**」的三层组装模式：

```
┌─────────────────────────────────────────────────────────────┐
│ 第①层：工厂装配期（create_agent，仅执行一次，被缓存）          │
│   effectiveSystemPrompt =                                    │
│     configurable['system_prompt']                            │
│     ?? systemPrompt（create_agent 第三参数）                  │
│     ?? _DEFAULT_ANTI_HALLUCINATION_PROMPT                    │
│                          ↓                                   │
│   if skills.enabled:                                         │
│     SkillPromptAggregator.aggregate(base, registry)          │
│     → base + '\n\n' + [Skill片段1, Skill片段2, ...].join()   │
└──────────────────────────┬──────────────────────────────────┘
                           ↓ 闭包持有
┌─────────────────────────────────────────────────────────────┐
│ 第②层：节点执行期（agentNode，每次请求执行）                  │
│   messages = [...state.messages]                             │
│   messages.unshift(SystemMessage(systemPrompt))    ← ①层产物 │
│   messages.splice(1,0, SystemMessage(perceptionCtx))         │
│   messages.splice(1,0, SystemMessage(knowledge))             │
│   messages.push(SystemMessage(stepCtx))  ← Plan-Execute 专用 │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│ 第③层：工具绑定期（bindTools，工厂装配时）                     │
│   boundLlm = llm.bindTools(tools)  ← 工具元信息走 function   │
│   calling 协议，不在 system prompt 文本中                     │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 现状问题

1. **主 Agent 无角色概念**：`systemPrompt` 需调用方硬编码传入，无法运行时切换
2. **子 Agent 角色模板硬编码**：`subgraph/builder.ts` 中 4 个模板写死在源码，无法通过配置增改
3. **无持久化**：角色提示词无存储，重启丢失
4. **无管理界面**：纯 SDK，宿主需自行实现 UI
5. **`llm.prompt_template` 形同虚设**：预留字段从未被读取

## 2. 方案总览与架构设计

### 2.1 设计目标

- **端到端**：前端配置 → API 存储 → 运行时注入，全链路打通
- **最小侵入**：核心 SDK 仅改 1 处（factory.ts 提示词组装段），其余通过新增模块实现
- **热更新**：角色配置变更后，新请求立即生效，无需重启
- **回滚安全**：角色读取失败时降级到默认提示词，不阻塞 Agent 运行
- **per-session 隔离**：支持请求级指定角色，互不影响

### 2.2 三层架构

```
┌──────────────────────────────────────────────────────────────────┐
│  前端层 (packages/modu-agent-ui)                                  │
│  React + Vite + TypeScript                                        │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  角色列表页  │  角色编辑器  │  实时预览  │  会话选择角色    │  │
│  └────────────────────────────────────────────────────────────┘  │
└──────────────────────────┬───────────────────────────────────────┘
                           │ HTTP REST + SSE
┌──────────────────────────▼───────────────────────────────────────┐
│  API 层 (packages/modu-agent-server)                              │
│  Fastify + better-sqlite3                                         │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────────────────┐  │
│  │ /api/roles   │  │ /api/sessions│  │ /api/agent/invoke     │  │
│  │   CRUD       │  │   角色绑定    │  │   (SSE 流式)          │  │
│  └──────────────┘  └──────────────┘  └───────────────────────┘  │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  RolePromptProvider (运行时读取角色 → 注入 configurable)   │  │
│  └────────────────────────────────────────────────────────────┘  │
└──────────────────────────┬───────────────────────────────────────┘
                           │ 编程式 API
┌──────────────────────────▼───────────────────────────────────────┐
│  SDK 层 (packages/modu-agent)  ← 仅 1 处改动                     │
│  factory.ts: 在 effectiveSystemPrompt 组装前插入角色解析          │
│  RolePromptProvider.resolve(roleId) → { system_prompt, ... }     │
└──────────────────────────────────────────────────────────────────┘
```

### 2.3 数据流

```
用户在前端创建角色 "数据分析专家"
    ↓ POST /api/roles
API 层校验 + 写入 SQLite roles 表
    ↓
用户发起会话，选择角色
    ↓ POST /api/agent/invoke { role_id: "role_xxx", prompt: "..." }
API 层 RolePromptProvider.resolve(role_id)
    ↓ 从 DB 读取角色配置
    ↓ 组装 configurable = { role_id, system_prompt, temperature, ... }
    ↓ 调用 stream_response(graph, userId, sessionId, input, ..., extraConfigurable)
SDK 层 factory.ts
    ↓ effectiveSystemPrompt = configurable['system_prompt'] ?? default
    ↓ SkillPromptAggregator.aggregate()（如果启用）
    ↓ makeAgentNode 闭包持有
运行时 agentNode
    ↓ 注入 SystemMessage + 感知上下文 + 知识 + 步骤上下文
    ↓ boundLlm.invoke(messages)
```

### 3.1 角色数据模型（TypeScript 接口）

```typescript
// packages/modu-agent-server/src/roles/types.ts

/**
 * 角色提示词配置（完整定义）。
 * 对应 DB 表 roles，也作为前后端 API 的数据契约。
 */
export interface RoleConfig {
  /** 主键，格式 `role_<uuid8>`，如 `role_a1b2c3d4` */
  id: string

  /** 角色显示名，前端列表展示，如「数据分析专家」 */
  name: string

  /** 角色简述，前端卡片展示，如「擅长 SQL 查询、数据可视化、统计建模」 */
  description: string

  /** 角色类型，决定子图默认模板回退（research/coding/review/default） */
  task_type: 'research' | 'coding' | 'review' | 'default'

  /** 核心系统提示词，注入 LLM 的角色设定 */
  system_prompt: string

  /**
   * 附加指令片段，拼接到 system_prompt 之后、Skill 片段之前。
   * 用于存放工具使用规范、输出格式约束等可独立维护的规则。
   */
  additional_instructions: string

  /** LLM 参数覆盖（null 表示沿用全局配置） */
  llm_overrides: {
    temperature?: number | null    // 0.0-2.0
    max_tokens?: number | null     // 1-8192
    model?: string | null          // 如 'deepseek-chat'
    provider?: string | null       // 如 'deepseek'
  }

  /** 关联 Skill 名列表，运行时仅激活这些 Skill（空=全部激活） */
  active_skills: string[]

  /** 关联工具名白名单（空=沿用全局工具集） */
  active_tools: string[]

  /** 是否为系统内置角色（内置角色不可删除，仅可编辑提示词） */
  is_builtin: boolean

  /** 是否启用（禁用的角色不出现在前端选择列表） */
  is_active: boolean

  /** 排序权重，越小越靠前 */
  sort_order: number

  created_at: string  // ISO 8601
  updated_at: string  // ISO 8601
}

/**
 * 创建角色时的输入（服务端生成 id/时间戳/is_builtin）。
 */
export type RoleCreateInput = Omit<RoleConfig, 'id' | 'is_builtin' | 'created_at' | 'updated_at'>

/**
 * 更新角色时的输入（部分字段可选）。
 */
export type RoleUpdateInput = Partial<RoleCreateInput>
```

### 4.2 存储访问层（DAO）

```typescript
// packages/modu-agent-server/src/storage/role-repository.ts

import Database from 'better-sqlite3'
import type { Database as DBType } from 'better-sqlite3'
import type { RoleConfig, RoleCreateInput, RoleUpdateInput } from '../roles/types.js'

const SCHEMA_SQL = `
CREATE TABLE IF NOT EXISTS roles (
  id                      TEXT PRIMARY KEY,
  name                    TEXT NOT NULL,
  description             TEXT NOT NULL DEFAULT '',
  task_type               TEXT NOT NULL DEFAULT 'default'
                          CHECK (task_type IN ('research', 'coding', 'review', 'default')),
  system_prompt           TEXT NOT NULL DEFAULT '',
  additional_instructions TEXT NOT NULL DEFAULT '',
  llm_overrides           TEXT NOT NULL DEFAULT '{}',
  active_skills           TEXT NOT NULL DEFAULT '[]',
  active_tools            TEXT NOT NULL DEFAULT '[]',
  is_builtin              INTEGER NOT NULL DEFAULT 0,
  is_active               INTEGER NOT NULL DEFAULT 1,
  sort_order              INTEGER NOT NULL DEFAULT 100,
  created_at              TEXT NOT NULL,
  updated_at              TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_roles_active ON roles (is_active, sort_order);
CREATE INDEX IF NOT EXISTS idx_roles_task_type ON roles (task_type);
`

/** 行结构（DB 原始类型，is_builtin/is_active 为 number） */
interface RoleRow {
  id: string
  name: string
  description: string
  task_type: string
  system_prompt: string
  additional_instructions: string
  llm_overrides: string
  active_skills: string
  active_tools: string
  is_builtin: number
  is_active: number
  sort_order: number
  created_at: string
  updated_at: string
}

export class RoleRepository {
  private db: DBType

  constructor(dbPath: string) {
    this.db = new Database(dbPath)
    this.db.pragma('journal_mode = WAL')
    this.db.exec(SCHEMA_SQL)
    this._seedBuiltinRoles()
  }

  /** 查询全部角色（按 sort_order 升序） */
  listAll(includeInactive = false): RoleConfig[] {
    const sql = includeInactive
      ? 'SELECT * FROM roles ORDER BY sort_order ASC, created_at ASC'
      : 'SELECT * FROM roles WHERE is_active = 1 ORDER BY sort_order ASC, created_at ASC'
    return this.db.prepare(sql).all().map((r) => this._rowToConfig(r as RoleRow))
  }

  /** 按 ID 查询单个角色 */
  findById(id: string): RoleConfig | null {
    const row = this.db.prepare('SELECT * FROM roles WHERE id = ?').get(id) as RoleRow | undefined
    return row ? this._rowToConfig(row) : null
  }

  /** 创建角色 */
  create(input: RoleCreateInput): RoleConfig {
    const id = `role_${this._uuid8()}`
    const now = new Date().toISOString()
    this.db.prepare(`
      INSERT INTO roles (
        id, name, description, task_type, system_prompt, additional_instructions,
        llm_overrides, active_skills, active_tools, is_builtin, is_active,
        sort_order, created_at, updated_at
      ) VALUES (
        @id, @name, @description, @task_type, @system_prompt, @additional_instructions,
        @llm_overrides, @active_skills, @active_tools, 0, @is_active,
        @sort_order, @created_at, @updated_at
      )
    `).run({
      id,
      name: input.name,
      description: input.description,
      task_type: input.task_type,
      system_prompt: input.system_prompt,
      additional_instructions: input.additional_instructions,
      llm_overrides: JSON.stringify(input.llm_overrides ?? {}),
      active_skills: JSON.stringify(input.active_skills ?? []),
      active_tools: JSON.stringify(input.active_tools ?? []),
      is_active: input.is_active ? 1 : 0,
      sort_order: input.sort_order ?? 100,
      created_at: now,
      updated_at: now,
    })
    return this.findById(id)!
  }

  /** 更新角色（内置角色仅允许更新提示词相关字段） */
  update(id: string, input: RoleUpdateInput): RoleConfig | null {
    const existing = this.findById(id)
    if (!existing) return null
    const now = new Date().toISOString()
    const merged = { ...existing, ...input, updated_at: now }

    // 内置角色保护：不允许修改 is_builtin / 删除
    if (existing.is_builtin) {
      delete (merged as any).task_type
      delete (merged as any).is_active
      delete (merged as any).sort_order
    }

    this.db.prepare(`
      UPDATE roles SET
        name = @name,
        description = @description,
        task_type = @task_type,
        system_prompt = @system_prompt,
        additional_instructions = @additional_instructions,
        llm_overrides = @llm_overrides,
        active_skills = @active_skills,
        active_tools = @active_tools,
        is_active = @is_active,
        sort_order = @sort_order,
        updated_at = @updated_at
      WHERE id = @id
    `).run({
      id,
      name: merged.name,
      description: merged.description,
      task_type: merged.task_type,
      system_prompt: merged.system_prompt,
      additional_instructions: merged.additional_instructions,
      llm_overrides: JSON.stringify(merged.llm_overrides ?? {}),
      active_skills: JSON.stringify(merged.active_skills ?? []),
      active_tools: JSON.stringify(merged.active_tools ?? []),
      is_active: merged.is_active ? 1 : 0,
      sort_order: merged.sort_order,
      updated_at: now,
    })
    return this.findById(id)
  }

  /** 删除角色（内置角色拒绝删除） */
  delete(id: string): boolean {
    const existing = this.findById(id)
    if (!existing) return false
    if (existing.is_builtin) {
      throw new Error('Cannot delete built-in role')
    }
    return this.db.prepare('DELETE FROM roles WHERE id = ?').run(id).changes > 0
  }

  /** 批量更新排序 */
  updateSortOrders(ids: string[]): void {
    const tx = this.db.transaction((ids: string[]) => {
      const stmt = this.db.prepare('UPDATE roles SET sort_order = ?, updated_at = ? WHERE id = ?')
      const now = new Date().toISOString()
      ids.forEach((id, idx) => stmt.run(idx, now, id))
    })
    tx(ids)
  }

  // ---------- 内部方法 ----------

  private _rowToConfig(row: RoleRow): RoleConfig {
    return {
      id: row.id,
      name: row.name,
      description: row.description,
      task_type: row.task_type as RoleConfig['task_type'],
      system_prompt: row.system_prompt,
      additional_instructions: row.additional_instructions,
      llm_overrides: JSON.parse(row.llm_overrides || '{}'),
      active_skills: JSON.parse(row.active_skills || '[]'),
      active_tools: JSON.parse(row.active_tools || '[]'),
      is_builtin: row.is_builtin === 1,
      is_active: row.is_active === 1,
      sort_order: row.sort_order,
      created_at: row.created_at,
      updated_at: row.updated_at,
    }
  }

  private _uuid8(): string {
    return Math.random().toString(16).slice(2, 10) + Date.now().toString(16).slice(-4)
  }

  /** 首次启动时种子内置角色（幂等，存在则跳过） */
  private _seedBuiltinRoles(): void {
    const count = (this.db.prepare('SELECT COUNT(*) as c FROM roles WHERE is_builtin = 1').get() as any).c
    if (count > 0) return

    const builtins: Array<Partial<RoleConfig> & { name: string; system_prompt: string }> = [
      {
        name: '通用助手',
        description: '默认角色，提供平衡的问答与工具调用能力',
        task_type: 'default',
        system_prompt: 'You are a helpful AI assistant. Answer questions accurately and use tools when needed.',
        additional_instructions: '',
        sort_order: 0,
      },
```

```typescript
function validateRoleInput(input: Partial<RoleCreateInput>): Record<string, string> {
  const errors: Record<string, string> = {}
  if (!input.name || input.name.trim().length === 0) {
    errors.name = '名称不能为空'
  } else if (input.name.length > 50) {
    errors.name = '名称不能超过 50 字符'

  if (input.system_prompt && input.system_prompt.length > 10000) {
    errors.system_prompt = '系统提示词不能超过 10000 字符'
  }
  if (input.llm_overrides?.temperature !== undefined && input.llm_overrides.temperature !== null) {
    const t = input.llm_overrides.temperature
    if (typeof t !== 'number' || t < 0 || t > 2) {
      errors.temperature = '温度必须在 0.0-2.0 之间'
    }
  }
  if (input.llm_overrides?.max_tokens !== undefined && input.llm_overrides.max_tokens !== null) {
    const m = input.llm_overrides.max_tokens
    if (typeof m !== 'number' || m < 1 || m > 8192) {
      errors.max_tokens = 'max_tokens 必须在 1-8192 之间'
    }
  }
  return errors
```

```typescript
// packages/modu-agent-server/src/routes/agent.ts

import type { FastifyInstance, FastifyPluginAsync } from 'fastify'

export const registerAgentRoutes: FastifyPluginAsync = async (app: FastifyInstance) => {
  const roleProvider = (app as any).roleProvider
  const streamResponse = (app as any).streamResponse as (
    graph: any, userId: string, sessionId: string, inputData: any,
    traceId?: string, eventBridge?: any, extraConfigurable?: Record<string, any>
  ) => AsyncGenerator
  const getRunner = (app as any).getRunner as () => Promise<any>

  /**
   * 流式调用 Agent。
   * Body: { role_id?, prompt, session_id?, user_id }
   * 响应: SSE 流（text/event-stream）
   */
  app.post('/api/agent/invoke', async (req, reply) => {
    const { role_id, prompt, session_id, user_id } = req.body as {
      role_id?: string
      prompt: string
      session_id?: string
      user_id: string
    }

    if (!prompt || !user_id) {
      return reply.code(400).send({ error: 'prompt and user_id are required' })
    }

    // ① 解析角色配置（若指定 role_id）
    let extraConfigurable: Record<string, any> = {}
    if (role_id) {
      try {
        const resolved = await roleProvider.resolve(role_id)
        extraConfigurable = resolved.configurable
      } catch (e: any) {
        app.log.warn({ role_id, err: e.message }, 'Role resolution failed, using defaults')
        // 降级：不注入角色配置，使用默认提示词
      }
    }

    // ② 获取图实例（带缓存）
    const graph = await getRunner()
    const sessionId = session_id || `sess_${Date.now()}`
    const traceId = `trace_${Date.now()}`

    // ③ 设置 SSE 响应头
    reply.raw.writeHead(200, {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      Connection: 'keep-alive',
    })

    // ④ 流式调用 modu-agent
    try {
      const stream = streamResponse(
        graph,
        user_id,
        sessionId,
        { prompt },
        traceId,
        undefined,  // eventBridge（可选）
        extraConfigurable,
      )

      for await (const event of stream) {
        // AG-UI 协议事件直接转发为 SSE
        reply.raw.write(`event: ${event.type}\n`)
        reply.raw.write(`data: ${JSON.stringify(event)}\n\n`)
      }
      reply.raw.end()
    } catch (e: any) {
      app.log.error({ err: e }, 'Stream failed')
      reply.raw.write(`event: error\n`)
      reply.raw.write(`data: ${JSON.stringify({ error: e.message })}\n\n`)
      reply.raw.end()
    }
  })
}
```

### 6.1 RolePromptProvider（角色解析器）

```typescript
// packages/modu-agent-server/src/roles/role-prompt-provider.ts

import type { RoleRepository } from '../storage/role-repository.js'
import type { RoleConfig } from './types.js'

/**
 * 解析后的角色配置，供 factory.ts 注入。
 */
export interface ResolvedRole {
  /** 原始角色配置 */
  role: RoleConfig

  /** 注入 RunnableConfig.configurable 的参数 */
  configurable: {
    role_id: string
    system_prompt: string          // 已拼接 system_prompt + additional_instructions
    temperature?: number
    max_tokens?: number
    model?: string
    llm_provider?: string
    tools?: string[]
  }
}

/**
 * 角色提示词解析器。
 *
 * 职责：
 *   1. 从 RoleRepository 读取角色配置
 *   2. 拼接 system_prompt + additional_instructions
 *   3. 过滤 null 值的 LLM 覆盖参数
 *   4. 转换为 RunnableConfig.configurable 格式
 *
 * 设计要点：
 *   - 纯函数式解析，无副作用，可缓存
 *   - 解析失败抛错，由调用方决定降级策略
 *   - 不直接修改 RuntimeConfig（保持全局配置不变）
 */
export class RolePromptProvider {
  /** 内存缓存：role_id → ResolvedRole（避免每次请求查 DB） */
  private cache = new Map<string, { resolved: ResolvedRole; ttl: number }>()
  private readonly TTL_MS = 60_000  // 60 秒缓存，平衡实时性与性能

  constructor(private repo: RoleRepository) {}

  /**
   * 解析角色配置为运行时注入参数。
   * @throws RoleNotFoundError 当角色不存在或已禁用时
   */
  async resolve(roleId: string): Promise<ResolvedRole> {
    // 命中缓存
    const cached = this.cache.get(roleId)
    if (cached && cached.ttl > Date.now()) {
      return cached.resolved
    }

    const role = this.repo.findById(roleId)
    if (!role) {
      throw new RoleNotFoundError(`Role not found: ${roleId}`)
    }
    if (!role.is_active) {
      throw new RoleNotFoundError(`Role is disabled: ${roleId}`)
    }

    // 拼接提示词：system_prompt 主体 + 附加指令
    const parts: string[] = []
    if (role.system_prompt) parts.push(role.system_prompt)
    if (role.additional_instructions) parts.push(role.additional_instructions)
    const systemPrompt = parts.join('\n\n')

    // 组装 configurable（仅包含非 null 的覆盖项）
    const configurable: ResolvedRole['configurable'] = {
      role_id: role.id,
      system_prompt: systemPrompt,
    }

    const ov = role.llm_overrides ?? {}
    if (ov.temperature !== undefined && ov.temperature !== null) {
      configurable.temperature = ov.temperature
    }
    if (ov.max_tokens !== undefined && ov.max_tokens !== null) {
      configurable.max_tokens = ov.max_tokens
    }
    if (ov.model) configurable.model = ov.model
    if (ov.provider) configurable.llm_provider = ov.provider
    if (role.active_tools && role.active_tools.length > 0) {
      configurable.tools = role.active_tools
    }

    const resolved: ResolvedRole = { role, configurable }

    // 写入缓存
    this.cache.set(roleId, { resolved, ttl: Date.now() + this.TTL_MS })
    return resolved
  }

  /** 角色变更后清缓存（由 API 层在 update/delete 后调用） */
  invalidate(roleId?: string): void {
    if (roleId) {
      this.cache.delete(roleId)
    } else {
      this.cache.clear()
    }
  }
}

export class RoleNotFoundError extends Error {
  constructor(message: string) {
    super(message)
    this.name = 'RoleNotFoundError'
  }
}
```

```tsx
  _ui: { errors: {}, isDirty: false, isSubmitting: false },
}

export function RoleEditorPage({ roleId, onBack }: {
  roleId?: string  // undefined = 新建模式
  onBack: () => void
}) {
  const [form, setForm] = useState<RoleFormState>(EMPTY_FORM)
  const [loading, setLoading] = useState(!!roleId)

  useEffect(() => {
    if (!roleId) return
    setLoading(true)
    rolesApi.get(roleId).then(({ data }) => {
      setForm({
        ...data,
        llm_overrides: {
          temperature: data.llm_overrides.temperature ?? '',
          max_tokens: data.llm_overrides.max_tokens ?? '',
          model: data.llm_overrides.model ?? '',
          provider: data.llm_overrides.provider ?? '',
        },
        _ui: { errors: {}, isDirty: false, isSubmitting: false },
      })
    }).finally(() => setLoading(false))
  }, [roleId])

  const update = <K extends keyof RoleFormState>(key: K, value: RoleFormState[K]) => {
    setForm((prev) => ({
      ...prev,
      [key]: value,
      _ui: { ...prev._ui, isDirty: true },
    }))
  }

  const validate = (): boolean => {
    const errors: Record<string, string> = {}
    if (!form.name.trim()) errors.name = '名称不能为空'
    else if (form.name.length > 50) errors.name = '名称不能超过 50 字符'
    if (form.system_prompt.length > 10000) errors.system_prompt = '系统提示词不能超过 10000 字符'
    if (form.llm_overrides.temperature !== '') {
      const t = Number(form.llm_overrides.temperature)
      if (isNaN(t) || t < 0 || t > 2) errors.temperature = '温度必须在 0.0-2.0 之间'
    }
    setForm((prev) => ({ ...prev, _ui: { ...prev._ui, errors } }))
    return Object.keys(errors).length === 0
  }

  const handleSubmit = async () => {
    if (!validate()) return
    setForm((prev) => ({ ...prev, _ui: { ...prev._ui, isSubmitting: true } }))

    // 转换为后端格式（空字符串 → null）
    const payload = {
      name: form.name,
      description: form.description,
      task_type: form.task_type,
      system_prompt: form.system_prompt,
      additional_instructions: form.additional_instructions,
      llm_overrides: {
        temperature: form.llm_overrides.temperature === '' ? null : Number(form.llm_overrides.temperature),
        max_tokens: form.llm_overrides.max_tokens === '' ? null : Number(form.llm_overrides.max_tokens),
        model: form.llm_overrides.model || null,
        provider: form.llm_overrides.provider || null,
      },
      active_skills: form.active_skills,
      active_tools: form.active_tools,
      is_active: form.is_active,
      sort_order: form.sort_order,
    }

    try {
      if (roleId) {
        await rolesApi.update(roleId, payload)
      } else {
        await rolesApi.create(payload)
      }
      onBack()
    } catch (e: any) {
      alert(`保存失败：${e.message}`)
    } finally {
      setForm((prev) => ({ ...prev, _ui: { ...prev._ui, isSubmitting: false } }))
    }
  }

  if (loading) return <div className="loading">加载中...</div>

  return (
    <div className="role-editor-page">
      <header className="page-header">
        <button onClick={onBack} className="btn-ghost">← 返回</button>
        <h1>{roleId ? '编辑角色' : '新建角色'}</h1>
        <button
          onClick={handleSubmit}
          disabled={!form._ui.isDirty || form._ui.isSubmitting}
          className="btn-primary"
        >
          {form._ui.isSubmitting ? '保存中...' : '保存'}
        </button>
      </header>

      {/* 基础信息 */}
      <section className="form-section">
        <h2>基础信息</h2>
        <label className="form-field">
          <span>角色名称 *</span>
          <input
            value={form.name}
            onChange={(e) => update('name', e.target.value)}
            maxLength={50}
            placeholder="如：数据分析专家"
          />
          {form._ui.errors.name && <em className="error">{form._ui.errors.name}</em>}
        </label>

        <label className="form-field">
          <span>简述</span>
          <input
            value={form.description}
            onChange={(e) => update('description', e.target.value)}
            placeholder="如：擅长 SQL 查询、数据可视化、统计建模"
          />
        </label>

        <label className="form-field">
          <span>角色类型</span>
          <select
            value={form.task_type}
            onChange={(e) => update('task_type', e.target.value as any)}
          >
            <option value="default">通用</option>
            <option value="research">研究</option>
            <option value="coding">编程</option>
            <option value="review">审查</option>
          </select>

          label="系统提示词（核心角色设定）"
```

## 9. 热更新与缓存失效策略

### 9.1 三层缓存与失效机制

| 层级 | 缓存对象 | 失效触发 | 实现位置 |
|------|---------|---------|---------|
| L1: RolePromptProvider | `role_id → ResolvedRole` | 角色更新/删除时调用 `invalidate()` | role-prompt-provider.ts |
| L2: runner 图缓存 | `config_hash → ModuGraph` | `llm.*` 等前缀变更触发 `reset_runner_cache()` | runner.ts:61 |
| L3: SQLite WAL | 数据库页缓存 | WAL checkpoint | better-sqlite3 内部 |

### 9.3 为什么角色变更不需要重建图？

关键洞察：**角色提示词通过 `configurable` 注入，属于请求级配置，不在图构建期固化**。

```
图构建期（create_agent，被缓存）：
  - 绑定工具集（受 tools 配置影响）→ 需重建
  - 构建 LLM（受 provider/model 影响）→ 需重建
  - 闭包持有 effectiveSystemPrompt → 看似需重建，但...

请求执行期（graph.stream，每次新执行）：
  - configurable 通过 RunnableConfig 传入
  - factory.ts 读取 configurable['system_prompt'] → 每次请求重新读取
```

**但有一个陷阱**：`create_agent` 在图构建期就把 `effectiveSystemPrompt` 固化到了 `makeAgentNode` 闭包中。因此 `configurable['system_prompt']` 必须在 `create_agent` 调用时就被填充。

**解决方案**：`stream_response` 的 `extraConfigurable` 参数会在 `create_agent` 之前合并到 `configurable`，确保角色提示词在图构建期就可用。由于不同角色会产生不同的 `configurable`，会导致图缓存失效重建——这是可接受的性能开销（角色切换是低频操作）。

### 9.4 优化：角色提示词延迟到请求期注入（避免图重建）

若希望切换角色不触发图重建，可将提示词注入从「工厂装配期」后移到「节点执行期」：

```typescript
// 方案 B（可选优化）：nodes.ts 的 agentNode 内动态读取角色提示词

async function agentNode(state: ModuAgentState): Promise<Partial<ModuAgentState>> {
  const messages: BaseMessage[] = [...(state.messages ?? [])]

  // ★ 从 state.config_overrides 或 configurable 动态读取角色提示词
  const roleId = state.config_overrides?.['role_id']
  let dynamicSystemPrompt = systemPrompt  // 闭包持有的默认值
  if (roleId) {
    const rolePrompt = state.config_overrides?.['system_prompt']
    if (rolePrompt) dynamicSystemPrompt = rolePrompt
  }

  if (dynamicSystemPrompt && ...) {
    messages.unshift(new SystemMessage({ content: dynamicSystemPrompt }))
  }
  // ... 其余不变 ...
}
```

> **取舍**：方案 B 避免图重建，但需要修改 `nodes.ts`（侵入核心）。方案 A（默认推荐）零侵入但切换角色会重建图。考虑到角色切换低频，**推荐方案 A**。

```typescript
    await provider.resolve(role.id)
    // 删除 DB 数据，缓存仍应命中
    repo.delete(role.id)
    const resolved = await provider.resolve(role.id)
    expect(resolved.role.id).toBe(role.id)
  })

  it('invalidate 后缓存失效', async () => {
    const role = repo.create({ /* ... */ })
    await provider.resolve(role.id)
    provider.invalidate(role.id)
    // 删除后应抛错（缓存已失效，重新查 DB）
    repo.delete(role.id)
    await expect(provider.resolve(role.id)).rejects.toThrow()
  })
})
```

## 附录 A：为什么选择这个设计

### A.1 为什么不直接改 factory.ts 加角色读取逻辑？

**保持 SDK 职责单一**。`modu-agent` 是纯 Agent 框架，不应感知「数据库」「角色表」「HTTP」等宿主概念。通过 `configurable` 注入实现了**控制反转**：SDK 只知道「`configurable['system_prompt']` 优先级最高」，至于这个值来自哪里（角色表、配置文件、环境变量）由宿主决定。

### A.2 为什么用 SQLite 而非 Prisma？

项目已依赖 `better-sqlite3`（checkpointer + event log），复用现有依赖零成本。角色数据量小（通常 < 100 条），SQLite 单文件部署足够。Prisma 会引入 schema migration 体系，对一个轻量配置场景过重。

### A.3 为什么 RolePromptProvider 要加缓存？

`stream_response` 每次请求都会调用 `RolePromptProvider.resolve()`。虽然 SQLite 读单行很快（< 1ms），但在高并发 SSE 场景下避免重复查询仍有价值。60 秒 TTL + 变更主动失效，平衡了实时性与性能。

### A.4 为什么前端用 React + Vite？

符合用户技术栈偏好（见 user_profile）。Vite 提供快速 HMR，React 生态成熟。表单场景无需 SSR，SPA 模式足够。
