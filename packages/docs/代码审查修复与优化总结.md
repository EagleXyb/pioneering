## 二、P0 功能正确性与安全缺陷（逐项说明）

### 1. state 膨胀：节点返回全量 × 追加 reducer 导致翻倍

- **原因**：`state.ts` 中 `tool_results`/`artifacts` 使用 append reducer（`[...prev, ...next]`），而 `toolResultProcessor` 先复制 `state.tool_results` 全量再整体返回；`responseNode` 同样回写全量。二者叠加后每轮结果翻倍，统计虚高、checkpoint 体积暴涨。
- **改动**：节点改为只产出增量（`newToolResults`），`responseNode` 不再回写 `tool_results`/`artifacts`（state 中本就保留）。
- **范围**：`src/graph/nodes.ts`、`src/graph/state.ts`（reducer 语义不变）。
- **效果**：`tool_results` 长度 = 真实工具调用次数；`_buildFallbackResponse` 统计准确；checkpoint 序列化体积不再随轮次膨胀。

### 2. doc_writer 强制计数跳变

- **原因**：节点返回 `(prev)+1` 的绝对值，reducer 又累加 → 1 → 3 → 7，使「最多强制 2 次」的路由判断失真。
- **改动**：返回增量 `1`（与同文件 `doc_writer_fail_count` 一致）。
- **效果**：计数与路由阈值语义一致。

### 3. Store 批量操作把 Get 当 Delete 执行

- **原因**：分支顺序 `value != null → put` / `key != null → delete`；GetOperation 同样无 `value` 且带 `key`，必然落入删除分支，末尾 get 分支永不可达。
- **改动**：抽出共享执行器 `_runBatchOps`（同时消除两个 Store 的重复实现），按 `value` 判 Put、`namespacePrefix` 判 Search；`{namespace, key}` 优先使用 `op.type` 判别，缺失时**保守按 Get 处理**（宁可不删，绝不误删）。
- **效果**：批量读不再触发删除；两个 Store 行为一致，后续修改只需改一处。

### 4. Guardrail 规则永不命中

- **原因**：规则参数名写 `mode`/`sql`，而 `FileOpsTool` 实际参数是 `op`、`SqlQueryTool` 是 `query` → 三条核心规则（文件写/删、SQL 写）永远匹配不上；`operation_type` 是死字段。
- **改动**：参数名修正为 `op`/`query` 并改用精确匹配（`=` 前缀，避免枚举值子串误判）；`operation_type` 在调用方显式提供时参与过滤；`code_executor` 的 `net` 子串改为 `net.`/`node:net` 等精确特征；SQL 黑名单补 `REPLACE`、`LOAD_EXTENSION`。
- **配套**：同步修正 `tests/tools/tool-guardrails.test.ts`（原用例复刻了错误参数名才"通过"），并新增反向回归断言（传旧参数名 `mode`/`sql` 时不得命中规则层）与精确匹配用例。
- **效果**：安全策略从"文档声明有效、实际靠矩阵兜底"变为细粒度规则真正生效。

### 5-7. HTTP 工具 SSRF 与响应体防护

- **原因**：(a) `_validateUrl` 用 `dns.lookup` 校验后，`fetch(url)` 重新解析 DNS → DNS Rebinding 可绕过；(b) `_isPrivateIp` 不识别 `::ffff:10.0.0.1` 等 IPv4-mapped IPv6；(c) 超时定时器在响应头到达后即清除，`arrayBuffer()` 无超时且先整体缓冲再截断。
- **改动**：
  - 校验返回"已校验 IP"，新增 `_requestPinned()`：通过 http/https 的 `lookup` 钩子把连接钉死在已校验 IP，同时保留原 hostname 作为 SNI 与 Host 头（保证 TLS 证书校验正常）；不跟随重定向。
  - `_isPrivateIp` 归一化方括号、还原 `::ffff:`/6to4 内嵌 IPv4 后判定。
  - 响应体改为流式读取，超过 `maxResponseBytes` 立即中断连接；socket 不活跃超时覆盖 body 阶段。
  - 过滤用户传入的受限请求头（Host/Connection/Content-Length/Transfer-Encoding）。
- **效果**：消除 DNS Rebinding 与映射地址绕过；大响应不再撑爆内存；body 阶段受超时保护。

### 8. datetime 时区计算错误

- **原因**：`utcMs = now.getTime() + now.getTimezoneOffset()*60000` 把 epoch 平移成"本地挂钟伪装 epoch"，再取 `getTime()`/`toISOString()`，非 UTC 宿主机偏差 `getTimezoneOffset()`（东八区 8 小时）。
- **改动**：`unix_timestamp` 直接取 epoch 秒；挂钟时间 = `epoch + 目标偏移`，全部用 UTC getter 读取；`_strftime` 增加 `utc` 参数，`_convert` 的目标时间同样按 UTC 字段渲染。
- **配套**：新增回归测试（epoch 秒与 `Date.now()` 对齐；CST 挂钟小时 = UTC+8；不再依赖宿主机时区）。

### 9-10. doc_writer 审批与路径校验

- **原因**：`doc_writer.requiresApproval()` 无条件下 `false`（与同为写盘工具的 file_ops 策略不一致）；两处 `_validatePath` 的盘符正则 `/^[CDEF]:/i` 漏掉 G: 及之后的驱动器相对路径。
- **改动**：`doc_writer` 默认需审批并实现 `requiresApprovalFor`（read/list 豁免）；盘符检查改为任意盘符 + `path.parse().root` 校验，两处同步。
- **效果**：写盘行为纳入 HITL；Windows 驱动器相对路径不再逃逸工作区。

### 11. sql-query 只读保证

- **原因**：以读写模式打开，唯一写防护是可静默失败（空 catch）的 `query_only` pragma。
- **改动**：文件库改用连接级 `readonly: true` + `fileMustExist: true`（内存库不支持 readonly，保留原路径 + pragma + 黑名单）；pragma 失败改为告警；依赖缺失错误码从 `SQL_003` 拆分为 `SQL_005`（原码与"SQL 执行错误"同码不同义）。
- **效果**：只读保证落在连接层；错误码可区分排障。

## 三、P1 性能与逻辑冗余

| 项 | 原因 | 改动 | 效果 |
|---|---|---|---|
| 流式日志 | `_normalizeLangGraphStream` 与 `event-bridge.consume` 在 messages 模式下每 token 输出 4-6 条同步 `console.info`，含 `Object.keys` + `%j` 序列化 | 全部降级 `logger.debug`，删除 keys/JSON 序列化，仅保留首尾汇总 | 热路径 I/O 与格式化开销下降，首 token 延迟改善，错误日志不再被淹没 |

## 四、P2 冗余、可读性与可维护性

1. **配置脱节收口**：`DEFAULT_CONFIG` 补齐 `plan_execute.planner_max_tokens`、`plan_execute.step_retry.{default_max_attempts,default_base_delay}`、`tools.register_defaults`；删除零消费且危险的 `llm.tool_call_pattern`（RegExp 对象，一旦被消费会被 `get()` 的浅拷贝破坏）。`UNDECLARED_CONSUMED_KEYS` 清空为回归哨兵，配套测试改为断言"必须为空"。

## 七、整体优化方向（后续路线）

1. **状态契约单一化**：为 `state.ts` 每个字段标注"节点应返回增量还是全量"，并加自动化回归（任意节点执行后不得出现重复 id），从机制上消灭 reducer 语义错配。
2. **安全能力共享内核**：把 URL/IP 校验、路径校验、超时/重试、错误码枚举、logger 工厂收敛到共享模块，避免"写了但没接线/复制后失配"再次发生。
3. **配置 SSOT**：zod 定义全量 ConfigSchema，`z.infer` 派生类型，`DEFAULT_CONFIG` 由 schema 派生，并用 CI 静态比对所有 `config.get()` 字面量。
4. **可观测性与生命周期对齐**：统一 logger 与级别、metrics 补 `ready()`、单例订阅配置变更、exporters 默认参数从配置读取。
5. **按风险补测 + 跨包契约层**：优先主干（nodes/factory/runner/agui-adapter/reasoning/memory），并把跨包依赖符号固化为契约测试。
