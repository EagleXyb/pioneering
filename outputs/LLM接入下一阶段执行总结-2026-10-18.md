# LLM 接入下一阶段执行总结（P5）

> 日期：2026-10-18
> 范围：图缓存 / 上下文预算 / SSE 回放 / 密钥来源 / 评测门禁 / 成本看板
> 原则：先做收益确定且不改协议的（P5-1），再做协议与基础设施（P5-2/3），最后做门禁与 UI（P5-4/5）

## 一、优先级与理由

| 顺序 | 事项 | 优先级理由 | 风险 |
|---|---|---|---|
| P5-1 | 图缓存 + chat 上下文预算 | 直接降低首 token 延迟与重建成本；不改协议 | 低 |
| P5-2 | SSE 事件 id + 断线回放 | 解决断网/切页丢内容；协议变更需谨慎 | 中 |
| P5-3 | 密钥来源抽象（env/file） | 把明文从 `.env` 移到可挂载文件；桌面已有 key-store | 低 |
| P5-4 | 评测门禁（eval:gate） | 模型升级的质量闸门；依赖真实模型 | 中 |
| P5-5 | 成本看板 UI | 让成本可观测；依赖前四项的数据 | 低 |

| 项 | 内容 |
|---|---|

### P5-2 SSE 事件 id + 断线回放

| 项 | 内容 |
|---|---|
| 事件缓冲 | 新增 `core/run-events.ts`：单调 seq、回放窗口 5 分钟、运行中订阅、TTL 清理 |
| 写帧 | chat 流统一走 `writeFrame`：`id: <seq>` + 原始 SSE 帧；断连后继续缓冲 |

## 四、发现的问题

### 1. 评测 smoke 基线 0/6（阻断项）

`eval:smoke` 6 条用例全部失败。典型表现：

- 用例 `core-calc-001` 期望最终答案 `4053`
- 实际返回「本次任务共执行 1 次工具调用（成功 1 次），涉及工具：calculator」
- 即：工具调用成功，但最终答复被**过程叙述**替代

这不是评测器误判，而是 Agent 通道在工具轮次后的最终答复选择问题。建议单独作为 P6 最高优先级修复；在修复前 CI 保持观察模式。

### 2. 回放粒度

chat 流中 `THINKING_START` 与 `THINKING_TEXT_MESSAGE_START` 可能合并为一帧，共用一个 seq。对断线续读无影响（整帧到达或整帧丢失），但事件 id 不是严格“一事件一 id”。

### 3. Agent 通道尚未接入回放

本次只覆盖 chat：pro/task 仍走 `streamCompletion` + `monitorAguiResponse`，没有事件 id 与回放接口。HITL resume 已有独立语义，后续再统一。

## 五、风险与回滚

| 项 | 风险 | 回滚 |
|---|---|---|
| 图缓存 | prompt/工具变化后复用旧图 | 清空进程缓存（重启）；缓存 key 已含 model/system_prompt/mode/domain |
| 事件缓冲 | 内存增长 | 单运行 10000 事件上限 + 5 分钟 TTL |
| chat 续读 | 运行已过期返回 404 | 前端按普通网络错误提示，可手动重试 |
| 密钥 file | 文件缺失/权限错误 | 自动回退 env，并打印告警 |
| 评测门禁 | 基线未达标阻断 PR | 当前 `continue-on-error`，修复后移除 |

## 六、下一步（P6 建议）

1. **修复工具轮次后的最终答复丢失**（评测 0/6 的根因），修复后把 eval gate 改为阻断。
2. **Agent 通道事件 id + 回放**，并让 pro/task 走统一 `requestAguiStream`。
3. **密钥轮换**：file provider 增加 mtime 监听或定时重载；后续接 Secret Manager。
4. **图缓存命中率指标**（构建次数 / 命中次数）接入 `/observability/metrics`。
5. **成本看板**增加时间范围切换与导出。
