# LLM 接入 P6 修复总结：工具调用后最终答复丢失

> 日期：2026-10-18
> 触发：P5 评测 smoke 基线 0/6，工具执行成功但用户只看到过程叙述
> 结果：根因修复，`eval:gate` 从 0/6 恢复到 **PASS**，CI 门禁改为阻断模式

---

## 一、问题现象

- `core-calc-001` 期望 `4053`，实际返回「本次任务共执行 1 次工具调用（成功 1 次），涉及工具：calculator。」
- 同批次 6 条 smoke 全部失败，但部分回答（日期、翻译、多步计算）内容本身正确。
- 评测总分 0.2985，system 层 0.0000。

---

## 二、根因（三个独立缺陷）

### 1. `responseNode` 不识别 `AIMessageChunk`（主因）

`packages/modu-agent/src/graph/nodes.ts` 的最终响应节点只判断 `msg instanceof AIMessage`。
流式 / 函数调用下 LangGraph 返回的是 `AIMessageChunk`，它不是 `AIMessage` 的子类：

- 最终答案被跳过 → 落到「工具调用摘要」兜底；
- 评测与线上 Agent 通道同时受影响。

同一问题也存在于子图 `subgraph/builder.ts` 的最终输出提取。

### 2. Judge 输出被 `max_tokens=256` 截断

`packages/evals/config/global.yaml` 的 `judge.max_tokens` 为 256，Judge 模型（推理模型）先消耗 reasoning，
JSON 只剩 `{"relevance` 这类残片 → 解析失败 → 回退 rule → `accuracy` 缺失被记 0。

### 3. 参考答案匹配过于字面

`system_ground_truth_match` 只用子串/bigram：
- 「第三季度」vs「第 **3** 季度」不匹配；
- 翻译语序不同（Know yourself... vs Know the enemy...）得分 0.06；
- 语义正确的解释因措辞不同被判 0。

---

## 三、修复内容

### 3.1 内核

| 文件 | 修改 |
|---|---|
| `packages/modu-agent/src/graph/nodes.ts` | `responseNode` 接受 `AIMessageChunk`；历史转换、提前终止检测、doc finalize 同步兼容 |
| `packages/modu-agent/src/graph/subgraph/builder.ts` | 子图最终输出接受 `AIMessageChunk` |
| `packages/modu-agent/src/feedback/quality-monitor.ts` | Judge JSON 截断时按字段正则抽取，不再整体判失败 |
| `packages/modu-agent/src/config/runtime-config.ts` | `quality_monitor_llm_max_tokens` 256 → 4096 |

### 3.2 评测

| 文件 | 修改 |
|---|---|
| `packages/evals/config/global.yaml` | `judge.max_tokens=4096`、`timeout_seconds=60`；SUT 温度 0；`llm.max_tokens=8192` |
| `packages/evals/src/metrics.ts` | `toToolCallRecord` 兼容 `status='success'`；数字归一化；英文按词 / 中文 bigram 取高；`ground_truth_aliases`；Judge 高准确率时视为语义等价 |
| `packages/evals/src/dataset-loader.ts`、`types.ts` | 支持 `ground_truth_aliases` |
| `packages/evals/src/report.ts` | 失败项附带 `metrics` 与 `responseSnippet`，便于 CI 定位 |
| `packages/evals/data/cases/core.yaml` | ReAct 用例补充等价表述 |
| `.github/workflows/llm-ci.yml` | 移除 `continue-on-error`，`eval:gate` 改为阻断 |

## 五、影响与注意事项

1. **生产行为变化**：Agent 通道在工具调用后会返回真实答案，而非过程摘要；这是修复，不是行为回归。
2. **Judge 成本**：`quality_monitor_llm_max_tokens` 默认提高到 4096，仅在 `quality_monitor_mode=llm/hybrid` 时产生费用；默认 `rule` 模式无影响。
3. **评测耗时**：smoke 门禁约 75s（Judge 4096 tokens + 并发 4）；CI 需允许该时长。
4. **语义等价兜底**：`ground_truth_match` 在字面分 < 0.5 且 Judge accuracy ≥ 0.8 时抬到 0.6；
   属于测试口径的务实处理，release 门禁可考虑更严格的独立 Judge。
5. **残留波动**：模型偶尔多调一次失败工具（calc-002），聚合门禁可通过；后续可用 `retries` 或工具选择约束降低波动。

---

## 六、后续建议

1. 为 `eval:smoke` 增加单用例重试（runner 已有 retries 配置，可调为 2）。
2. 将 `ground_truth_aliases` 推广到 full/regression 数据集。
3. 观察 Judge 4096 预算下的平均耗时与成本，必要时按模式（rule/llm/hybrid）分别配置。
4. 若后续接入非推理 Judge 模型，可下调 `max_tokens` 并恢复 15s 超时。
