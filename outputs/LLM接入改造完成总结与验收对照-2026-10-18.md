## 二、当前架构（单宿主形态）

```text
apps/web
  ├─ api/base-url           运行时 API base（无硬编码 /api）
  ├─ api/capabilities       GET /capabilities
  ├─ hooks/useCapabilities  目录缓存
  ├─ hooks/useModelOptions  能力驱动 + /system/models 回退
  ├─ lib/sseClient          统一请求、空闲看门狗、错误分级
  └─ modes/{chat,pro,task}  同一流客户端

apps/backend-ts
  ├─ routes/chat            限流 → 幂等 → 配额预扣 → 网关 → AG-UI
  ├─ routes/agent           限流 → 配额 → modu-agent（注入 resolver）
  ├─ routes/capabilities    目录能力
  ├─ routes/observability   metrics / costs / settings
  ├─ core/llm               AG-UI 适配层 + 指标，保留 legacy 开关
  ├─ core/llm-gateway       宿主装配（目录 + env + policy）
  ├─ core/idempotency       非流式幂等
  ├─ core/quota(-reservation) 预扣/结算/释放
  ├─ core/metrics           TTFT / 截断 / 401 / 断线
  └─ plugins/rate-limit     用户 / 模型固定窗口

packages/llm-gateway → llm-core / llm-adapters → llm-contracts
packages/modu-agent        内核零厂商依赖；宿主注入连接解析器
```

## 四、E2E 实测结果（2026-10-18）

环境：本机后端 `127.0.0.1:8088`，真实 DeepSeek Key，Postgres 可用。

| 场景 | 结果 |
|---|---|
| `GET /health` | 200 |
| 注册 / 登录 | 200，JWT 正常 |
| `GET /capabilities` | 200，返回 `fast` / `reasoning`，含 capabilities/context_window/status |
| 非流式 chat（`model=fast`） | 200，内容「好的」，usage 35/2/37，model `deepseek-v4-flash` |
| 流式 chat | 事件计数：RUN_STARTED / THINKING_* / TEXT_MESSAGE_CONTENT×17 / TEXT_MESSAGE_END / RUN_FINISHED |
| deepThink 非流式（maxTokens=400） | 200，model `deepseek-v4-pro`，内容「思考完成」 |
| `Idempotency-Key` 连发两次 | 两次返回同一 `chatcmpl_*` id，第二次未重新调用上游 |
| Agent react_agent 非流式 | 200，「好的」，1.1s |
| Agent plan_execute 非流式 | 200，「好的」，2.4s，含 thinking 块 |
| Agent `model=reasoning` | 200；日志 `Building ChatOpenAI ... model=deepseek-v4-pro` |
| Agent 会话模型字段 | 创建返回 `model: "fast"`（别名已落库） |
| `GET /system/models` | 字段为 `context_window`，`max_tokens` 已移除 |
| `GET /observability/costs` | 200，3 请求 / 196 tokens / $0.000045 |
| `GET /observability/metrics` | 含 `pioneering_llm_requests_total{status="success"} 3`、`truncated 1`、TTFT sum/count |

**E2E 发现的问题**

1. `deepThink` + `maxTokens=64` 时，推理内容耗尽输出预算 → `finish_reason=length`、正文为空，接口返回 502。建议对推理模型设置最小输出预算（如 ≥256）或在空正文时自动重试一次更大预算。
2. 推理模型默认会先输出 `reasoning_content`，前端需要保证「只有思考、没有正文」时给出可读提示（现有 pro 模式已有空回答兜底，chat 模式未验证）。

## 七、运行与回滚

```bash

npm run build:packages

# 后端
cd apps/backend-ts && npm run dev

# 测试
cd apps/backend-ts && npm test
cd apps/web && npm test
```

| 回滚点 | 动作 |
|---|---|
| chat 网关 | `LLM_GATEWAY_ENABLED=0` |

| 限流 | `RATE_LIMIT_USER_RPM=0` / `RATE_LIMIT_MODEL_RPM=0` |
| 幂等 | 不传 `Idempotency-Key` 即旧行为 |
| 配额预扣 | 代码级回退（无独立开关） |

## 八、建议的下一阶段

1. **SSE 事件 id 与续传**（TC-16/19/27）：与任务事件表一起设计，避免两次改协议。
2. **图缓存与上下文预算**（TC-24/25）：对首 token 与成本影响最大。
3. **密钥托管**（TC-28）：后端接 Secret Manager，桌面接 key-store。
4. **成本看板 UI**（TC-31）：需要先确定管理页入口。
5. **护栏影子观察**（TC-29）：在 staging 开启 `enabled=true` 跑一周，统计误拦/漏拦后再 `shadow=false`。
6. **评测门禁**（TC-32）：固定题集 + CI，模型升级前阻断。
