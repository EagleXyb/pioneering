# apps/desktop 修复任务清单（按优先级）

- 来源：《desktop-ui功能分析报告-2026-10-05.md》，逐条回源确认，全部行号以工作树（HEAD `d133c2c` + AccountMenu 未提交改版）为准。
- 优先级定义：P1 = 功能错误或真实资源损耗；P2 = 误导用户 / 安全隐患 / 架构债；P3 = 死路交互与半成品（伤可信度但不伤功能）；P4 = 有意占位（仅需文案或排期标注）。
- 「改动面」标注是否跨包：仅 desktop 可自闭环，或需联动 packages/modu-agent / apps/backend-ts 契约。

## P1 —— 先修（正确性与 token 成本）

### T1. IPC 抢占发送产生孤儿 run（烧 token）
- 现状：流式中发送新消息走 `chatStore.ts:677-699`，只 `abortController.abort()`（渲染端退订），不调 `transport.stop()`；主进程 `executeSend` 继续跑到自然结束。停止按钮路径已修（`chatStore.ts:984-993`），两处语义不一致。
- 方案：抢占分支对齐停止按钮——对 Agent 通道（`useAgent` 时）追加 `void getTransportForRuntime(targetSession?.runtime).stop(sid).catch(()=>{})`；普通聊天沿用 `chatService.stopGeneration`。
- 文件：`stores/chatStore.ts`。改动面：仅 desktop。
- 验收：本地 IPC 模式流式中直接发新消息，主进程日志出现 `stopRun aborted=true`，旧 run 事件提前终止（不再有旧 runId 的后续 AGENT_EVENT）。

### T2. 本地模式 getHitlState 不透传 artifacts
- 现状：`main/agent-runtime.ts:454-468` 返回体缺 `artifacts` 字段（类型 `HitlStateResponse` 与云端均支持），本地 plan_confirm 恢复场景丢产物列表。
- 方案：补 `artifacts: (state['artifacts'] as HitlArtifact[]) ?? undefined`。
- 文件：`main/agent-runtime.ts`（+`main/__tests__/agent-runtime.test.ts` 断言）。改动面：仅 desktop。
- 验收：单测覆盖 state 载荷含 artifacts 时透传、缺省时 undefined。

### T3. TaskMonitor「待办」硬编码示例数据
- 现状：`TaskMonitor.tsx:44-49` DEFAULT_TODO_ITEMS 为 4 条与任何会话无关的"已完成"历史示例，右栏默认打开即展示（`rightPanelStore` 默认标签 = monitor）。
- 方案分两步：① 立即——默认值改为空数组走「暂无待办项」空态（`TaskMonitor.tsx:341-343` 已有空态分支）；② 数据接线——消费已有 `plan-step` TraceNode（STATE_DELTA 已在 stream-handler 落地，`stream-handler.ts:550-586`），把当前会话 plan-step 节点映射为待办项（标题=description、完成态=status），历史会话取最后一条 assistant 消息的 traceNodes。
- 文件：`right-panel/TaskMonitor.tsx`。改动面：仅 desktop（数据源已存在）。
- 验收：普通会话右栏不再出现无关待办；plan_execute 轨迹下待办与步骤状态同步。

### T4. 图片发送全链路断（UI 完整、模型永远收不到图）
- 现状：附件三入口 + 20MB 校验 + 气泡缩略图全可用，但 `SendMessageRequest`（`shared/types.ts:107-131`）无 images 字段；纯图消息发英文占位字面量 `'[User attached images without additional text.]'`（`image-attachments.ts:25` → `InputArea.tsx:855`）；内核 image_processor 未注册（modu-agent 侧）。
- 方案（跨包，需契约评审，分三段落地）：
  1. desktop：`SendMessageRequest.images?: AttachedImage[]`（复用现有 AttachedImage），chatStore 发送时携带；占位字面量改为约定哨兵（或由后端按 images 非空省略文本）；
  2. 本地通道：`agent-runtime.validateSendRequest` 白名单放行 images → `inputData` 传入 `history/prompt` 结构（modu-agent `input_type:'image'` 分支需内核支持，见 3）；云端通道：backend-ts completions 端点透传；
  3. modu-agent：注册 image_processor / 多模态消息构造（属 packages 侧排期）。
- 前置决策：桌面端仅做 1+2 时模型仍看不到图（内核不支持），故建议整包立项，或临时在 UI 上把图片附件标注「仅本地记录，暂不发送给模型」消除误导（低成本止血，2 行文案）。
- 改动面：desktop + backend-ts + modu-agent。

## P2 —— 尽快修（误导 / 安全 / 架构债）

### T5. 「检查更新」假结果
- 现状：`AboutSection.tsx:144-153` 用 `Math.random() > 0.2` 决定"已是最新/出错"，用户会得到虚假反馈；主进程 `APP_CHECK_UPDATE` 仅回传版本号（`ipc-handlers.ts:290-294`）。
- 方案：接入真实 updater 前，按钮点击直接展示"当前版本 vX，暂无自动更新通道"（或调用 `appApi.checkUpdate()` 回显版本），删除随机逻辑。
- 文件：`settings/sections/AboutSection.tsx`。改动面：仅 desktop。

### T6. 模型选择三处断裂 + apiKey 明文
- 现状：输入框下拉硬编码 `MODEL_OPTIONS`（`InputArea.tsx:212-220`）与设置页 `modelConfigs/defaultModel`（localStorage persist，apiKey 明文）零连通；本地 IPC 模式 model 被 `validateSendRequest` 丢弃；'Auto' 原样发给云端。
- 方案：① ModelSelect 改为读 `useAppStore.modelConfigs`（enabled 项 + defaultModel），保留"配置模型"跳设置入口；② apiKey/apiBase 迁入既有 safeStorage 受管键通道（SECURE_KEY_SET 已含图缓存失效），localStorage 不再存敏感值；③ 本地模式如需按会话换模型，内核侧要求 model 进入 config hash 或提供运行时覆盖——短期可先在 UI 标注"本地模式模型以设置页密钥配置的 LLM_DEFAULT_MODEL 为准"。
- 文件：`InputArea.tsx`、`ModelSection.tsx`、`useAppStore.ts`、（可选）`agent-runtime.ts`。改动面：desktop 为主。

### T7. SecuritySection 装饰开关
- 现状：10 组 useState（含"沙箱安全"默认显示开）无持久化无副作用（`SecuritySection.tsx:37-46`），与实际安全实现（IPC 校验/iframe sandbox）零耦合，构成安全错觉。
- 方案：短期整页标注"规划中"并禁用视觉态（灰显）；中期把可落地项（如「渲染端外链策略」）接真实开关，其余保持占位。
- 文件：`SecuritySection.tsx`。改动面：仅 desktop。

### T8. chatStore ↔ hitlStore 循环 import
- 现状：chatStore 顶层 import hitlStore，hitlStore import chatStore（模块级互相引用，靠运行时时序侥幸）。
- 方案：hitlStore 对 chatStore 的访问改为惰性 `require`/回调注入（store 文件内已有 `useChatStore.getState()` 用法，保留），删除任一侧顶层 import——推荐 hitlStore 通过依赖注入接收 `resume/abort/recover 落库` 回调，在 App 启动时接线；或抽 `hitl-bridge` 模块承载两 store 协作函数。
- 验收：`madge --circular`（或等价脚本）对 stores 目录零环。改动面：仅 desktop。

### T9. 草稿图片 base64 同步整档写 electron-store
- 现状：草稿（含 ≤20MB 图 base64）经 `STORE_SET` 写主进程，主进程 JSON 往返 + 同步整档落盘，高频编辑会阻塞主进程。
- 方案：图片附件落 `userData/draft-assets/<id>`（FILE_WRITE 或主进程专用通道），草稿仅存引用；草稿写节流加大（现有 debounce 基础上限制 value 体积阈值超限跳过图片）。
- 文件：`hooks/use-input-draft-persistence.ts`、`lib/input/input-drafts.ts`、（配套）`ipc-handlers.ts`。改动面：仅 desktop。

### T10. agentMode=plan_execute 无 UI 入口（透传链全、无法触发）
- 方案：Composer 增加「计划模式」开关（命令面板 `/plan` 正好收口为真实动作——与 T11 合并实现），写入会话 `agentMode='plan_execute'`（createSession 支持入参 + 本地库列已具备）；注意内核组合模式 plan_execute 入口边缺陷（memory 记录 graph.ts:670 unknown destination）需 modu-agent 侧先修复，故本任务标"依赖内核"。
- 改动面：desktop + modu-agent。

## P3 —— 排期修（死路交互清理）

### T11. 斜杠命令无执行器（/clear /plan /agent /help /optimize）
- 方案：先落地前端可自闭环的两个——`/clear`（清空当前会话消息与草稿，等价删除会话或新建）、`/agent`（复用 toggle-agent 动作）；`/plan` 归入 T10；`/help` 打开设置-关于或快捷键页；`/optimize` 无后端能力，从注册表移除（`CommandPalette.tsx:77-148` 注释明言"仅收录已落地能力"，现状自相矛盾）。同时处理 Skill 前缀：`selectedSkill` 无设置入口（仅草稿恢复路径），实现技能选择器或移除 `[Skill: x]` 拼接与 badge。
- 验收：命令面板每条命令选中后均有可观察效果；`applyCommand` 无空动作分支。

### T12. ChatHeader 搜索/分享/历史死按钮
- 方案：分享复用 `chatStore.shareSession`（与 SessionActionsDropdown 同逻辑，直接接线）；搜索实现会话内消息查找（列表定位 + 高亮，复用 highlightMessageIdAtom 机制）；历史可暂移除（侧栏即历史）。最小修 = 接分享 + 隐藏另两个。
- 文件：`layouts/ChatHeader.tsx:91-93`。

### T13. 插件页死路与态丢失
- 方案：安装态 `installedNames` 持久化（localStorage 或 store key）；「添加」按钮接"导入本地插件（占位对话框）"或禁用并 tooltip"即将开放"；「技能/工作伙伴」Tab 保持占位但禁用安装入口暗示。整页加"演示数据"角标（诚实性）。
- 文件：`pages/PluginsPage.tsx:351-445`。

### T14. 自动化页无持久化无调度
- 方案分级：① 最小——任务列表持久化（store key）+「运行记录」Tab 标注"待接入调度"；② 完整——对接调度（QoderWork cron / backend 定时能力），触发时经 Transport 发一次 Agent run 并落会话。②跨系统，单独立项。
- 文件：`pages/AutomationPage.tsx:240-295`。

### T15. WorkspacePage 空转路由
- 方案：产物卡加「在工作区打开」调 `openFile`（FILE_READ 已有），并给编辑器加保存（FILE_WRITE）；或短期从路由/导航摘除避免"看得见进不去"。
- 文件：`pages/WorkspacePage.tsx`、`stores/useWorkspaceStore.ts`。

### T16. 测试债：match-accelerator 5 例平台断言漂移
- 方案：测试注入平台参数或 vi.mock `isMacPlatform`（`lib/match-accelerator.ts:29` 读真 navigator），使 CI 跨平台稳定。
- 文件：`lib/__tests__/match-accelerator.test.ts`。
