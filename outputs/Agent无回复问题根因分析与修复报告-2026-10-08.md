# Agent 无回复问题根因分析与修复报告

- 日期：2026-10-08
- 影响范围：`/pro`（react_agent）、`/task`（plan_execute）两条 Agent 链路
- 典型现象：pro 模式输入内容后，仅渲染用户气泡，助手侧无任何输出；或首轮正常、追问时报 `400`

---

## 一、问题现象

| 编号 | 现象 | 复现条件 |
|---|---|---|
| P1 | 只显示用户气泡，助手消息完全消失 | pro 模式输入短文本（如「你好」）→ 澄清卡片回答后 |
| P2 | 助手气泡空白、无任何提示（连报错也没有） | run 正常结束但正文为空 |
| P3 | 首轮能答，追问时报 `Agent 错误: Error: 400 ...` | 多轮对话，第 2 轮起 |

---

## 二、排查过程

### 2.1 日志定位

`apps/backend-ts/agent.1.log` 中每个 pro 会话呈现同一签名：

```
[agent.completions] stream.end  sseCount:3  answerLen:0   messageLen:2
[agent.resume]       stream.end  sseCount:2  streamError:false
```

- `sseCount:3` = `RUN_STARTED` + `USER_QUESTION_REQUEST` + `RUN_PAUSED`
- `sseCount:2` = `RUN_STARTED` + `RUN_FINISHED`，**零个 `TEXT_MESSAGE_CONTENT`**

据此判定为 HITL 澄清链路问题，而非普通对话链路问题。

### 2.2 真实链路复现

```
① POST /agent/completions  「你好」→ RUN_STARTED → USER_QUESTION_REQUEST(kind=choice) → RUN_PAUSED
② GET  /agent/state/:id    → pending:true, next_nodes:["clarify"]   （中断可读，排除 checkpointer 问题）
③ POST /agent/resume       → RUN_STARTED → RUN_FINISHED              （零正文）
```

对照实验确认与 LLM/工具链无关：

| 输入 | 事件序列 | 结论 |
|---|---|---|
| 长文本「帮我分析一下新能源汽车销量下滑的原因」 | `RUN_STARTED → THINKING_* → TOOL_CALL_* ×3 → TEXT_MESSAGE_* → RUN_FINISHED` | 常规路径健康 |

**缺陷被隔离到 HITL resume 路径与多轮对话。**

### 2.3 载荷拦截与单变量对比

拦截 `globalThis.fetch` 抓取图链路真实发出的 LLM 请求体，逐项剥离参数重放：

```
[请求1] messages=2  max_tokens=4096  tools=4  → HTTP 200
    role=system / role=user
[请求2] messages=2  max_tokens=4096  tools=4  → HTTP 400
    role=system / role=assistant(content="")        ← 以 assistant 结尾，缺 user 轮
```

| 组合 | 结果 |
|---|---|
| 无 `tools` + `[system, assistant]` | 200 |
| **有 `tools` + `[system, assistant]`（缺 user 轮）** | **400** |
| 有 `tools` + `[system, assistant, user]` | 200 |
| 改 `stream` / `max_tokens` | 无影响 |

## 三、根因清单

### 缺陷 1｜`resume_stream` 未做事件归一化（主因）

`packages/modu-agent/src/graph/runner.ts`

| 入口 | 归一化 | 产出形状 |
|---|---|---|
| `stream_response` | 经 `_normalizeLangGraphStream` | `{type:'messages', event: msgObj, data: msgObj, metadata}` |
| `resume_stream` | **直接转发原始元组** | `{type:'messages', data: [msgChunk, metadata]}`（数组） |

`AGUIStreamAdapter._process_langgraph_event`（`agui-adapter.ts:1247`）读 `event.event ?? event.data`：
resume 路径下 `event.event` 缺失 → 退化为数组 → `msgType` 解析为空 → 正文取不到 → **整轮零个 `TEXT_MESSAGE_CONTENT`**。

### 缺陷 2｜`llm.max_tokens` 默认过小

`packages/modu-agent/src/graph/adapters/llm-adapter.ts:119`

```ts
const effectiveMaxTokens =
  cfg.maxTokens != null ? cfg.maxTokens : runtimeConfig.get('llm.max_tokens', 512)
```

`deepseek-v4-flash` 为 thinking 模型，**思考与输出共用该预算**，而 `config.yaml` 未配置该项：

| `max_tokens` | 实测 |
|---|---|
| 512 | `completion=512`，`content=""`（推理即耗尽） |
| 4096 | 第1轮 `reasoning_tokens=2035` → content=5900 ✅；第2轮 `reasoning_tokens=4096` → **content=0** ❌ |
| 8192 | 两轮均正常产出（7477 / 7203 字） |

补充事实：LangChain 的 `ChatOpenAI` **不透传 `reasoning_content`**（实测 `additional_kwargs: {}`，usage 中仅有 `reasoning_tokens`）。裸 API 确认该字段本身存在（79 字符），属 LangChain 侧丢失。

### 缺陷 3｜resume 段正文未回填 `ctx`

`apps/backend-ts/src/core/agent-bridge.ts`

`streamAgentCompletion` 有 `ctx.answerContent = adapter.collected_text`，而 `streamAgentResume` 没有。
路由层 `persistAssistantMessage` 依赖 `ctx.answerContent`，导致落库 `content: ''` —— 流式可见但**刷新后回答消失**。

### 缺陷 4｜多轮对话丢失本轮用户输入（P3 的直接原因）

`packages/modu-agent/src/graph/nodes.ts`（`agentNode`）

```ts
// 修复前：仅消息队列为空时才注入用户输入
if (messages.length === 0) {
  messages.push(new HumanMessage({ content: cleanedText }))
}
```

第 2 轮起 `state.messages` 已含上一轮消息 → 本轮提问被静默丢弃 → 请求以 assistant 结尾 →
**携带 `tools` 时 DeepSeek 判定 thinking 模式，返回 400**
`The reasoning_content in the thinking mode must be passed back to the API.`

### 缺陷 5｜空终态消息渲染为 `null`（P2 的直接原因）

`apps/web/src/modes/pro/components/AnalysisMessageList.tsx`

```
text ? <Markdown/> : isStreaming ? <流式占位> : null
```

run 正常结束（`status='complete'`）但正文为空时整条消息渲染为 `null`，用户无从区分「Agent 没回复」与「页面坏了」。

## 四、修复内容

| 文件 | 改动 |
|---|---|
| `packages/modu-agent/src/graph/runner.ts` | `resume_stream` 复用 `_normalizeLangGraphStream`，与 `stream_response` 语义对齐 |
| `packages/modu-agent/src/graph/nodes.ts` | 改为「尾部非 user 且本轮输入未注入则追加」，双守卫避免 ReAct 回环重复注入、避免 clarify 恢复后追加原始 prompt |
| `packages/modu-agent/config.yaml` | 新增 `llm.max_tokens: 8192` |
| `apps/backend-ts/src/core/agent-bridge.ts` | `ResumeAgentOptions` 增加 `ctx`；流结束回填 `ctx.answerContent` + `ctx.finish()` |
| `apps/backend-ts/src/routes/agent.ts` | `/agent/resume` 调用处传入 `ctx` |
| `apps/web/.../AnalysisMessageList.tsx` + `pro.css` | 空终态消息渲染可见提示（仅 `status==='complete'` 触发，不误报 HITL 占位消息） |
| `apps/web/.../useAgentChat.ts` | 显式声明 `agentMode: 'react_agent'`（原依赖后端 schema 默认值，契约见 `modu-agent/AGENTS.md:13`） |
| `apps/web/.../AnalysisInput.tsx` + `useTaskInput.ts` | 附件未就绪时 Enter 发送不再清空输入与草稿（`onSend` 返回 `false` 表示拦截） |

### `nodes.ts` 双守卫设计

```ts
const tailIsUser = messages.length > 0 && messages[messages.length - 1] instanceof HumanMessage
const hasSameUserInput = messages.some(
  (m) => m instanceof HumanMessage && String((m as any).content ?? '').trim() === cleanedText.trim(),
)
if (cleanedText && !tailIsUser && !hasSameUserInput) {
  messages.push(new HumanMessage({ content: cleanedText }))
}
```

- `hasSameUserInput`：同一轮 ReAct 回环（`agent→tools→agent`）会多次进入本节点，需避免重复追加；
- `tailIsUser`：clarify 中断恢复后消息尾部已是 Human（澄清后的需求），不应再追加原始 prompt。

## 六、遗留问题（未在本次修复）

| # | 问题 | 说明 |
|---|---|---|
| 1 | `reasoning_content` 无法回传 | LangChain `ChatOpenAI` 不透传该字段。当前通过「不触发」规避（保证消息序列以 user 轮结尾）。若模型强制要求，需自定义子类从原始 SSE delta 提取 |
| 2 | task 模式 resume 图拓扑 | `agent-bridge.ts` 的 `streamAgentResume` 使用 `get_runner()`（`planExecuteEnabled=false`），且未透传 `extraConfigurable`，与 `runner.ts:1090-1095` 的显式警告冲突 |
| 3 | thinking 偶发空正文 | `max_tokens` 预算被推理吃尽时正文为空。已加前端兜底提示，可考虑按任务类型动态分配预算 |
| 4 | `HITL_ABORTED` 无发射点 | 协议已定义、前端已消费，服务端无发射代码，`onHitlAborted` 分支实际不可达 |
| 5 | `ARTIFACT_CREATED` / `ArtifactPanel` 死代码 | `artifactStore.openArtifact` 全仓无调用点，`activeArtifact` 恒为 null |

## 七、部署注意

`packages/modu-agent/dist/` 已被 `.gitignore` 忽略，后端通过 `dist/index.js` 引用。

**修改 `packages/modu-agent/src` 后必须重新构建并重启后端**：

```bash
cd packages/modu-agent && npm run build
cd apps/backend-ts && npm run dev
```

`tsx watch` 仅监听 `src`，`dist` 变更不会热加载。
