# Agent 架构优化优先级清单

> **生成依据**：2026-08-26 对 `packages/modu-agent`、`apps/desktop`、`apps/backend-ts` 全量代码深度阅读后的架构完整性评估。
> **总体判断**：架构呈"中段强、两端弱"形态——交互编排层与 Agent 核心层 ReAct 主链路成熟；**模型层与数据/知识层薄弱**；大量能力（Plan-Execute、多 Agent、MCP、Skills、进化闭环、可观测性）已实现但默认关闭且无生产验证，系统实际运行在"单轮 ReAct + 4 个安全工具"最小路径上。
> **核心问题不是"缺层"，而是 4 条层间断链 + 已建能力未通电**。

---

## 优先级总览

| 优先级 | 定义 | 数量 | 核心内容 |
|--------|------|------|----------|
| **P0** | 层间断链/致命缺陷，小改动大收益，立即修 | 8 | 参数断链、持久化缺失、反馈死库、最小 RAG |
| **P1** | 兑现已付成本（激活关闭能力）、补关键体验 | 9 | 动态路由、Plan 可视化、LLM 降级链、输出护栏 |
| **P2** | 层能力补齐、工程化治理 | 7 | 业务解耦、任务队列、评测体系 |
| **P3** | 长期演进项 | 4 | 多模态实装、Skill 分发、审计持久化 |

## 实施建议

1. **第一批（P0 全部）**：均为小改动大收益，且 P0-1/0-2/0-3/0-4 相互独立可并行；
2. **依赖关系**：P1-7 依赖 P0-2（checkpoint 持久化）；P2-4 依赖 P0-3（质量信号源）；P1-1 与 P0-8 建议同批（激活 Plan-Execute 时同步补可视化）；
3. **验收原则**：每项完成后在 config.yaml 模板同步默认值，避免"代码默认与模板分叉"问题重演（当前 HITL 已存在该分叉：模板 `enabled: true` vs 代码默认 `false`）。
