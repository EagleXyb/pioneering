## 一、产品定位回顾

**一句话价值主张**：用户和Agent聊天互动，Agent帮用户梳理出他真正该做的事——做洞察，不做信息搜索。

**核心体验标准**：用户听到Agent的洞察后说出「对，这就是我一直想做但没想清楚的事」。

**MVP形态**：微信小程序，以对话为核心交互，Agent主动引导用户完成自我探索。

## 二、信息架构

### 2.1 架构组织方式

采用**线性为主 + 有机补充**的混合结构：
- **线性**：对话流程本身是Agent引导的线性探索
- **有机**：洞察卡内容可自由回顾、延续探索

### 2.2 一级导航（3 Tab）

```
创路Agent 小程序
├── Tab 1: 对话      ← 默认着陆页，核心价值交付
├── Tab 2: 洞察本    ← 洞察沉淀与回顾
└── Tab 3: 我的      ← 基础设置与状态
```

**设计理由**：
- 只设3个Tab，减少认知负担，MVP聚焦核心
- 对话是首页，用户打开即用，零学习成本
- 洞察本是「资产层」的MVP体现——对话产生的洞察需要被沉淀和回顾
- 我的仅保留必要功能，MVP不做社交

### 2.3 页面清单与层级

#### Tab 1: 对话

| 页面 | 用途 | 入口 | 出口 |
|------|------|------|------|
| 对话首页 | 展示当前/最近对话，引导开始 | Tab切换、小程序打开 | 进入对话、跳转洞察本 |
| 对话流 | 核心聊天界面，Agent与用户交互 | 对话首页点击 | 产生洞察卡、跳转洞察详情 |

#### Tab 2: 洞察本

| 页面 | 用途 | 入口 | 出口 |
|------|------|------|------|
| 洞察列表 | 展示所有已生成的洞察卡 | Tab切换、对话中查看洞察 | 进入洞察详情、继续探索 |
| 洞察详情 | 单个洞察的完整内容与后续行动 | 洞察列表点击 | 继续探索（回到对话） |

#### Tab 3: 我的

| 页面 | 用途 | 入口 | 出口 |
|------|------|------|------|
| 个人中心 | 用户状态、设置 | Tab切换 | 各设置子页 |

## 三、核心对话流程设计

### 3.1 对话五阶段模型

这是创路Agent的核心产品逻辑，Agent的背后运行这五个阶段，每个阶段有不同的引导策略：

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│  破冰    │───→│  探索    │───→│  澄清    │───→│  洞察    │───→│  锚定    │
│ Icebreak │    │ Explore  │    │ Clarify  │    │ Insight  │    │ Anchor   │
└─────────┘    └─────────┘    └─────────┘    └─────────┘    └─────────┘
  Agent了解       Agent深挖       Agent镜像       Agent结晶       Agent落地
  用户现状        动机与恐惧      反映模式        核心洞察        下一步行动
```

### 3.2 各阶段详细设计

#### 阶段一：破冰（Icebreak）

**目标**：让用户放下戒备，开始讲述自己的现状
**Agent策略**：共情式开场，不追问，先听
**典型Agent话术**：

| 轮次 | Agent | 交互方式 |
|------|-------|----------|
| 1 | "嗨，我是你的创路伙伴。听说你在想创业的事？跟我聊聊，你现在什么情况？" | 开放文本 |
| 2 | "8年程序员，年薪50万……说实话，这已经是很多人羡慕的位置了。但你觉得不够？" | 反射+追问 |
| 3 | [用户回答后] "升职无望的感觉我理解。那你有想过具体做什么方向吗？还是只是'想创业'这个念头？" | 快速选择 + 自由输入 |

**交互要点**：
- Agent先用1-2句话回应用户的话，让用户感觉「被听到」
- 每次只问一个问题
- 选项设计：给出2-3个常见方向 + "我想说别的"自由输入

#### 阶段二：探索（Explore）

**目标**：深挖用户动机、恐惧、能力、资源
**Agent策略**：苏格拉底式追问，从表面到深层
**探索维度**：

| 维度 | Agent挖掘方向 | 典型问题 |
|------|--------------|----------|
| 动机 | 为什么要创业？是想要什么？ | "你说想创业，最想要的是自由？收入？还是证明自己？" |
| 恐惧 | 最怕什么？ | "你提到怕失败后找不到好工作——这个'怕'背后，是经济压力还是自我认同？" |
| 能力 | 你擅长什么？做过什么？ | "你说喜欢研究新科技，最近在研究什么？有试过把兴趣变成项目吗？" |
| 资源 | 身边有什么可用资源？ | "老婆支持你创业——这个支持到什么程度？精神上还是经济上也行？" |
| 限制 | 什么是不能妥协的？ | "如果创业，你最低的生活保障线在哪？" |

**交互要点**：
- 用用户自己的话回应用户（"你刚才说的'越看越迷茫'——迷茫的是什么？"）
- 敏感问题（恐惧、限制）用温和措辞，不逼问
- 适时总结："让我理一下你说的……"

#### 阶段三：澄清（Clarify）

**目标**：把模糊的感觉变成清晰的表述
**Agent策略**：镜像反映——把用户说过的碎片拼成模式，让用户确认
**典型Agent话术**：

| 轮次 | Agent | 交互方式 |
|------|-------|----------|
| 1 | "我听到一个有意思的矛盾：你说想创业，但你最享受的是研究技术本身，而不是找人、谈合作、做商业判断。对吗？" | 确认/修正选择 |
| 2 | "而且你害怕的不是创业本身，而是害怕失去现在安稳的生活后，发现自己其实没有商业天赋。" | 确认/修正选择 |
| 3 | "所以你真正想要的，可能不是'创业'这个标签，而是——在技术领域有更深的影响力，不依赖升职也能成长。我理解得对吗？" | 确认/修正选择 |

**交互要点**：
- 这是洞察的前奏——Agent开始"拼图"，让用户看到全貌
- 用户可以修正Agent的理解（"不完全是，应该是……"）
- 澄清完成后，进入洞察阶段

#### 阶段四：洞察（Insight）⭐ 核心时刻

**目标**：产出「对，就是这！」的洞察
**Agent策略**：结晶化表述，用洞察卡承载
**洞察卡触发条件**：Agent识别到用户对澄清内容连续2次确认

**洞察卡内容结构**：
```
┌──────────────────────────────────────┐
│  💡 你的方向洞察                      │
│                                      │
│  你不是一个"创业者"，                │
│  你是一个"深度技术专家"。            │
│                                      │
│  你真正渴望的不是公司，              │
│  而是不受组织天花板限制的             │
│  技术影响力。                        │
│                                      │
│  ── 基于你的对话发现 ──              │
│  · 8年深耕技术，享受钻研本身         │
│  · 对商业运作没有内驱力              │
│  · 核心恐惧是"失去安全网"            │
│  · 真正想要的是"自主成长空间"        │
│                                      │
│  [继续探索行动方案]  [保存到洞察本]  │
└──────────────────────────────────────┘
```

**交互要点**：
- 洞察卡在对话流中以特殊样式呈现（视觉区分）
- 用户可以"不对，我再想想"拒绝洞察，回到探索
- 用户确认后，洞察卡保存到洞察本

#### 阶段五：锚定（Anchor）

**目标**：把洞察落地为可执行的方向
**Agent策略**：从洞察推导行动路径
**典型Agent话术**：

| 轮次 | Agent | 交互方式 |
|------|-------|----------|
| 1 | "既然你的方向是'深度技术专家'，而不是'创业者'，那我们可以想想：怎么在不离开当前工作的情况下，先扩大你的技术影响力？" | 开放讨论 |
| 2 | "有几个方向你可以考虑——" | 行动建议卡 |
| 3 | "你想先深入聊哪个？或者你有别的想法？" | 选择+自由输入 |

**行动建议卡示例**：
```
┌──────────────────────────────────────┐
│  🎯 行动建议                          │
│                                      │
│  基于你的洞察，3个起步方向：          │
│                                      │
│  1. 技术博主/KOL                     │
│     把你的技术研究输出为内容           │
│     风险：⭐ | 潜力：⭐⭐⭐            │
│                                      │
│  2. 开源项目维护者                    │
│     在GitHub建立技术影响力             │
│     风险：⭐ | 潜力：⭐⭐              │
│                                      │
│  3. 大厂技术专家路线                  │
│     跳槽到更有技术深度的公司           │
│     风险：⭐⭐ | 潜力：⭐⭐             │
│                                      │
│  [选择深入]  [我想看看别的方向]       │
└──────────────────────────────────────┘
```

### 3.3 对话状态机

```
[新用户] ──→ 破冰
[老用户] ──→ 继续/新话题

破冰 ──(了解基本现状)──→ 探索
探索 ──(收集足够信号)──→ 澄清
澄清 ──(用户确认模式)──→ 洞察
澄清 ──(用户否定模式)──→ 探索（重新深挖）
洞察 ──(用户接受)──→ 锚定
洞察 ──(用户拒绝)──→ 探索（换角度）
锚定 ──(选择行动)──→ [结束本轮/新话题]
锚定 ──(想继续聊)──→ 探索（深化）
```

## 四、交互体验设计

### 4.1 核心交互原则

| 原则 | 说明 | 对话中的体现 |
|------|------|-------------|
| **Agent主动引导** | 不是用户问Agent答，而是Agent带领用户探索 | Agent主动提问、主动总结、主动推进 |
| **一次一问** | 每次只问一个问题，降低用户思考负担 | 绝不一次抛出多个问题 |
| **先听后说** | Agent先回应理解，再推进 | "你说……我理解得对吗？" |
| **用用户的话** | 反射用户自己的表述，不是Agent的术语 | 捕捉关键词，原话映射 |
| **洞察有仪式感** | 洞察是产品最珍贵的时刻 | 洞察卡视觉突出、可保存、可回顾 |
| **允许犹豫** | 用户可以说"我不知道" | Agent降低难度，换角度问 |

### 4.2 输入交互设计

**混合输入模式**：快速选择 + 自由文本，降低表达门槛

```
┌──────────────────────────────────────────┐
│  Agent: "你想创业，最想要的是什么？"      │
│                                          │
│  [💰 收入自由]  [🆓 时间自由]             │
│  [🏆 成就感]    [✍️ 我想说说别的]         │
│                                          │
│  ┌─────────────────────────────┐ [发送]  │
│  │ 也可以直接打字...            │         │
│  └─────────────────────────────┘         │
└──────────────────────────────────────────┘
```

**设计理由**：
- 很多用户"想不清楚"恰恰因为不知道怎么表达——选项帮他们定位
- "我想说说别的"兜底，不限制自由表达
- 文本输入框始终可见，鼓励深入表达

### 4.3 对话节奏设计

| 节奏 | 阶段 | Agent回复策略 | 用户感知 |
|------|------|--------------|----------|
| **慢热** | 破冰 | 回应长一点，追问短一点 | "这个AI在认真听我说话" |
| **深挖** | 探索 | 短问+等待，不急着总结 | "它问到了我没想过的地方" |
| **聚焦** | 澄清 | 开始整合，镜像反映 | "它在帮我把散乱的想法串起来" |
| **点亮** | 洞察 | 洞察卡呈现，语感升华 | "对！就是这种感觉！" |
| **落地** | 锚定 | 具体化、行动化 | "我知道下一步该做什么了" |

### 4.4 洞察卡交互

**生成时机**：Agent判断用户连续确认澄清内容 ≥ 2次

**呈现方式**：
1. 对话流中插入洞察卡（特殊视觉样式）
2. 用户可以：
   - ✅ 「这就是我！」→ 保存到洞察本
   - 🔄 「部分对，我再说说」→ 继续对话修正
   - ❌ 「不对，再聊聊」→ 回到探索阶段

**保存后**：
- 洞察本中出现新卡片
- 用户可随时回顾
- 可从洞察卡「继续探索」，开启新一轮对话

### 4.5 首次使用引导

```
[开屏页]
"每个人心里都有一个'想做的事'，
 只是还没想清楚。
 
 我来帮你找到它。"

[开始探索] 按钮 → 进入对话
```

**设计理由**：
- 一句话共鸣，不解释产品功能
- 直接行动按钮，无教程
- 价值在前，功能在后

- 社交功能（社区、评论、关注）

## 六、数据指标体系

### 6.1 北极星指标

**洞察达成率** = 产生至少1张洞察卡的用户数 / 启动对话的用户数

### 6.2 关键指标

| 指标 | 定义 | 目标(MVP) | 统计周期 |
|------|------|-----------|----------|
| 洞察达成率 | 产生≥1张洞察卡的用户占比 | ≥40% | 周 |
| 对话深度 | 平均每用户每轮对话消息数 | ≥15条 | 周 |
| 洞察认同率 | 用户点击「这就是我！」的洞察卡占比 | ≥60% | 周 |
| 次日留存 | D1留存率 | ≥30% | 日 |
| 续聊率 | 老用户继续对话的占比 | ≥25% | 周 |

## 七、关键设计决策

| 决策点 | 选项A | 选项B | 选择 | 理由 |
|--------|-------|-------|------|------|
| 首页形态 | 直接进入对话 | 展示功能入口 | A | 降低启动成本，打开就用 |
| 输入方式 | 纯文本 | 混合输入(选择+文本) | B | 目标用户"想不清楚"，选项降低表达门槛 |
| 洞察呈现 | 纯文字总结 | 洞察卡(结构化卡片) | B | 洞察是核心资产，需要仪式感和可回顾性 |
| 对话可见性 | 用户看不到阶段 | 展示当前探索阶段 | 渐进式 | 前期不展示（避免焦虑），澄清阶段后展示（增强进展感） |
| Agent人格 | 专业顾问型 | 朋友型 | 朋友型 | 目标用户需要的是"有人懂我"而不是"有人教我" |

## 八、风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| Agent对话质量不稳定，洞察不准 | 高 | 高 | 五阶段结构约束Agent行为，降低开放性带来的不确定性 |
