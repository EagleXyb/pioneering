# 小程序体验优化优先级方案

> 基于《技术栈评估与体验差距分析》的详细差距，制定分阶段、可落地的优化方案。  
> 优先级排序原则：**用户可感知影响度 > 实现成本 > 技术债务累积风险**

---

## 总览：四阶段优化路线

| 阶段 | 代号 | 目标 | 周期 | 优先级 |
|------|------|------|------|:--:|
| P0 | 体验红线 | 消除用户可感知的体验硬伤 | 第 1-2 周 | 🔴 高 |
| P1 | 基础工程化 | 建立质量保障基线 | 第 3-4 周 | 🟡 中 |
| P2 | 产品化打磨 | 接近大厂商业化水准 | 第 5-6 周 | 🟡 中 |
| P3 | 长期建设 | 建立数据驱动的迭代能力 | 持续 | 🟢 低 |

---

## P0：体验红线（第 1-2 周）

> 目标：修复用户可直接感知的性能问题和交互动效 bug，消除「山寨感」。

```tsx
  height={/* 屏幕高度 */}
  itemData={caseList}
  itemCount={caseList.length}
  itemSize={/* 每项高度 */}

  {ItemComponent}
</VirtualList>
```

```tsx
// SidebarDrawer 历史会话列表 - 同 VirtualList 方案

```

**涉及文件**：

### P0-2：修复 SidebarDrawer 入场动画 bug

**问题**：`if (!visible) return null` 导致 CSS transition 入场动画无法触发。

**方案**：
```tsx
// 参照 ModeSheet 实现模式
const SidebarDrawer: React.FC<Props> = ({ visible, onClose }) => {
  const [animating, setAnimating] = useState(false)
  const [shouldRender, setShouldRender] = useState(false)

  useEffect(() => {
    if (visible) {
      setShouldRender(true)
      requestAnimationFrame(() => {
        requestAnimationFrame(() => setAnimating(true))
      })
    } else {
      setAnimating(false)
      const timer = setTimeout(() => setShouldRender(false), 300) // 与 CSS transition 时长一致
      return () => clearTimeout(timer)
    }
  }, [visible])

  if (!shouldRender) return null

  return (
    <View className={`sidebar-overlay ${animating ? 'sidebar-overlay--visible' : ''}`}>
      <View className={`sidebar-panel ${animating ? 'sidebar-panel--open' : ''}`}>
        {/* ... */}
      </View>
    </View>
  )
}
```

**涉及文件**：
- `src/pages/iac/components/SidebarDrawer.tsx`
- `src/pages/iac/components/SidebarDrawer.scss`

**验收标准**：
- 打开时侧边栏有平滑的滑入动画
- 关闭时侧边栏有平滑的滑出动画
- 无闪烁或跳变

### P0-3：骨架屏 — 全页面首屏加载

**问题**：所有页面首屏加载时呈现白屏或空状态，体验粗糙。

**方案**：
```tsx
// components/Skeleton/index.tsx — 通用骨架屏组件
interface SkeletonProps {
  type: 'card' | 'list' | 'chat' | 'profile'
  count?: number
}

const Skeleton: React.FC<SkeletonProps> = ({ type, count = 1 }) => {
  switch (type) {
    case 'card':
      return Array.from({ length: count }).map((_, i) => (
        <View key={i} className="skeleton-card">
          <View className="skeleton-line skeleton-line--title" />
          <View className="skeleton-line skeleton-line--text" />
          <View className="skeleton-line skeleton-line--text skeleton-line--short" />
        </View>
      ))
    case 'list':
      // 列表骨架屏
      break
    case 'chat':
      // 聊天骨架屏
      break
  }
}
```

**使用方式**：

| 页面 | 骨架屏类型 | 涉及文件 |
|------|:--:|------|
| case-library | card x3 | `src/pages/case-library/index.tsx` |
| profile | profile | `src/pages/profile/index.tsx` |
| training | card x2 | `src/pages/training/index.tsx` |
| 子培训页 | list | `src/pages/training/incubation/index.tsx` |

**验收标准**：
- 各页面数据加载前展示骨架屏动画
- 骨架屏形态与真实内容布局一致
- 数据到达后平滑过渡到真实内容

### P0-4：异常态 — 空态 / 错误态 / 网络断连

**问题**：多个场景缺失空态和错误反馈，白屏或无响应。

**方案**：创建统一的异常态组件。

```tsx
// components/StateWrapper/index.tsx

interface StateWrapperProps {
  loading: boolean
  error: Error | null
  empty: boolean
  emptyText?: string
  errorText?: string
  onRetry?: () => void
  loadingSlot?: React.ReactNode  // 骨架屏
  children: React.ReactNode
}

const StateWrapper: React.FC<StateWrapperProps> = ({
  loading, error, empty,
  emptyText = '暂无数据',
  errorText = '加载失败，请重试',
  onRetry,
  loadingSlot,
  children,
}) => {
  if (loading) return <>{loadingSlot ?? <LoadingSpinner />}</>
  if (error) return <ErrorState message={errorText} onRetry={onRetry} />
  if (empty) return <EmptyState message={emptyText} />
  return <>{children}</>
}
```

**需要添加异常态的页面**：

| 页面 | 加载态 | 空态 | 错误态 | 重试 |
|------|:--:|:--:|:--:|:--:|
| case-library | ✅ P0-3 骨架屏 | ✅ 搜索无结果 | ✅ | ✅ |
| profile | ✅ P0-3 骨架屏 | ❌ 暂不需要 | ✅ | ✅ |
| training 列表 | ✅ P0-3 骨架屏 | ✅ 无数据 | ✅ | ✅ |
| incubation | ❌ 已有 | ✅ 无话题 | ✅ | ⚠️ 待加 |

**全局网络断连**：
```tsx
// app.tsx 中添加
useDidShow(() => {
  Taro.onNetworkStatusChange((res) => {
    if (!res.isConnected) {
      Taro.showToast({ title: '网络已断开', icon: 'none', duration: 3000 })
    }
  })
})
```

**涉及文件**：
- `src/components/StateWrapper/index.tsx`（新建）
- `src/app.tsx`（添加网络监听）
- `src/pages/case-library/index.tsx`
- `src/pages/profile/index.tsx`

**验收标准**：
- 各异常态有明确友好的视觉反馈
- 错误态提供「点击重试」按钮
- 网络断连时有全局 toast 提示

## P1：基础工程化（第 3-4 周）

> 目标：建立代码质量底线，消除技术债务，为后续迭代提供稳定基础。

### P1-1：统一样式 Token，禁止硬编码

**问题**：多处硬编码颜色、混用 px/rpx、KnowledgeCard 全硬编码。

**方案**：

1. **完善 token 文件**：
```scss
// src/assets/variables.scss — 在现有基础上补充
$spacing-xs: 8rpx;
$spacing-sm: 16rpx;
$spacing-md: 24rpx;
$spacing-lg: 32rpx;
$spacing-xl: 48rpx;

$radius-sm: 8rpx;
$radius-md: 16rpx;
$radius-lg: 24rpx;
$radius-round: 50%;
```

2. **重构 KnowledgeCard 样式**：
```scss
// 将所有硬编码颜色替换为 token 变量
.knowledge-card {
  background: $color-bg-card;
  border-radius: $radius-md;
  padding: $spacing-md;
  
  &__title {
    color: $color-text-primary;  // 替换 #1A1A1A
    font-size: $font-size-lg;
  }
  
  &__desc {
    color: $color-text-secondary;  // 替换 #666
    font-size: $font-size-sm;
  }
  
  &__badge {
    color: $color-text-tertiary;  // 替换 #999
  }
}
```

3. **统一 px → rpx**：
```
# 全局搜索 px 替换（注意排除 transform 中的 px）
margin: 24px  →  margin: 24rpx
padding: 12px →  padding: 12rpx
```

**涉及文件**：
- `src/assets/variables.scss`
- `src/components/KnowledgeCard/index.scss`
- `src/components/UserAvatar/index.scss`
- `src/pages/case-library/index.scss`
- `src/pages/login/index.scss`
- `src/pages/profile/index.scss`

**验收标准**：
- 全项目无硬编码颜色值（十六进制除外 token 定义处）
- 尺寸单位统一为 rpx（transform/opacity 等特殊场景除外）

### P1-3：TypeScript Strict 模式

**问题**：`strict: false`、`noImplicitAny: false`，多处 `any` 类型。

**方案**：

1. 修改 `tsconfig.json`：
```json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true
  }
}
```

2. 逐个消除 `any`：

| 位置 | 当前 | 修改为 |
|------|------|------|
| `ChatInput.tsx` | `useRef<any>` | `useRef<HTMLInputElement>` |
| `iac/index.tsx` | `(e: any)` | `(e: ITouchEvent)` |
| `services/api.ts` | `data?: any` | `data?: T`（泛型） |
| `useStreamingResponse.ts` | `React.Dispatch<...>` | 使用 Taro 兼容的类型别名 |

**涉及文件**：
- `tsconfig.json`
- `src/pages/iac/components/ChatInput.tsx`
- `src/pages/iac/index.tsx`
- `src/services/api.ts`
- `src/pages/iac/hooks/useStreamingResponse.ts`

**验收标准**：
- `tsc --noEmit` 无类型错误
- 项目中 `any` 出现次数归零

## 投入产出汇总

| 阶段 | 任务数 | 预计工作量 | 用户感知提升 | 技术价值 |
|------|:--:|:--:|:--:|:--:|
| P0 体验红线 | 4 | 5 人天 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| P1 基础工程化 | 3 | 4 人天 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| P2 产品化打磨 | 5 | 3 人天 | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| P3 长期建设 | 4 | 持续 | ⭐⭐ | ⭐⭐⭐⭐⭐ |

**执行建议**：

1. **P0 必须本周启动**，这些是用户直接可感知的体验硬伤。
2. **P1 紧随其后**，工程化在代码量不大时推进成本最低。
3. **P2 可视业务优先级排期**，属于锦上添花。
4. **P3 建议以 20% 时间持续投入**，避免测试/监控债务累积。
