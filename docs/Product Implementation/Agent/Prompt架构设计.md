# 自研 Prompt 工程

# 自研Prompt工程业务落地全流程（可执行、体系化）
自研Prompt工程，绝非零散写提示词，而是**搭建一套适配业务目标、可复用、可管控、可迭代、可观测的大模型业务落地体系**，核心是让大模型能力稳定、合规、规模化地嵌入业务流程，最终达成业务指标。

完整的业务落地分为6个核心阶段，每个阶段有明确的动作、交付物和验收标准，全程以业务目标为核心锚点。

---

## 第一阶段：业务锚定与需求闭环（前置核心，决定成败）
本阶段核心是**杜绝为了Prompt而Prompt**，先明确业务边界、目标和验收标准，避免后续研发与业务脱节。
### 核心步骤
1.  **明确业务核心目标与可量化指标**
    - 锁定具体业务场景：比如智能客服工单分类、合同合规审核、营销文案批量生成、生产质检报告自动生成、财务单据自动校验等，**禁止泛化的“提升效率”类模糊目标**。
    - 定义可量化的核心指标（OKR）：比如工单分类准确率≥95%、人工审核率降低60%、文案转化率提升15%、单条请求Token成本降低30%、响应时长≤1s；同时明确红线指标，比如合规违规率=0、隐私泄露风险=0。
    - 明确业务受众与使用链路：是内部员工使用，还是C端用户直接接触；是嵌入现有业务系统，还是独立工具；对接的上游数据来源、下游业务动作是什么。

2.  **拆解业务规则与能力边界定义**
    - 梳理全量业务规则：把业务的标准化流程、行业术语、审批规则、禁忌要求、合规条款全部文档化，比如售后退款的触发条件、合同审核的禁止条款、金融行业的监管要求。
    - 划定大模型+Prompt的能力边界：
      - ✅ 适合Prompt工程：规则明确、流程标准化、输入输出格式固定、需要快速迭代、数据量中等的场景；
      - ⚠️ 需补充能力：强专属知识场景需搭配RAG检索，复杂逻辑分步执行需搭配Function Call（工具调用），极致低幻觉/强行业属性需搭配模型微调；
      - ❌ 禁止用Prompt覆盖：高风险决策、无明确规则的主观判断、涉及核心数据安全的场景。

3.  **合规与隐私风险前置评估**
    - 明确数据合规要求：比如用户隐私数据脱敏规则、行业监管合规条款、数据出境限制，确定哪些数据可以传入大模型，哪些必须在业务系统内处理。
    - 设定强制合规约束：比如医疗场景禁止诊疗建议、金融场景禁止投资推荐、政务场景禁止违规承诺，所有约束必须写入Prompt体系的强制层。

## 第二阶段：技术底座与Prompt架构设计（工程化的根基）
本阶段核心是搭建可扩展、可维护的技术框架，避免零散Prompt导致的“维护灾难”，实现规模化复用。
### 核心步骤
1.  **大模型与配套技术栈选型**
    - 大模型选型：根据业务的隐私要求、成本、性能、并发、场景适配性选型，比如：
      - 高隐私要求：本地部署开源大模型（Qwen、Llama、DeepSeek等）；
      - 通用高性能场景：闭源商用大模型（豆包、GPT、Claude等）；
      - 核心选型标准：场景适配准确率、响应速度、Token成本、并发支持、安全合规性。
    - 配套技术栈选型（自研Prompt工程的必备组件）：
      | 组件类型 | 核心作用 | 可选方案 |
      |---|---|---|
      | Prompt模板管理 | 版本控制、模板复用、权限管控 | Git+内部模板平台、开源Prompt管理工具 |
      | 上下文管理 | 动态填充业务数据、会话状态维护 | 业务数据库对接、变量渲染引擎 |
      | 检索增强RAG | 解决幻觉、注入专属业务知识 | 向量数据库+检索引擎 |
      | 工具调用框架 | 对接业务系统API、执行复杂逻辑 | 大模型原生Function Call、开源Agent框架 |
      | 合规校验引擎 | 输入/输出的合规过滤、敏感数据脱敏 | 规则引擎+轻量合规模型 |
      | 监控告警系统 | 全链路指标监控、异常预警 | 业务监控平台、日志系统 |

2.  **分层模块化的Prompt架构设计（自研核心）**
    摒弃单条长Prompt的写法，设计**分层、模块化、可插拔**的Prompt架构，不同业务场景可快速组合复用，核心分为4层：
    - **基础层（全局强制层，全场景复用）**：固定不变的核心指令，包括角色定位、全局合规约束、输出底线、错误处理规则、基础格式要求，所有业务任务共用，避免重复编写。
    - **业务层（行业/业务专属层，同业务线复用）**：业务专属规则、行业术语定义、标准化流程、专属知识库指引、业务禁忌，同一条业务线的不同任务共用，比如电商售后全场景共用一套售后规则模块。
    - **任务层（单任务执行层，单场景专用）**：具体任务的执行指令、输出格式、思维链要求、少样本示例、工具调用规则，比如工单分类、退款审核、话术生成分别对应独立的任务模块。
    - **动态层（实时数据层，每次请求动态填充）**：通过变量占位符实现，比如{{用户订单信息}}、{{实时库存数据}}、{{用户对话上下文}}、{{RAG检索到的专属知识}}，每次请求由业务系统自动渲染填充，保证Prompt的实时性和准确性。

3.  **全链路业务流程设计**
    明确Prompt工程在业务系统中的完整执行链路，标准链路如下：
    ```
    业务系统接收用户输入/触发任务 → 数据预处理（脱敏、格式校验、异常过滤）
    → 从业务库/向量库获取上下文/专属知识 → 动态渲染Prompt模板（填充变量）
    → 合规前置校验（过滤违规输入） → 调用大模型执行Prompt指令
    → 输出结果后置校验（合规、格式、业务规则校验）
    → 解析结果并触发下游业务动作（自动回复、工单流转、数据入库等）
    → 全链路日志留存、指标上报 → 异常场景兜底（转人工、触发兜底话术）
    ```

## 第三阶段：Prompt核心研发与工程化封装
本阶段核心是基于架构设计，完成Prompt模板的研发、工程化封装，实现可调用、可管理、可复用。
### 核心步骤
1.  **基于业务场景的Prompt模板研发**
    - 选用适配业务的Prompt框架：标准化场景用CO-STAR/CRISPE框架，复杂逻辑推理用ReAct/思维链(CoT)框架，分类/审核场景用少样本(Few-Shot)框架，杜绝无章法的堆砌。
    - 核心编写原则：
      1.  指令精准、无歧义：用祈使句，明确“必须做什么、禁止做什么、输出什么格式”，避免模糊表述；
      2.  少样本优先：业务场景必须用**真实的历史业务案例**做少样本，覆盖正常案例、边界案例、异常案例，禁止用虚构案例；
      3.  强制格式约束：明确输出格式（比如JSON、Markdown、固定字段），方便业务系统解析，避免自然语言输出导致的解析失败；
      4.  思维链分步执行：复杂业务逻辑，强制大模型“先分步思考，再输出结果”，大幅降低幻觉，提升准确率；
      5.  容错与兜底指令：明确异常输入的处理方式，比如“若输入信息不足，直接返回【参数缺失】，禁止编造信息”。
    - 模块化解耦：把合规校验、格式输出、错误处理、规则说明做成独立的子模块，不同任务模板可直接引用，修改时一处更新、全量生效。

2.  **工程化封装与模板管理**
    - 模板化与变量化：把固定内容做成模板，动态内容用变量占位符，对接业务系统的渲染引擎，实现“一套模板，适配海量个性化请求”，比如退款审核模板，只需要动态填充订单信息、用户诉求、售后规则，无需重复编写Prompt。
    - 版本管理：用Git等工具对Prompt模板进行版本管控，每次修改必须记录变更原因、变更内容、测试结果，支持版本回滚，避免多人协作导致的模板混乱、问题无法追溯。
    - 权限管控：建立模板的编辑、审核、发布权限体系，核心模板变更必须经过审核才能上线，避免误操作导致的业务风险。
    - 接口标准化封装：把Prompt模板、大模型调用、前后置校验、结果解析封装成标准化的API接口，提供给业务系统调用，屏蔽底层细节，业务方只需要传入核心参数，即可拿到标准化的结果。

3.  **配套能力集成**
    - RAG集成：把业务专属知识库、实时数据通过检索引擎，精准注入Prompt的动态层，解决大模型幻觉、知识过时的问题；
    - 工具调用集成：在Prompt中定义Function Call规则，让大模型按需调用业务系统的API，比如查询实时订单、库存、用户信息，执行数据计算等，实现复杂业务流程的自动化；
    - 前后置合规校验集成：在Prompt调用前后，接入合规引擎，输入侧做敏感数据脱敏、违规内容过滤，输出侧做合规校验、业务规则校验，拦截不符合要求的结果。

## 第四阶段：全维度测试与效果验收
本阶段核心是通过真实业务数据，验证Prompt工程是否达到业务验收标准，杜绝“实验室效果好，上线就崩”的问题。
### 核心步骤
1.  **搭建业务专属测试数据集**
    - 数据集必须来自**真实的业务历史数据**，禁止用虚构数据，覆盖：
      - 正常案例：80%，覆盖主流业务场景；
      - 边界案例：10%，覆盖规则边缘、特殊场景、参数不全的情况；
      - 异常/对抗案例：10%，覆盖违规输入、诱导性内容、乱码、无关内容、恶意攻击等场景；
    - 数据集标注：对所有测试用例进行人工标注，明确标准输出结果，作为效果评估的基准；
    - 数据集拆分：分为训练集（用于模板优化）、测试集（用于效果验证）、验证集（用于最终验收），避免过拟合。

2.  **多维度专项测试**
    - **功能测试**：验证输出是否符合格式要求、业务规则、指令要求，是否能正确触发工具调用、兜底逻辑；
    - **效果准确率测试**：对比模型输出与人工标注的标准结果，计算核心指标：精准率、召回率、F1值、合格率，验证是否达到业务预设指标；
    - **鲁棒性测试**：验证异常输入、对抗输入、参数波动时，模型是否能稳定输出，不会出现违规内容、编造信息、系统崩溃；
    - **合规与安全测试**：全量验证是否存在隐私泄露、违规输出、监管红线触碰，确保合规违规率为0；
    - **性能测试**：验证单请求响应时长、并发支持能力、Token消耗成本，是否符合业务系统的性能要求；
    - **兼容性测试**：验证与业务系统的对接是否顺畅，上下游链路是否能正常流转，异常场景是否能正确触发兜底机制。

3.  **A/B测试与迭代优化**
    - 对不同版本的Prompt模板，进行受控的A/B测试，控制变量，对比核心业务指标，筛选最优版本；
    - 对测试中不通过的案例，进行根因分析，优化Prompt模板：补充少样本、优化指令、完善业务规则、补充RAG知识、调整思维链逻辑，直到所有核心指标达到验收标准。

4.  **最终业务验收**
    - 用预留的验证集进行盲测，邀请业务方、合规方、技术方共同验收，确认核心指标、合规要求、性能要求全部达标，签署验收确认，方可进入上线阶段。

## 第五阶段：业务系统集成与灰度上线
本阶段核心是把Prompt工程平稳嵌入业务流程，控制上线风险，实现平滑过渡。
### 核心步骤
1.  **业务系统全链路集成**
    - 与上游业务系统对接：实现用户输入、业务数据的自动获取、脱敏、预处理，完成Prompt模板的动态渲染；
    - 与下游业务系统对接：实现输出结果的自动解析，触发对应的业务动作，比如自动回复用户、工单自动流转、数据自动入库、审批流程自动触发；
    - 全链路联调：完成端到端的业务流程联调，验证正常流程、异常流程、兜底流程的全链路通畅，无断点。

2.  **灰度上线与流量控制**
    - 制定灰度上线计划：先从最小流量开始（比如5%），覆盖低风险场景，逐步扩大流量，禁止全量直接上线；
    - 建立人工兜底机制：灰度期间，所有模型处理的结果，都保留人工审核/人工接管的入口，异常场景自动转人工，避免影响业务正常运行；
    - 实时数据观测：灰度期间，实时监控核心指标，包括业务指标、效果指标、性能指标、合规指标，一旦出现异常，立即缩容或回滚。

3.  **全量上线**
    - 灰度期间核心指标持续达标，无重大异常，逐步扩大流量至100%全量上线；
    - 完成业务切换：比如人工客服的场景，逐步降低人工处理占比，完成自动化流程的切换；
    - 上线培训：对业务使用人员、运维人员进行培训，明确使用规范、异常处理流程、问题反馈渠道。

## 第六阶段：全量监控与持续迭代优化
Prompt工程不是一劳永逸的，上线后需要持续运营优化，适配业务变化、模型更新、用户需求变化。
### 核心步骤
1.  **搭建全维度监控体系**
    - **业务指标监控**：工单解决率、人工干预率、转化率、处理时长、成本降低率等核心业务指标；
    - **效果指标监控**：输出准确率、合规通过率、幻觉发生率、格式错误率等效果指标；
    - **性能指标监控**：大模型调用成功率、响应时长、Token消耗量、并发量、接口报错率等技术指标；
    - **异常告警机制**：设定指标阈值，比如准确率下降超过5%、合规违规次数>0、接口报错率超过1%，立即触发告警，通知负责人处理。

2.  **数据回流与案例沉淀**
    - 建立全链路日志体系：留存每一次请求的输入、Prompt模板、模型输出、业务结果、人工反馈、异常信息，可追溯、可分析；
    - 异常案例回流：把线上的错误案例、人工修正案例、边界案例、用户反馈的问题，定期回流到少样本案例库和测试数据集；
    - 业务规则更新同步：业务规则、合规条款、知识库更新时，同步更新Prompt模板和RAG知识库，确保与业务现状一致。

3.  **持续迭代优化**
    - 定期迭代周期：比如每周做小版本优化，每月做大版本迭代，基于回流的案例和数据，优化Prompt模板、补充少样本、完善业务规则、优化RAG检索效果；
    - 大版本变更管控：Prompt模板的重大变更、大模型版本升级，必须重新经过测试和灰度上线，避免影响线上业务；
    - 成本优化：持续优化Prompt模板，精简冗余内容，降低Token消耗，平衡效果与成本。

4.  **规模化复用与能力沉淀**
    - 把成熟的Prompt模块、模板、流程，沉淀到企业内部的Prompt资产库，新的业务场景可快速复用，降低研发成本；
    - 基于业务实践，沉淀企业内部的Prompt工程规范、最佳实践、培训体系，实现能力的规模化复制。

## 核心避坑指南（高频踩坑点）
1.  **脱离业务谈Prompt技巧**：所有Prompt优化都必须围绕业务目标，而非炫技，很多看似高级的技巧，反而会增加业务不稳定性。
2.  **忽略工程化，只关注单条Prompt效果**：没有版本管理、监控、合规校验的Prompt，上线后必然出现维护灾难和业务风险。
3.  **用虚构数据测试，上线后失效**：只有真实业务数据才能验证Prompt的实际效果，实验室的完美效果，在真实场景中大概率会崩盘。
4.  **过度依赖Prompt，忽略配套能力**：强专属知识场景必须搭配RAG，复杂流程必须搭配工具调用，极致要求必须搭配微调，单靠Prompt无法解决所有问题。
5.  **没有兜底机制，完全信任大模型**：任何场景都必须设计异常兜底、人工接管机制，避免大模型输出错误导致的业务事故。
6.  **忽略合规与隐私**：敏感数据未脱敏、合规约束缺失，会导致监管风险、数据泄露，是业务落地的绝对红线。
