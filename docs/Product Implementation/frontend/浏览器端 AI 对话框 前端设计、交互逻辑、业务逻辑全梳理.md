## 一、整体产品结构（前端页面模块划分）

AI 对话框整体分为三大核心模块，为基础设计前提：

1. **对话内容展示区（主体区域）**
承载历史对话上下文：用户提问气泡、AI 回复流式输出气泡、系统提示占位、加载状态、错误提示、分割线等；支持滚动、历史消息渲染、上下文持久化展示。

2. **底部输入操作区（功能区域）**
多行文本输入框、发送按钮、清空对话按钮、重置对话、换行 / 快捷键、附加功能（清空、截图、上传文件、清空上下文、语音输入等拓展按钮）。

3. **全局固定辅助模块**
顶部会话标题 / 会话列表、移动端适配折叠按钮、回到底部 / 最新消息快捷按钮、暗色 / 亮色主题切换、内容复制 / 收藏 / 点赞 / 差评操作栏。

## 二、前端 UI 设计规范（行业标准）

### 1\. 布局规范

- 整体：上下分区布局，内容区自适应高度，输入区底部固定悬浮，不随滚动消失。

- 消息气泡：左右分栏布局

    - 用户消息：靠右对齐，主色调背景、圆角卡片、文字左对齐；

    - AI 消息：靠左对齐，浅灰 / 白色背景、圆角卡片、文字左对齐；

    - 系统通知：居中浅色文字，弱化展示（欢迎语、版本提示、合规提示）。

- 自适应：兼容 PC / 平板 / 移动端，小屏自动压缩边距、输入框高度，气泡宽度自适应。

### 2\. 样式细节

- 输入框：支持单行 / 多行自动撑开、限制最大高度，超出高度出现内部滚动条；

- 按钮状态：默认态、hover 态、禁用态、加载态四级样式区分；

- 排版：AI 回复支持富文本渲染（Markdown、代码块、表格、列表、公式、链接），纯文本自动换行；

- 空白处理：页面留白、消息间距统一，避免内容挤压，长对话滚动平滑。

### 3\. 拓展 UI 组件

- 流式输出光标：AI 生成中展示动态闪烁光标 / 打字动画；

- 骨架屏：网络请求阶段展示 AI 消息骨架加载；

- 操作按钮：每条 AI 消息底部固定【复制、重试、点赞、反对、收藏】。

## 三、核心交互逻辑（完整用户操作链路）

### 1\. 基础正向交互流程

#### 初始状态

页面加载完成，内容区展示默认欢迎语 \+ 使用提示，输入框自动聚焦，发送按钮置灰禁用。

#### 用户输入操作

- 输入框输入文本内容，实时监听输入；

- 输入非空内容：发送按钮解除禁用；

- 清空内容：发送按钮恢复禁用。

#### 发送触发方式（多渠道触发，行业标配）

- 点击【发送按钮】；

- 快捷键：Enter 发送、Shift\+Enter 换行；

- 移动端：软键盘「发送」按键触发。

#### 发送后即时交互

1. 用户提问立即渲染到对话内容区，滚动自动定位到最新消息；

2. 输入框清空内容，锁定不可二次编辑；

3. 发送按钮全局禁用，防止重复点击、重复提交；

4. AI 消息位置渲染空容器 \+ 加载骨架 / 等待状态。

#### AI 流式输出交互

- 大模型接口返回分片数据流（SSE/Streaming）；

- 前端逐片段拼接文字，实时动态渲染到 AI 消息卡片；

- 文字逐字刷新，保持滚动自动跟随最新内容；

- 生成过程中：展示「正在思考 / 生成中」文案 \+ 动态光标。

#### 生成完成交互

- 流式传输结束，关闭加载动画、移除动态光标；

- 解锁发送按钮，恢复正常输入；

- AI 消息完整渲染，富文本、代码块、格式统一解析完成；

- 展示本条消息操作栏（复制、重试等）。

### 2\. 补充交互规则（易遗漏）

- 滚动交互：新消息自动滚动至底部；人工向上滑动浏览历史消息时，暂停自动滚动；新增「回到底部」悬浮按钮，点击快速定位最新对话。

- 输入框限制交互：限制最大输入字符数（如 2000/4000 字），超出实时文字计数提示；禁止纯空格、空内容发送，拦截无效请求。

- 快捷键 \&amp; 焦点交互：对话区点击空白，不丢失输入框焦点；连续对话无需重复点击输入框，持续输入提问。

### 3\. 异常场景交互

- 网络中断 / 接口超时：停止流式渲染，展示红色错误文案：「网络异常，请重试」；提供【重新生成】按钮，单条消息独立重试。

- 大模型接口报错 / 限流 / 合规拦截：屏蔽敏感内容，展示标准化合规提示；拒绝违规提问，不向后端发送请求，前端直接拦截。

- 长时间无响应：前端设置超时阈值（默认 30s/60s），超时自动终止请求并提示。

- 重复点击防护：请求期间全局按钮锁定，防抖节流处理，防止重复请求。

## 四、业务逻辑 \&amp; 数据流逻辑（前后端协作标准）

### 1\. 核心数据流链路

用户输入内容 → 前端本地校验（空值/敏感词/字数）
→ 组装请求参数（prompt、会话ID、上下文历史、模型参数）
→ 通过 SSE/HTTP Streaming 向后端大模型服务发起长链接请求
→ 后端调用大模型API，返回分片数据流
→ 前端接收分片 → 实时拼接 → 动态渲染AI消息
→ 流结束 → 关闭连接 → 保存会话记录 → 等待下一轮提问

### 2\. 前端本地业务校验（前置拦截，减少无效请求）

- 内容校验：空内容、纯空格、换行：前端直接拦截，提示「请输入问题」；超长文本：超出字数限制，截断或弹窗提示；本地敏感词基础过滤，基础违规词汇前端拦截，复杂内容交由后端二次审核。

- 状态校验：AI 生成中，禁止发起新提问、禁止清空会话，防止上下文错乱。

### 3\. 上下文会话业务逻辑

- 上下文携带规则：每一轮提问，前端自动拼接历史对话记录（用户问题 \+ AI 回复），随请求传给大模型，实现连续对话、语境理解；

- 会话隔离：每个对话独立 sessionId，新建会话清空历史上下文，互不干扰；

- 上下文截断机制：对话过多、Token 超标时，前端 / 后端自动裁剪早期历史消息，避免请求超限、响应卡顿。

### 4\. 接口通信方案（行业主流）

- 主流方案：SSE（Server\-Sent Events）：轻量、浏览器原生支持，适合文本流式输出，长链接单向推送；

- 备选方案：Fetch Streaming / WebSocket：复杂多模态场景（图片、文件、语音）选用 WebSocket；

- 请求参数标准：必传：question（用户问题）、history（上下文数组）、model（模型版本）、sessionId、temperature（随机性）。

### 5\. 数据持久化业务

- 临时存储：当前会话历史存储在前端内存中，页面刷新丢失；

- 持久化存储：结合后端接口，对话记录存入数据库，支持历史会话列表查询、回溯历史对话、删除单条 / 清空全部对话；

- 本地缓存：简易版可通过 localStorage 缓存近期会话，提升体验。

### 6\. 消息状态管理

每条消息独立状态字段，前端统一管理：

- loading：AI 思考中 / 流式加载中；

- success：回复完成；

- error：请求失败、接口异常；

- block：合规拦截、内容屏蔽。

## 五、高级业务规则（企业级 / 标准化必备）

- 停止生成功能：AI 生成过程中，提供【停止生成】按钮，手动中断 SSE 连接，终止大模型输出，节省接口费用与带宽。

- 内容解析业务：AI 返回 Markdown 格式内容，前端集成解析器，实现代码块高亮、表格渲染、引用、列表、公式展示。

- 权限 \&amp; 限流逻辑：游客模式限制提问次数、限制上下文长度；登录用户解锁完整能力，后端做接口限流、QPS 限制。

- 合规与安全业务：所有 AI 回复后端二次风控审核；禁止自动保存敏感对话，支持一键清空全部会话；复制内容增加水印 / 版权标注（产品可选）。

- 性能优化逻辑：分片渲染节流，避免高频 DOM 操作导致页面卡顿；长对话虚拟滚动，只渲染可视区域消息，优化大量历史消息页面性能。
