# 云边双模 Agent 实施方案

> 版本：v2.2（2026-10-17），替代 v2.1 / v2.0 / v1.0（2026-08-25）
> 范围：apps/desktop、apps/backend-ts、packages/modu-agent、apps/web
> 目标形态：**豆包工作型**——把"电脑"作为一等产品对象，任务选择在哪台电脑执行；云电脑是一台真实可用的远程桌面；手机是遥控器。
> 交付策略：**模型取豆包，顺序取 WorkBuddy**——数据模型一次到位，能力分批解锁。

---

## 0. 本版修订要点

### 0.1 唯一不可逆的决策

> **执行位置必须挂在 Task 上，不能挂在 Session 上。**

- 挂在 Session 上：`runtime = local|cloud` → 永远做不了"任务跑到一半换机器"，因为会话归属是静态的。
- 挂在 Task 上：`task.deviceId + lease` → 换机只是改一个字段，功能可以后置，不产生重构。

这条决定了未来三年能不能做跨设备接力。除此之外的功能都可以渐进交付。

### 0.2 V1 / V2 能力边界

| 能力 | V1（先上，WorkBuddy 节奏） | V2（增量解锁，豆包形态） |
|---|---|---|
| 执行位置 | "默认电脑" + 云电脑，二选一 | 任务级从设备列表任选 |
| 本地多台电脑 | 只暴露当前这一台 | 公司电脑 / 家里电脑可互相调度 |
| 任务中途换机 | 不支持（新建任务） | 支持，step 边界接力 |
| 手机 | 看进度 / 审批 / 远控 | 创建任务时选设备 |
| 数据模型 | Device + Task.deviceId + lease + task_events（**完整**） | **无 schema 变更** |
| 云电脑 | 常驻 Linux 桌面 VM | 同（可能加 Windows 档位） |
| 远控 | 投屏 + 有限接管 | 完整接管 / 多屏 / 高清 |

**关键承诺**：V1 的数据库 schema 就是 V2 的 schema。V2 只加接口与 UI，不改表结构。

### 0.3 相对 v1 的实质修正

| # | v1 结论 | 现结论 | 依据 |
|---|---|---|---|
| 1 | 会话级 `runtime` 归属 | **任务级 `deviceId` 是唯一路由真相**；`runtime` 降级为默认值 | 豆包 2026-08 同样锁死环境，2026-09 废弃 |
| 2 | checkpoint 不可跨 runtime 迁移 | 仅 `MemorySaver` 不可迁移；真约束是不能双写 | `factory.ts:241-253` 告警针对 memory 模式 |
| 3 | 移动端只连云端 | 移动端是遥控器，可驱动任意已登录电脑 | 豆包/WorkBuddy 均支持 |
| 4 | 本地→云单向同步最终消息 | 产物级同步 + 幂等 + 墓碑，不同步会话壳子 | 否则产生幽灵会话 |
| 5 | utilityProcess 后置 | 前置到阶段 B | 进程边界决定 Transport 接口形态 |
| 6 | 序号队列防乱序 | IPC 单 channel 本就 FIFO；真风险是背压 | `agent-runtime.ts:30-31` 注释自述 seq 仅诊断 |
| 7 | "断网完整可用" | 改为"断网可降级本机执行" | 本地电脑模式同样依赖云端下发指令 |
| 8 | 桌面端跑 Prisma + SQLite | better-sqlite3 手写 DAO（已落地） | Prisma engine 在 Electron 成本高于收益 |

## 1. 目标形态

### 1.1 终态（V2）

```
用户（手机 / 桌面 / IM 入口）
        │
        ▼
   Session   上下文与消息（服务端真源）
        │
        ▼
   Task      状态机 / 产物 / 事件日志(seq) / deviceId + lease / 可换机
        │
        ├──────────────┬──────────────┐
        ▼              ▼              ▼
  我的 MacBook    办公室 PC        云电脑
  local-fs        内网 + 本地软件   Linux 桌面 VM
  可休眠          需开机在线        24h 在线 / 可定时
```

### 1.2 V1 形态（先上线）

用户只看到两台"电脑"：**这台电脑** 与 **云电脑**。默认上次使用的那台。手机能看进度、审批、远控，但不能在任务中途换机。

对用户来说这已经是完整闭环；差异在于"多台本地电脑"和"换机"两个能力后置。

### 1.3 四条原则

1. **云边同源**：modu-agent 内核与 AGUI 协议零改动，只换投递层。跨 IPC 只走 `AGUIStreamAdapter.transform_langgraph_events` 的 `{ data: "<json>" }`，**禁止**直传原始 yield（含 LangChain `BaseMessage` 类实例，无法 structured clone）。
2. **唯一路由真相**：`task.deviceId`。任何"当前是本地还是云端"的全局判断都视为技术债。
3. **任务与连接解耦**：客户端断线只退订，不终止任务；只有显式 stop / 超时才终止。
4. **能力边界按机器算**：换机 = 换文件系统、换软件、换登录态。切换前预检并显式提示。

## 2. 行业对标

### 2.1 豆包工作（模型基准）

| 维度 | 事实 |
|---|---|
| 双执行环境 | 本地电脑 / 云电脑，2026-08-19 上线 |
| 云电脑 | 每用户独立隔离的云端环境（据公开资料为轻量 Linux 虚拟机，2C4G 级），**默认不访问本地设备文件**；本机关机任务照跑；支持定时/周期任务；手机、网页、PC 三端同步看进度 |
| 本地电脑 | 读本机文件、调本地软件、复用浏览器登录态；目标电脑需开机并已登录 |
| 切换粒度 | 任务执行中可随时切到云电脑或**另一台已登录的本地电脑**（2026-09-10 起），无需重开对话，上下文保留 |
| 跨设备 | 任意已登录电脑可作为执行目标 |
| 演进教训 | 8 月版本同样"选定环境即锁死，只能重开对话"；两周后当缺陷修复 |

### 2.2 WorkBuddy（交付节奏基准）

| 维度 | 事实 |
|---|---|
| 分层 | 交互层 / 业务应用层 / 能力服务层 / 智能体底座层 / **基础设施层（云端沙箱 + 本地运行环境）** |
| 切换粒度 | 设置 → 运行模式 → 桌面端深度执行 / 云端沙箱，**应用级开关**（据实测体验文，官方未公开该章节） |
| 云端沙箱 | 腾讯云隔离沙箱，任务结束数据自动删除；支持定时/后台，关机照跑；无法触达本地文件与内网 |
| 移动端 | 独立 APP：直连云沙箱；另有**远程控机**（投屏 + 操作 + 文件回传），需预先配对 |
| 关键观察 | 手机侧的"连云 Agent"与"远控电脑"是**两条并列通道**，不共用一个抽象 |
| 存疑 | 有自媒体称支持"执行中切换"，但该文有 SEO 注入、命名对不上，与实测冲突，不作依据 |

### 2.3 其他参照

- **VS Code Remote / JetBrains Gateway**：执行位置是 workspace/连接属性，换宿主即换窗口，从不迁移运行中进程。
- **Cursor Cloud Agents**：本地与云端并行，显式 handoff（repo snapshot + branch + PR）。
- **Codex cloud / Devin / Copilot coding agent**：detached run + 持久事件流，客户端可断开重连。

### 2.4 结论

- **数据模型取豆包**：设备是一等对象，任务级调度，可换机。
- **交付顺序取 WorkBuddy**：先"一台默认电脑 + 云电脑"，再解锁多设备与换机。
- **远控取 WorkBuddy 的并列结构**：不塞进 Agent Transport，走独立网关。

## 3. 现状核实

### 3.1 已落地（v1 阶段 0–2）

| 能力 | 位置 |
|---|---|
| Transport 三件套 + 按 runtime 选择 | `apps/desktop/src/renderer/src/services/transport/{types,http-transport,ipc-transport,index}.ts` |
| AGUI 分发器与 SSE 解析分层 | `services/api/agui.ts`（`createAguiEventDispatcher` 被两个 transport 共用） |
| 主进程内嵌 agent，5 个入口对齐 REST | `apps/desktop/src/main/agent-runtime.ts` |
| 本地 DAO（better-sqlite3 手写 SQL） | `apps/desktop/src/main/local-store.ts`，8 个 `localChat:*` 通道 |
| 会话 runtime 字段 | `apps/backend-ts/prisma/schema.prisma:93-95`、本地 DDL |
| preload 安全暴露 | `apps/desktop/src/preload/index.ts`，`sandbox`/`contextIsolation` 已开 |
| 密钥治理 | safeStorage + `SECURE_KEY_SET` 后 `reset_runner_cache()` |
| 设置页模式切换 | `components/settings/sections/LocalRuntimeSection.tsx` |
| 会话列表云 + 本地合并 | `stores/chatStore.ts` `loadSessions` |

### 3.2 与目标形态的差距

1. **两套真相并存**（最高优先级技术债）：`isLocalRuntimeActive()` 全局判断决定新会话去向，会话级 `runtime` 又决定后续路由。必须收敛到 `task.deviceId` 一处。
2. **没有"设备"概念**：只有本地/云端两档，无设备注册、在线状态、多台电脑。
3. **没有任务对象**：`agent_runs` 是记账实体，UI 不可见；用户看不到"这条任务在哪台电脑跑、跑了多久、产出了什么"。
4. **没有云电脑**：云侧只有 backend-ts 进程，没有能跑文件操作与办公软件的桌面环境。
5. **run 绑连接**：`routes/agent.ts:559-568` 客户端 close → `abort`，无法后台执行，也无法多端看直播。
6. **没有事件日志**：全仓无 `Last-Event-ID`；`agent_runs.events` 仅在 `finishAgentRun` 一次性写折叠后的里程碑。
7. **没有任何实时通道**：backend-ts 无 WebSocket（仅 `mcp.ts:51` 一个 `'websocket'` 字符串常量），设备无法保持在线，远控无从谈起。
8. **普通聊天通道未抽象**：`chatStore.ts:1012-1013` 仍走 `chatService.sendMessageStream`（SSE）。
9. **小程序登录是 mock**：`auth.ts:159` 用 `wx_mp_${code.slice(0,16)}`，未调 code2session。

### 3.3 关键约束

| 约束 | 证据 | 影响 |
|---|---|---|
| 内核有进程级单例 | `runtime-config.ts` `_config`、`factory.ts:91` `_sharedMemoryCheckpointer`、`runner.ts:80-84` `_runnerCache` | 一进程一份配置/检查点/图缓存；utilityProcess 隔离是收益而非开销 |
| checkpoint 默认内存 | `runtime-config.ts:72` 默认 `memory`；`factory.ts:241-253` 明确告警 | 重启后 resume 直接 404，换机不可能成立 |
| sqlite 路径相对 CWD | `factory.ts:197` 默认 `'checkpoints.db'` | 打包后 CWD 不可写，必须指到 `app.getPath('userData')` |
| sqlite 失败粘性降级 | `factory.ts:100` `_sqliteSaverUnavailable` | 静默降到内存 → 线上"偶发 resume 失效"，必须启动期 fail-fast |
| native 版本冲突 | 内核 optional 依赖 `better-sqlite3 ^11`，desktop `^13` | 同进程只能装一份，需收敛或改为 peer |
| 工具是宿主语义 | `file-ops`（tmpdir）、`doc-writer`（`~/.pioneering/documents`）、`code-executor`（`python3`）、MCP stdio（本机拉起） | 换电脑 = 换能力集，必须由设备注入根目录 |
| 无账号体系关联设备 | 本地固定 `LOCAL_USER_ID` | 多设备归属同一用户的前提是桌面端登录 |

## 4. 核心设计

### 4.1 四层模型

```ts
interface Device {
  id: string                 // 安装实例 UUID，与账号绑定
  userId: string
  name: string               // "我的 MacBook" / "办公室台式机" / "云电脑"
  kind: 'local' | 'cloud'
  os: 'macos' | 'windows' | 'linux'
  status: 'online' | 'busy' | 'asleep' | 'offline'
  capabilities: Array<'fs.local' | 'app.control' | 'net.intranet' | 'office' | 'gpu' | 'browser.persist'>
  authorizedRoots: string[]  // 用户授权的可访问目录
  remoteControl: boolean     // 是否允许被接管
  lastHeartbeat: string
}

interface Task {
  id: string
  sessionId: string
  deviceId: string           // ← 唯一路由真相
  status: 'pending' | 'running' | 'paused' | 'handoff' | 'completed' | 'error' | 'cancelled'
  leaseUntil: string | null
  fencingToken: number
  checkpointRef: string | null
  workspaceRef: string | null
  artifacts: ArtifactRef[]
}
```

`ChatSession.runtime` 保留列名，语义改为"上次使用的设备类型"，仅用于 UI 标注与新建任务预选。`chatStore` 中所有 `isLocalSession(session) ? ... : ...` 的三元分派都要改判 `task.deviceId`（过渡期用 `session.lastDeviceId`）。

### 4.2 Device 抽象

- **注册**：桌面启动即注册（安装实例 UUID + 设备名 + OS + capabilities + 授权目录），归属当前登录账号。
- **心跳**：15s 一次，30s 无心跳判 `offline`；休眠判 `asleep`（可被唤醒）。
- **租约**：一个 task 同时只允许一台设备写。`lease_until` 到期释放；接管时 `fencing_token += 1`，旧设备的写入被服务端拒绝。
- **能力预检**：任务指派前比对 `device.capabilities ⊇ task.requiredCapabilities`，不满足直接提示"这一步需要本机文件/内网/Office，只能在那台电脑上跑"。
- **V1 降级**：设备表完整建，但 UI 只展示"这台电脑 + 云电脑"两台，不做设备选择器。

### 4.3 Workspace：整机视角

| | 本地电脑 | 云电脑 |
|---|---|---|
| workspace 根 | 用户授权的目录集合 | 整机 `/home/user` |
| `MODU_FILE_OPS_ROOT` | 第一个授权目录 | `/home/user` |
| `MODU_DOC_WRITER_ROOT` | `~/Documents/Pioneering` | `/home/user/Documents` |
| `MODU_SQLITE_PATH` | `app.getPath('userData')/checkpoints.db` | `/data/checkpoints.db` |
| 浏览器登录态 | 复用用户现有 profile | 云电脑内独立 profile（可持久） |
| MCP stdio | 本机拉起 | 云电脑内拉起 |

不做全盘文件同步。跨机器只传 `artifactRef`（产物），不传文件系统镜像。

### 4.4 云电脑

规格与生命周期（**本方案最大成本项**）：

| 项 | 建议 |
|---|---|
| 形态 | 每用户常驻 Linux 虚拟机，2C4G 起步、20–40G 持久盘 |
| 图形栈 | 轻量桌面 + 浏览器 + 办公套件；无人操作时暂停渲染 |
| 生命周期 | 空闲 15min 休眠（内存或磁盘快照），任务触发即唤醒；连续空闲 7 天回收磁盘 |
| 软件 | 预装 Python/Node/浏览器；用户可自装 |
| 定时任务 | 调度器直接唤醒 VM，与客户端在线状态无关 |
| 隔离 | 单用户单 VM；产物落持久盘；会话结束清理临时目录 |
| 能力缺口 | **Windows 专属应用（宏、企业内网 IE、本地 ERP 客户端）跑不了**，选机时明确拦截 |

不建议"按任务起容器"：那不是"一台电脑"的心智，装软件与保留登录态都做不了。

### 4.5 任务换机（V2）

```
POST /tasks/:id/reassign  { targetDeviceId }
```

1. 服务端置 `handoff`，向源设备下发 graceful pause；
2. 源设备**在 step / turn 边界停下**（不等 node 内部完成，也不迁移正在执行的步骤）；
3. 导出 `TaskState = { checkpointBlob, artifacts[], planCursor }` 写入 `checkpoint_ref`，清空 `lease_until`；
4. 目标设备认领租约（`fencing_token += 1`），拉取状态，**从下一个 step 开始**执行；
5. 全过程追加 `handoff.requested / handoff.ready / handoff.resumed` 到事件日志。

要点：

- **不迁移运行中的进程**（业界也没有）。迁移的是静止的任务状态。
- 停粒度选 step 边界是关键：用户点"换到云电脑"后 1–3 秒切过去，而不是等一个长 node。
- checkpoint 可迁移的前提是 saver 可序列化：本地 `SqliteSaver`，云端 `PostgresSaver`。`MemorySaver` 无法导出。
- 换机后能力集会变：源设备读过的本地文件在云电脑上不存在，需先上传为 artifact 或触发能力预检。

### 4.6 事件日志与订阅

- 写入：设备每产出一条 AGUI 事件，除实时推送外追加 `task_events`（**边跑边写**）。`seq` 由服务端分配，避免跨设备时钟漂移。
- 订阅：`GET /tasks/:id/events?after_seq=N` 回放 + `GET /tasks/:id/subscribe`（SSE，支持 `Last-Event-ID`）。
- 断连语义：连接 close **不 abort**；只有 `POST /tasks/:id/stop`、超时、fencing 失效才终止。
- 客户端重连携带已消费 `seq`，补齐缺口。桌面 IPC 侧同样落本地事件表，窗口刷新后按 seq 重放。

### 4.7 远控通道（独立于 Agent Transport）

远控不是 Agent 的一条 Transport，是并行的第二条链路。手机侧两条通道并存：

```
手机 ──┬── HTTPS/SSE ──▶ 云端 ──▶ 云电脑（Agent 执行）
       │
       └── WSS ──▶ 设备网关 ──▶ 已配对电脑（人接管）
```

**为什么要独立**：协议（SSE vs 双向流）、时延要求（秒级 vs 百毫秒）、权限模型（账号 vs 设备配对 + 二次确认）都不同。合并会导致接口变形。

分三档实现：

| 档位 | 内容 | 技术 | 排期 |
|---|---|---|---|
| T1 | 指令 + 状态 + 审批 + 停止 | HTTP + SSE，复用任务通道 | 随阶段 C |
| T2 | 屏幕查看 | 截图轮询（1–2 fps）→ 后期 WebRTC | 阶段 E 首个迭代 |
| T3 | 屏幕接管 | 屏幕流 + 输入注入 | 独立子项目 |

平台差异：

| 端 | WebRTC | 输入通道 | 建议 |
|---|---|---|---|
| H5 | 可用（需 HTTPS + 手势） | HTTPS 或 DataChannel | 中等码率 |
| App | 可用 | DataChannel | 最佳体验 |
| 小程序 | 无 DataChannel，需 TRTC / live-player | HTTPS 短连接 | 截图轮询 + 点击注入足够 |

系统授权门槛（最容易卡住的地方）：

- macOS 需要**屏幕录制**权限 + **辅助功能**权限，用户手动到系统设置授权；
- Windows 可能被 EDR / 杀软拦截；
- 企业 MDM 可能直接禁用。

输入注入实现：`webContents.sendInputEvent` 只对自家窗口生效；操作系统级需 `nut.js` / 平台 API。这是又一个原生模块 ABI 风险点。

### 4.8 人机互斥

人和 Agent 抢同一台机器是必然冲突，必须有设备级仲裁：

```
agent_running ──(用户点"接管")──▶ human_takeover
      ▲                                 │
      └──────(用户点"归还")────── handoff_back
                │
                └─ agent 从 step 边界恢复（复用 §4.5 的停顿语义）
```

规则：

1. 同一台设备同一时刻只有一个控制者（agent 或人），用设备级 lease 表达。
2. 人工接管时 agent 必须暂停在 step 边界，不得继续注入输入。
3. 被控设备必须有醒目标识"正在被 XX 接管"，以及一个物理可达的中断方式。
4. 归还后从接管点继续，不重跑。

### 4.9 数据边界与合规

采用 WorkBuddy 的叙事，但保留豆包的模型：

| 概念 | 表述 |
|---|---|
| 默认电脑 | **官方数据边界承诺**：选"这台电脑"= 数据不出本机；选"云电脑"= 数据进入你的专属云环境 |
| 换机 | **用户显式操作**，不是系统自动迁移；每次换机写审计记录 |
| 云电脑 | 单用户单 VM，产物落用户专属持久盘，会话结束清理临时目录 |
| 企业策略 | 可强制锁定默认设备；可禁止换机；可禁止远控 |

这样既拿到豆包式的流畅体验，也保留 WorkBuddy 式的合规表达。

### 4.10 本地联网与离线降级

豆包形态要求本地电脑保持在线（设备注册 + 指令通道 + 远控）。取舍：

- **默认联网**：设备常驻出站长连接，接收云端指令；桌面端有明确状态指示。
- **离线降级**：断网时本机仍可独立创建/执行任务（本地 DAO + 本地 agent），任务标 `offline`，恢复后按 `clientTaskId` 幂等补报，并标注"该任务在离线期间完成"。
- **不做**：离线状态下无法被远控、无法换机、无法定时触发——这些能力本身依赖云。

### 4.11 进程隔离

- agent 移入 `utilityProcess`，主进程只做窗口编排与 IPC 路由。
- 理由：内核全局单例天然按进程隔离；better-sqlite3 同步 IO 与流式 JSON 解码不挤占主线程；单任务崩溃不带走应用。
- 通信：`MessageChannelMain` + `MessagePort`，信封 `{ taskId, seq, event }`。
- 背压：渲染端按 16ms / 64 条合帧；设备侧维护 `ack_seq` 水位，超阈值暂停读取 generator。
- Transport 接口不变（`sendMessage / resume / abort / getState / stop`），实现从"主进程直调"改为"主进程转发"。

### 4.12 凭据域

| | 本地电脑 | 云电脑 |
|---|---|---|
| LLM Key | safeStorage 加密，注入 env 后 `reset_runner_cache()` | 平台托管，不下发客户端 |
| 用户身份 | 登录后持有 JWT（多设备归属前提） | 服务端身份 |
| 渲染进程 | 只拿"已配置"状态，不读明文 | 零密钥 |

计量口径需产品决策：本地执行用平台托管 key 才能计费；若允许自带 key，订阅协议需区分 `billing_mode: platform | byok`。

## 5. 实施路线图

```
阶段 A  已完成（Transport / IPC 内核 / 本地 DAO）
   └─▶ 阶段 B  数据模型一次到位 + 进程隔离       ← 唯一不可逆的一步
          └─▶ 阶段 C  任务解耦 + 事件日志
                 ├─▶ 阶段 D  云电脑
                 │      └─▶ 阶段 F  任务级选机 + 换机（增量）
                 └─▶ 阶段 E  移动端 + 远控通道
```

### 阶段 A · 已完成（v1 阶段 0–2）

见 §3.1。遗留收口项：

1. 普通聊天通道抽象到 Transport（`chatStore.ts:1012-1013`）。
2. CRUD 收敛到 `SessionRepository`，替代散落的 `isLocalSession ? localChatService : chatService` 三元。
3. 会话列表分页（现固定取两端各 50 条，无 cursor）。
4. better-sqlite3 版本收敛（`^11` vs `^13`）。

### 阶段 B · 数据模型一次到位 + 进程隔离

**目标**：把"本地/云端两档"换成 Device + Task，但 UI 只暴露两台电脑。这一步之后，V2 的功能都只是加接口。

改动清单：

1. **桌面端登录**：接入现有 JWT + refresh（`auth.ts`），本地档案与云端 userId 绑定；未登录保留为降级态（不可被远控、不可换机）。
2. `devices` 表 + 注册/心跳/列表接口；桌面启动注册，上报 name/os/capabilities/authorizedRoots。
3. `tasks` 表（由 `agent_runs` 升级）+ `task_events` 表；`deviceId` 为必填。
4. **收敛两套真相**：删除 `isLocalRuntimeActive()` 的全局分派；`chatStore` 改为按 `session.lastDeviceId` 路由；`ChatSession.runtime` 仅作 UI 标注。
5. `agent-runtime.ts` 迁入 `agent-process.ts`（utilityProcess 入口），主进程保留薄转发；事件信封 `{ taskId, seq, event }` + 合帧 + `ack_seq`。
6. `/agent/sessions` 补写默认设备；`init_db()` 同步 ALTER（注意 `schema.prisma` 注释：TS 侧不 migrate，列变更由 Python `init_db()` 维护）。
7. 全局"默认电脑"设置项，替代现有 `LocalRuntimeSection` 的模式开关。

验收：两台设备注册成功且状态正确；新建任务记录正确 `deviceId`；删除全局判断后 HTTP/IPC 两条路径行为一致；强杀 agent-process 后应用不崩。
回退：设置页保留"仅本机"入口；设备功能按账号灰度。

### 阶段 C · 任务解耦 + 事件日志

**目标**：任务成为 UI 可见对象；断线不中断、刷新可续看。

改动清单：

1. `task_events` 边跑边写，服务端分配 `seq`。
2. `POST /tasks/:id/stop` 替代"连接关闭即 abort"（`routes/agent.ts:559-568` 改为只退订）。
3. 订阅端点支持 `Last-Event-ID` / `after_seq`；桌面 IPC 侧同样保存本地事件表。
4. checkpoint 切 `SqliteSaver`（本地）/ `PostgresSaver`（云端）；显式绝对路径；`_sqliteSaverUnavailable` 改启动期 fail-fast。
5. 任务列表 / 任务详情 UI：设备名、状态、耗时、产物、事件时间线。
6. 离线降级：本地任务标 `offline`，恢复后按 `clientTaskId` 幂等补报。

验收：任务执行中断网 30s 恢复，事件不丢、任务未中断、seq 连续；关窗重开可看到完整过程；云端重启后 `resume` 仍成功。
回退：事件日志双写开关关闭，重回"仅 SSE"。

### 阶段 D · 云电脑

**目标**：云侧从"一个后端进程"变成"一台能干活儿的电脑"。

改动清单：

1. 每用户常驻 Linux VM（2C4G / 20–40G 持久盘）+ 桌面栈 + 镜像与初始化脚本。
2. Workspace 注入（§4.3）：工具根目录全部按设备注入，禁止读隐式默认路径。
3. 空闲休眠 / 唤醒 / 7 天回收；配额与并发限制。
4. 定时任务：`schedule` 作为 task 触发源，直接唤醒 VM。
5. 能力预检 + UI 拦截：Windows 专属应用、本地文件依赖。
6. 协议版本协商：事件增加 `protocol_version`，设备上报 `supported_versions`；字段只增不删。

验收：默认设备切到云电脑后，文件写入 / 文档生成 / 浏览器任务全部可用；关掉客户端后定时任务仍按时执行；依赖本地文件的任务被正确拦截并给出可理解提示。
回退：云电脑入口按用户灰度。

### 阶段 E · 移动端 + 远控通道

**目标**：手机成为可用的遥控器（T1 + T2）。

改动清单：

1. 设备网关：`@fastify/websocket` + 设备出站 WSS 长连接 + 配对/鉴权/心跳。
2. 移动端接入：任务创建、事件订阅、HITL 审批、停止。
3. 微信小程序真实登录（替换 `auth.ts:159` 的 mock）；补手机号/扫码登录。
4. 推送：任务完成 / 暂停 / 失败 / 需要审批。
5. T2 屏幕查看：截图轮询（1–2 fps）+ 前端查看器。
6. 同步规则：
   - **同步对象**：消息（`clientMsgId` 幂等 upsert）、产物（`artifactRef`）、任务终态。
   - **不变量**：不做会话壳子同步；本地归档会话在云端标 `archived_from: device`，标注"仅归档，需在来源设备继续"。
   - **删除**：墓碑 `deleted_at`。
   - **冲突**：服务端单一真源 + 客户端乐观更新，冲突按 `updated_at` 后写胜出并记审计。

验收：手机创建任务（云电脑）并看到实时输出；手机批准 HITL 后任务继续；手机能看到本机桌面截图；归档会话不出现在可续跑列表。
回退：移动端入口灰度；远控默认关闭，逐设备开启。

### 阶段 F · 任务级选机 + 换机（增量）

**目标**：解锁豆包形态，不改 schema。

改动清单：

1. 设备选择器：新建任务时从设备列表任选（含其他已登录电脑）。
2. `POST /tasks/:id/reassign` + step 边界停顿 + 状态导出/恢复 + 租约转移。
3. `artifactRef` 跨设备寻址：内容哈希 + 自动上传或显式拒绝。
4. 能力预检扩展到换机路径；UI 明确提示"该文件仅存在于 A 设备"。
5. 远控 T3：WebRTC 推流 + 输入注入 + 人机互斥（§4.8）+ 审计。

验收：本机跑到一半换到云电脑，纯网络类任务从下一个 step 续跑成功；依赖本机文件的任务在换机前被拦截；人工接管时 agent 暂停且归还后继续。
回退：换机入口按用户灰度。

## 6. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| **两套真相（全局开关 + 会话 runtime）** | 高 | 阶段 B 一次性收敛到 `task.deviceId`；不接受"过渡期两套并存"超过一个版本 |
| **云电脑成本**（每用户常驻 VM） | 高 | 空闲休眠 + 快照恢复；7 天回收磁盘；套餐限制规格与并发；免费额度只给按需唤醒 |
| **Linux 云电脑跑不了 Windows 专用应用** | 高 | 能力预检拦截 + 明确文案；预留 Windows 档位 |
| native 模块 ABI（better-sqlite3 / sqlite saver / 输入注入） | 高 | 版本收敛单一 major；`asarUnpack`；干净虚拟机验证安装包；utilityProcess 内加载 |
| sqlite saver 静默降级到内存 | 高 | 启动期 fail-fast；健康检查暴露 `checkpointer_ready`，降级即告警 |
| **远控攻击面**（账号被盗 = 拿到一台内网机器） | 高 | 设备出站连接不开端口；每会话一次性 token 绑定设备指纹；端到端加密；设备端可见指示 + 一键中断；完整审计；企业可整体禁用 |
| 常驻远控通道被安全软件拦截 / 企业禁用 | 高 | 明确状态指示与开关；提供企业白名单；支持"仅指令不下发屏幕"降级模式 |
| 换机状态不一致（产物丢失/重复） | 高 | `artifactRef` 内容哈希 + 幂等写入；换机失败回滚源设备并保留原租约 |
| 双设备同时写同一 thread | 中 | 租约 + `fencing_token`，服务端拒绝旧 token 写入 |
| 人工接管与 agent 抢输入 | 中 | 设备级 lease + 人机互斥状态机（§4.8），接管即暂停 agent |
| 事件背压导致渲染卡顿 | 中 | 合帧（16ms/64 条）+ `ack_seq` 水位 + 超阈值暂停读 generator |
| 本地联网依赖 vs "离线可用" | 中 | 默认联网；断网降级本机执行 + 幂等补报；不承诺"断网可被远控" |
| 多设备文件不一致 | 中 | 不做全盘同步；只传产物；预检提示文件所在设备 |
| 协议版本漂移 | 中 | `protocol_version` + `supported_versions` 协商 + 只增不改 |
| 内核进程级单例 | 中 | 每进程一份；utilityProcess 隔离后天然解决；云端按 `threadId` 隔离 |
| 凭据域串台 | 中 | 切换设备时同步切换凭据域；云端模式渲染端零密钥 |
| 商业模型缺口（自带 key 无法计费） | 中 | 订阅协议区分 `billing_mode: platform \| byok` |

## 7. 明确不做的事

- **不在会话上做执行位置**——唯一路由真相是 `task.deviceId`。
- **V1 不做任务级选机与换机**——数据模型就位，但 UI 与接口后置，避免一上来就背分布式一致性。
- **不把远控塞进 Agent Transport**——两条并行链路，只在设备租约层交汇。
- **不做运行中进程/步骤的热迁移**——迁移的是静止任务状态，换机在 step 边界发生。
- **不做全盘文件同步**——跨设备只传产物。
- **不做无头函数沙箱**——云侧就是一台桌面 VM（形态选择，不是技术偏好）。
- **不做双向实时同步**——只做消息/产物/终态的幂等单向收敛。
- **不做纯离线 agent**——离线只保证"本机能独立跑"，不保证"能被远控"。
- **不做会话壳子的跨端复制**——归档只读，避免幽灵会话。
- **不退役 backend-ts**——转为云形态 + 设备调度 + 移动端后端。
- **不在渲染进程持有云端密钥**。

## 9. 工作量判断

内核改动仍接近零（async generator + 标准事件协议是根本杠杆）。工作量分四块，且**前两块是不可省的**：

| 块 | 阶段 | 说明 | 相对量级 |
|---|---|---|---|
| 数据模型一次到位 | B | Device/Task/lease 表 + 收敛两套真相 + utilityProcess | 中，但**不可跳过** |
| 任务解耦 | C | task_events + 订阅 + checkpoint 持久化 | 中 |
| 云电脑 | D | VM 镜像、初始化、休眠唤醒、持久盘、回收 | **最大**，且是运维不是编码 |
| 移动端 + 远控 | E | 设备网关 + 截图投屏 + 小程序登录 | 中大；T3 接管单列 |
| 换机 | F | 接口 + 状态导出 + 预检 + UI | **小**（前提是 B 做对了） |

一句话：**阶段 B 是唯一不可逆的一步，成本很低但决定了后面能不能做豆包形态；阶段 F 之所以能做到"增量"，完全依赖 B 的 schema 设计。**
