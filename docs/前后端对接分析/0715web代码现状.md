## 3. 核心业务逻辑与数据流向

### 3.1 认证流

```
Login.tsx → useAuth.login(data, rememberMe) → loginApi() POST /auth/login
  → useAuthStore.authenticate(user, token, refreshToken, rememberMe)
  → client.setToken(token, refreshToken, persistent)  // persistent 选 localStorage 否则 sessionStorage
  → navigate(from || '/chat')
```

[ProtectedRoute.tsx](file:///d:/Administrator/Desktop/pioneering/apps/web/src/components/auth/ProtectedRoute.tsx) 在挂载时调用 `init()`：仅检查 `localStorage.token` 是否存在，存在即置为 `authenticated`，**不验证 Token 有效性**。`auth.ts` 通过 `onRehydrateStorage` 在 hydration 时根据 token 恢复 status，避免刷新闪回登录页。

### 3.2 会话列表与创建流

`Sidebar` 挂载时 `fetchSessions()` 拉取第一页，底部 `IntersectionObserver` 触发 `fetchMoreSessions()` 无限滚动。`fetchMoreSessions` 含 `fetchingCursor` 防同页重复请求 + `dedupedLen >= total` 终止 + `dedupeById` 按 id 去重。

新建会话采用 **乐观更新 + 并发去重 + 空壳清理**（[conversationStore.ts](file:///d:/Administrator/Desktop/pioneering/apps/web/src/store/conversationStore.ts)）：

1. 立即插入 `temp_${Date.now()}` 临时会话到列表顶部并激活；
2. 若已有 `createPromise` 在进行中，复用同一 Promise；
3. 后台调用 `sessionApi.createSession()`，成功后用真实会话替换临时会话并迁移 `sessionModes` 映射，失败则回滚；
4. **空壳清理**：`create()` 进入时若发现标题为「新会话」且无预览的临时会话，自动清理防止列表堆积。

删除会话通过 `remove(id, archive=true)` 默认走软删除归档；删除活跃会话时**自动切换到相邻会话**。`setArchivedView` 支持在「会话列表 / 归档视图」间切换并重新拉取。

**注意**：`sessionModes` 本地映射用于弥补后端 `Session` 无 `mode` 字段，通过 `persist` 持久化。

### 3.3 ChatMode 消息流

```
ChatMode (顶层)
  ├─ useEffect[activeId] → getMessages(direction:'before') → setHistoryMessages()
  │                                  （含竞态保护：loadingForId === store.activeId）
  ├─ useEffect[historyMessages] → chatEngine.setMessages(historyMessages, 'replace')
  │                                  （手动同步，不再用 key={activeId} 重挂载）
  ├─ useChatSync(activeId, messages) → updatePreview / generateTitle（AI 摘要）
  ├─ handleSend
  │    ├─ 无 activeId → create('chat') 后再发送
  │    ├─ activeId.startsWith('temp_') → await store.createPromise
  │    └─ chatEngine.sendUserMessage({ prompt })
  ├─ handleStop → chatEngine.abortChat() + stopGeneration(后端，取最后 assistant.id)
  └─ handleReplay → regenerateMessage(专用端点) + reloadHistory
```

`useChat` 的 `onRequest` 通过 `useConversationStore.getState()` 读取最新 `activeId`，避免闭包捕获陈旧值。

### 3.4 ProMode Agent 流

`useAgentChat`（[useAgentChat.ts](file:///d:/Administrator/Desktop/pioneering/apps/web/src/modes/pro/hooks/useAgentChat.ts)）是自研 AG-UI SSE 状态机：

- 直接 `fetch('/api/agent/completions')` + ReadableStream 手动解析 `data: ` 行；
- 解析事件类型：`RUN_STARTED/FINISHED/ERROR`、`TEXT_MESSAGE_CONTENT/THINKING_*`、`TOOL_CALL_START/ARGS/END/RESULT`、`STATE_DELTA`；
- 维护 `stateMap`（步骤字典）与 `messages`（对话消息）；
- `AgentMessage = ChatMessagesData` 直接复用类型；
- `sendMessage` 每次调用 **重置 messages 为 [userMsg]**（[useAgentChat.ts:99](file:///d:/Administrator/Desktop/pioneering/apps/web/src/modes/pro/hooks/useAgentChat.ts#L99)），意味着**不支持多轮对话累积**；

## 4. API 交互机制

### 4.1 通用 client

[client.ts](file:///d:/Administrator/Desktop/pioneering/apps/web/src/api/client.ts) 提供 `request<T>` 统一封装：

- Token 双存储：`setToken(token, refreshToken, persistent)` 根据 `persistent` 选择 `localStorage`（跨会话保留）或 `sessionStorage`（关闭浏览器清除），并清理另一侧避免双存；`getToken`/`getRefreshToken` 同时查两处；
- 自动注入 `Content-Type: application/json` 与 `Authorization: Bearer <token>`；
- 204 直接返回 `undefined`；
- **401 自动刷新重试**：调用 `tryRefreshToken()`，单例 `refreshPromise` 防并发刷新，POST `/auth/refresh`（蛇形 `refresh_token` 字段，与类型层驼峰 `refreshToken` 命名不一致），成功后保留原存储位置写入新 token 并重试原请求；仍 401 则 `clearToken()` + throw `ApiError`；
- **注意**：刷新失败后**无全局跳转登录页**，仅向上抛 401，依赖各 UI 自行处理（如 Sidebar 在 401 错误时展示「去登录」按钮）；
- 自动解包后端 `ResponseInterceptor` 的 `{ code, data, message }` 格式；
- 导出 `get / post / put / del` 四个动词封装；GET/DELETE 通过 `URLSearchParams` 拼接 query。

### 4.2 流式对话三条路径并存

| 路径 | 入口 | 状态 |
|------|------|------|
| `api/chat.ts` 的 `streamChat` | 手动 fetch + ReadableStream + SSE 解析 | **死代码**，无任何调用方（详见 §7.2.4） |
| `@tdesign-react/chat` 的 `useChat` | TDesign 内部封装，`protocol: 'agui'` | ChatMode / TaskMode 使用 |
| `useAgentChat` | 自研 fetch + AG-UI 事件解析 | ProMode 使用 |

`streamChat` 的 `AguiEvent` 接口 `delta` 为单一 string 字段，`TEXT_MESSAGE_CONTENT` 与 `THINKING_TEXT_MESSAGE_CONTENT` **共享同一段处理逻辑**，未对思考内容做区分回调。`reasoningContent` 仅在 `converter.ts` 从持久化的 `ContentBlock` 提取时区分。

### 4.3 API 模块清单

| 模块 | 路径 | 关键 API |
|------|------|---------|
| `auth-api.ts` | `/auth/*`、`/user/profile` | login / register / refreshToken / logout / getProfile |
| `session.ts` | `/chat/sessions/*` | getSessions（游标分页）/ create / get / update / delete（默认软删除）/ generateTitle（AI 摘要） |

### 4.4 类型契约

[api/types.ts](file:///d:/Administrator/Desktop/pioneering/apps/web/src/api/types.ts) 与后端 DTO 对齐。但存在以下不一致：

- `ContentBlock` 同时存在 `text?` / `code?` / `content?` / `reasoningContent?` 多个文本字段，其中 `content / id / role` 三个非标准字段无注释说明用途，疑似与 Message 字段混淆的历史遗留（详见 §7.6.1）；
- `ChatCompletionChoice.delta` 未声明 `reasoningContent` 字段，流式思考内容无法类型化；

## 5. 状态管理策略

### 5.1 状态分层

| Store | 形式 | 持久化 | 职责 |
|-------|------|--------|------|
| `useAppStore` | Zustand | 否 | 仅 `sidebarOpen`（`mode` 已下放到 `useMode`） |
| `useConversationStore` | Zustand + persist | `sessionModes` | 会话列表、activeId、分页、创建去重、归档视图 |
| `useAuthStore` | Zustand + persist | `user` | 认证状态机 |
| `ThemeContext` | React Context | localStorage('theme') | 主题切换 |
| `ToastContext` | React Context | 否 | 全局 Toast |
| `app:preferences` | localStorage（原生） | — | SettingsDialog 偏好（主题/字号/密度/通知/对话行为） |

### 5.2 关键设计

- **`useConversationStore.create` 并发去重**：通过 `createPromise` 字段保证多次快速点击只创建一个会话；空壳「新会话」自动清理；sessionModes 映射在成功时迁移 tempId → realId，失败时清理 tempId。
- **`useMode` 派生 mode**：从 `useLocation().pathname` 正则匹配 `^/(chat|pro|task)` 作为 mode 唯一真理来源，替代原 `appStore.mode`。直接访问 `/pro` 时高亮正确。
- **`useChat` 内部状态 vs store 状态**：消息列表 `messages` 由 TDesign `useChat` 内部维护，未上提到 store，跨模式/跨会话切换时通过 `chatEngine.setMessages(historyMessages, 'replace')` 手动同步（不再用 `key={activeId}` 重挂载）。
- **Token 双存储**：`rememberMe` 贯通全链路——`login(data, rememberMe)` → `authenticate(..., rememberMe)` → `setToken(token, refreshToken, persistent)`，persistent 决定 localStorage/sessionStorage。

### 5.3 状态管理主要问题

1. **Zustand 与 Context 混用**：`ThemeContext` / `ToastContext` 完全可以用 Zustand 替代以保持一致性；当前混用导致 Provider 链冗长且无法用 `getState()` 在组件外访问。
