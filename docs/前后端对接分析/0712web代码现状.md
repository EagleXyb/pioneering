## 3. 核心业务逻辑与数据流向

### 3.1 认证流

```
Login.tsx → useAuth.login() → loginApi() POST /auth/login
  → useAuthStore.authenticate(user, token, refreshToken)
  → client.setToken() 写 localStorage
  → navigate(from || '/chat')
```

路由守卫 [ProtectedRoute.tsx](file:///Users/ybxue/Desktop/pioneering/apps/web/src/components/auth/ProtectedRoute.tsx#L13-L22) 在挂载时调用 `init()`：仅检查 `localStorage.token` 是否存在，存在即置为 `authenticated`，**不验证 Token 有效性**。

### 3.2 会话列表与创建流

`Sidebar` 挂载时 `fetchSessions()` 拉取第一页（[Sidebar.tsx:315-317](file:///Users/ybxue/Desktop/pioneering/apps/web/src/layout/Sidebar/Sidebar.tsx#L315-L317)），底部 `IntersectionObserver` 触发 `fetchMoreSessions()` 无限滚动（[Sidebar.tsx:323-335](file:///Users/ybxue/Desktop/pioneering/apps/web/src/layout/Sidebar/Sidebar.tsx#L323-L335)）。

新建会话采用 **乐观更新 + 并发去重**（[conversationStore.ts:113-188](file:///Users/ybxue/Desktop/pioneering/apps/web/src/store/conversationStore.ts#L113-L188)）：

1. 立即插入 `temp_${Date.now()}` 临时会话到列表顶部并激活；
2. 若已有 `createPromise` 在进行中，复用同一 Promise；
3. 后台调用 `sessionApi.createSession()`，成功后用真实会话替换临时会话，失败则回滚。

**注意**：`sessionModes` 本地映射用于弥补后端 `Session` 无 `mode` 字段（[conversationStore.ts:24-25](file:///Users/ybxue/Desktop/pioneering/apps/web/src/store/conversationStore.ts#L24-L25)），通过 `persist` 持久化。

### 3.3 ChatMode 消息流

```
ChatMode (顶层)
  ├─ useEffect[activeId] → getMessages() → setHistoryMessages()
  │                                  （含竞态保护：loadingForId === store.activeId）
  └─ ChatSession
       ├─ useEffect[historyMessages] → chatEngine.setMessages(historyMessages, 'replace')
       │                                  （绕过 useChat 内部 length>0 守卫）
       ├─ useChatSync(activeId, messages) → updatePreview / updateTitle
       ├─ handleSend
       │    ├─ 无 activeId → create('chat') 后再发送
       │    ├─ activeId.startsWith('temp_') → await store.createPromise
       │    └─ chatEngine.sendUserMessage({ prompt })
       ├─ handleStop → chatEngine.abortChat() + stopGeneration(后端)
       └─ handleReplay → 找到前一条 user 消息重新 sendUserMessage
```

详见 [ChatMode.tsx:75-138](file:///Users/ybxue/Desktop/pioneering/apps/web/src/modes/chat/ChatMode.tsx#L75-L138)。

`useChat` 的 `onRequest` 通过 `useConversationStore.getState()` 读取最新 `activeId`，避免闭包捕获陈旧值（[ChatMode.tsx:41-59](file:///Users/ybxue/Desktop/pioneering/apps/web/src/modes/chat/ChatMode.tsx#L41-L59)）。

### 3.4 ProMode Agent 流

`useAgentChat`（[useAgentChat.ts](file:///Users/ybxue/Desktop/pioneering/apps/web/src/modes/pro/hooks/useAgentChat.ts)）是自研 AG-UI SSE 状态机：

- 直接 `fetch('/api/agent/completions')` + ReadableStream 手动解析 `data: ` 行；
- 解析事件类型：`RUN_STARTED/FINISHED/ERROR`、`THINKING_START/TEXT_MESSAGE_CONTENT/END`、`TOOL_CALL_START/ARGS/END/RESULT`、`STATE_DELTA`；
- 维护 `stateMap`（步骤字典）与 `messages`（对话消息）；
- `sendMessage` 每次调用 **重置 messages 为 [userMsg]**（[useAgentChat.ts:103](file:///Users/ybxue/Desktop/pioneering/apps/web/src/modes/pro/hooks/useAgentChat.ts#L103)），意味着**不支持多轮对话累积**。

### 3.5 TaskMode 流

直接复用 TDesign `useChat`，但相比 ChatMode 缺失多项能力（详见 §7.3）。

## 4. API 交互机制

### 4.1 通用 client

[client.ts](file:///Users/ybxue/Desktop/pioneering/apps/web/src/api/client.ts) 提供 `request<T>` 统一封装：

- 自动注入 `Content-Type: application/json` 与 `Authorization: Bearer <token>`；
- 204 直接返回 `undefined`；
- 401 调用 `clearToken()` 并 throw `{ code: 401, message: '未认证或 Token 已过期' }`；
- 自动解包后端 `ResponseInterceptor` 的 `{ code, data, message }` 格式（[client.ts:85-87](file:///Users/ybxue/Desktop/pioneering/apps/web/src/api/client.ts#L85-L87)）。

### 4.2 流式对话两条路径并存

| 路径 | 入口 | 状态 |
|------|------|------|
| `api/chat.ts` 的 `streamChat` | 手动 fetch + ReadableStream + SSE 解析 | **死代码**，无任何调用方 |
| `@tdesign-react/chat` 的 `useChat` | TDesign 内部封装，`protocol: 'agui'` | ChatMode / TaskMode 使用 |
| `useAgentChat` | 自研 fetch + AG-UI 事件解析 | ProMode 使用 |

详见 [chat.ts](file:///Users/ybxue/Desktop/pioneering/apps/web/src/api/chat.ts)（死代码）与 [ChatMode.tsx:36-63](file:///Users/ybxue/Desktop/pioneering/apps/web/src/modes/chat/ChatMode.tsx#L36-L63)（useChat）。

### 4.3 类型契约

[api/types.ts](file:///Users/ybxue/Desktop/pioneering/apps/web/src/api/types.ts) 与后端 DTO 对齐。但存在以下不一致：

- `ContentBlock` 同时存在 `text?` / `code?` / `content?` / `reasoningContent?` 多个文本字段（[types.ts:86-98](file:///Users/ybxue/Desktop/pioneering/apps/web/src/api/types.ts#L86-L98)），注释自承 `reasoningContent` 是"非标准 ContentBlock 字段"；
- `ChatCompletionChoice.delta` 未声明 `reasoningContent` 字段，流式思考内容无法类型化；
- `Message.parentMessageId` / `childrenMessageIds` 用于消息树，但前端从未消费（无分支对话 UI）。

## 5. 状态管理策略

### 5.1 状态分层

| Store | 形式 | 持久化 | 职责 |
|-------|------|--------|------|
| `useAppStore` | Zustand | 否 | `mode` / `sidebarOpen` |
| `useConversationStore` | Zustand + persist | `sessionModes` | 会话列表、activeId、分页、创建去重 |
| `useAuthStore` | Zustand + persist | `user` | 认证状态机 |
| `ThemeContext` | React Context | localStorage('theme') | 主题切换 |
| `ToastContext` | React Context | 否 | 全局 Toast |

### 5.2 关键设计

- **`useConversationStore.create` 并发去重**：通过 `createPromise` 字段保证多次快速点击只创建一个会话（[conversationStore.ts:114-116](file:///Users/ybxue/Desktop/pioneering/apps/web/src/store/conversationStore.ts#L114-L116)）。
- **`sessionModes` 本地映射**：弥补后端 `Session` 无 `mode` 字段，前端通过 `persist` 维护 `sessionId -> mode` 映射，是当前架构的一个**权宜之计**（[conversationStore.ts:24-25](file:///Users/ybxue/Desktop/pioneering/apps/web/src/store/conversationStore.ts#L24-L25)）。
- **`useChat` 内部状态 vs store 状态**：消息列表 `messages` 由 TDesign `useChat` 内部维护，未上提到 store，跨模式/跨会话切换时通过 `chatEngine.setMessages(historyMessages, 'replace')` 手动同步（[ChatMode.tsx:66-68](file:///Users/ybxue/Desktop/pioneering/apps/web/src/modes/chat/ChatMode.tsx#L66-L68)）。

### 5.3 状态管理主要问题

1. **目录分裂**：`store/`（appStore/conversationStore/themeContext/toastContext）与 `stores/`（auth）并存，无任何理由。
2. **Zustand 与 Context 混用**：`ThemeContext` / `ToastContext` 完全可以用 Zustand 替代以保持一致性；当前混用导致 Provider 链冗长且无法用 `getState()` 在组件外访问。
3. **`appStore.mode` 与路由不同步**：`mode` 是本地状态，但路由 `/chat|/pro|/task` 才是真理来源。直接访问 `/pro` 时 `appStore.mode` 仍为默认 `'chat'`，需等 Sidebar 渲染才同步（[appStore.ts:11-15](file:///Users/ybxue/Desktop/pioneering/apps/web/src/store/appStore.ts#L11-L15)）。

### 7.8 类型契约问题

#### 7.8.1 `ContentBlock` 字段冗余

**问题**：[types.ts:86-98](file:///Users/ybxue/Desktop/pioneering/apps/web/src/api/types.ts#L86-L98)：

```ts
export interface ContentBlock {
  type: 'text' | 'code' | 'image' | 'file';
  text?: string;
  code?: string;
  language?: string;
  imageUrl?: string;
  fileId?: string;
  reasoningContent?: string;  // 非标准字段
  content?: string;            // 与 text/code 语义重叠
  id?: string;
  role?: string;
}
```

`text` / `code` / `content` 三个文本字段语义重叠，`reasoningContent` 是非标准字段，`id` / `role` 与外层 `Message` 重复。

**建议**：用 discriminated union 重构：

```ts
type ContentBlock =
  | { type: 'text'; text: string }
  | { type: 'code'; code: string; language?: string }
  | { type: 'image'; imageUrl: string }
  | { type: 'file'; fileId: string }
  | { type: 'reasoning'; reasoningContent: string };
```

#### 7.8.2 `ChatCompletionChoice.delta` 缺少 `reasoningContent`

**问题**：流式响应中思考内容字段未类型化（[types.ts:134-141](file:///Users/ybxue/Desktop/pioneering/apps/web/src/api/types.ts#L134-L141)）。

**建议**：

```ts
export interface ChatCompletionChoice {
  index: number;
  delta: {
    role?: string;
    content?: string;
    reasoningContent?: string;  // 补充
  };
  finishReason?: 'stop' | 'length' | 'content_filter' | null;
}
```
