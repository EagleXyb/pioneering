### 1.2 各模块职责详解

#### 1.2.1 API 请求层（`src/api/`）

| 文件 | 职责 | 关键设计 |
|------|------|----------|
| `client.ts` | HTTP 基础设施 | 统一 `request<T>` 函数，自动注入 `Authorization: Bearer` 头；401 自动清除 Token；自动解包后端 `{code, data, message}` 响应包装；支持 GET/POST/PUT/DELETE |
| `chat.ts` | 对话补全 | `streamChat` 基于 `fetch + ReadableStream` 手动解析 SSE；返回 `AbortController` 用于中止；`[DONE]` 信号结束流 |
| `session.ts` | 会话 CRUD | `getSessions`(分页)、`createSession`、`getSession`、`updateSession`、`deleteSession`(归档/物理删除) |
| `message.ts` | 消息管理 | `getMessages`(游标分页)、`editMessage`、`feedbackMessage`、`regenerateMessage`、`stopGeneration` |
| `auth-api.ts` | 认证接口 | `loginApi`、`registerApi`(预留)、`refreshTokenApi`、`getProfileApi` |
| `converter.ts` | 格式转换 | 后端 `Message` → TDesign `ChatMessagesData`；assistant 消息从 `contentBlocks` 提取 `reasoningContent` 转为 `thinking` block |
| `types.ts` | 类型契约 | 对齐后端 API schema，定义 User/Session/Message/ChatCompletion 等接口 |

#### 1.2.2 状态管理层（`src/store/` + `src/stores/`）

采用 **Zustand + React Context 混合方案**：

| Store | 类型 | 持久化 | 职责 |
|-------|------|--------|------|
| `appStore.ts` | Zustand | 否 | `mode`(chat/pro/task)、`sidebarOpen` |
| `conversationStore.ts` | Zustand + persist | `sessionModes` | 会话列表、分页加载、创建/删除/重命名、`sessionModes` 映射（弥补后端无 mode 字段） |
| `stores/auth.ts` | Zustand + persist | `user` | 认证状态机(idle/loading/authenticated/error)、Token 管理 |
| `themeContext.tsx` | React Context | localStorage | 主题切换(light/dark/system)，设置 `data-theme` 属性 |
| `toastContext.tsx` | React Context | 否 | 全局 Toast 通知（2s 显示 + 300ms 退场动画） |

#### 1.2.3 布局层（`src/layout/`）

- **Sidebar**：模式切换器(chat/pro/task)、新建会话按钮、会话列表(按"今天/昨天/更早"分组)、无限滚动加载、会话重命名(双击/按钮)、删除确认弹框、账号弹出菜单(主题切换/设置/登出)
- **TopNav**：侧边栏折叠/展开、状态演示下拉(原型用 loading/error/empty 状态切换)、内联错误提示与重试

#### 1.2.4 业务模式层（`src/modes/`）

| 模式 | 入口 | 通信协议 | 核心特性 | 完成度 |
|------|------|----------|----------|--------|
| **chat（对话）** | `ChatMode.tsx` | TDesign `useChat` + AGUI | SSE 流式对话、深度思考开关、联网查询开关、建议词快捷发送、历史消息加载 | ✅ 基本可用 |
| **pro（分析）** | `ProMode.tsx` | 自研 `useAgentChat` + AGUI | SSE 流式 + AG-UI 协议解析、推理过程可视化(stateMap)、双栏布局(对话+流程面板)、进度条 | ✅ 核心可用 |
| **task（任务）** | `TaskMode.tsx` | TDesign `useChat` + AGUI | 对话 + 任务流水线面板 | ⚠️ 流水线待开发 |

#### 1.2.5 认证模块（`src/pages/auth/` + `src/components/auth/`）

- **AuthLayout**：双栏品牌布局（左侧 3D 立方体装饰 + 右侧表单卡片）
- **Login**：TDesign Form 表单验证、记住我、微信登录占位、Tab 切换登录/注册
- **Register**：密码强度计算算法（长度+大小写+数字特殊字符三维度）、密码匹配校验
- **ProtectedRoute**：路由守卫，未认证跳转 `/auth/login` 并保存 `from` 路径

### 2.4 架构设计要点说明

1. **懒加载**：三大模式组件均使用 `React.lazy` + `Suspense`，减小首屏 bundle 体积。
2. **状态分层**：全局状态用 Zustand（会话/认证/应用），UI 局部状态用 React Context（主题/Toast），职责清晰。
3. **持久化策略**：`conversationStore` 仅持久化 `sessionModes`（因为后端无 mode 字段），`authStore` 仅持久化 `user`，Token 存 localStorage 由 `client.ts` 管理——三者分离，避免敏感信息冗余存储。
4. **API 代理**：开发环境 Vite proxy 将 `/api` 转发至 `http://localhost:8000`（后端 FastAPI），生产环境需同源部署或 Nginx 反代。
5. **AG-UI 协议**：Pro 模式自研 `useAgentChat` 解析 AG-UI 标准事件协议，实现了推理过程(thinking)、工具调用(tool_call)、工具结果(tool_result)、文本流(text_message)的完整状态机。

## 3. 关键业务流程梳理

### 3.1 认证流程

```
[用户访问] 
    │
    ▼
ProtectedRoute 
    │
    ├── init() → 检查 localStorage.token
    │   ├── 有 token → status='authenticated' → 放行
    │   └── 无 token → Navigate /auth/login (保存 from 路径)
    │
    ▼
[LoginPage]
    │
    ├── TDesign Form 校验 (username + password required)
    │
    ├── useAuth.login({ username, password })
    │   ├── setStatus('loading')
    │   ├── loginApi → POST /auth/login
    │   │   ├── 成功 → authenticate(user, token, refreshToken)
    │   │   │        → setToken (localStorage)
    │   │   │        → status='authenticated'
    │   │   │        → navigate(from || '/chat')
    │   │   └── 失败 → setError + status='error'
    │   └── 
    │
    ▼
[AppLayout] → Sidebar + TopNav + Mode
```

**状态流转**：`idle → loading → authenticated | error`

### 3.2 会话管理流程

```
[Sidebar 挂载]
    │
    ├── useEffect → fetchSessions()
    │   ├── getSessions(1, 50) → GET /chat/sessions?page=1&pageSize=50
    │   ├── sessionToConversation() 转换（mode 从 sessionModes 映射读取）
    │   └── 按 group 分组（今天/昨天/更早）
    │
    ├── [无限滚动] IntersectionObserver → fetchMoreSessions()
    │   └── getSessions(nextPage, 50) 追加
    │
    ├── [新建会话] handleNewConversation()
    │   ├── create(mode) → POST /chat/sessions { title:'新会话', model:'deepseek-v4-flash' }
    │   ├── sessionToConversation(session, { [id]: mode })
    │   ├── 更新 conversations + activeId + sessionModes + total
    │   └── navigate(`/${mode}`)
    │
    ├── [切换会话] handleSelectConversation()
    │   ├── activate(id) → set activeId
    │   ├── setMode(conv.mode)
    │   └── navigate(`/${mode}`)
    │
    ├── [重命名] 双击标题 / 点击重命名按钮
    │   ├── 进入编辑态 (input.focus + select)
    │   ├── Enter / Blur → commitRename → updateTitle(id, title)
    │   │   └── PUT /chat/sessions/:id { title }
    │   └── Escape → cancelRename
    │
    └── [删除] 点击删除 → 确认弹框 → confirmDelete()
        ├── remove(id, false) → DELETE /chat/sessions/:id?archive=false
        ├── 过滤 conversations + 清理 sessionModes
        └── 若删除的是 activeId → 自动激活第一个剩余会话
```

### 3.3 Chat 模式对话流程

```
[用户输入] ChatInput
    │
    ├── ChatSender.onChange → inputValue 更新
    │
    ├── [发送] handleSend(text)
    │   ├── if (!activeId) → create('chat') 创建会话
    │   ├── chatEngine.sendUserMessage({ prompt: text })
    │   │   └── onRequest 回调:
    │   │       ├── 读取 useConversationStore.getState().activeId (避免闭包过期)
    │   │       ├── 注入 Authorization header
    │   │       └── body: { sessionId, message, stream:true, deepThink: deepThinkingRef.current }
    │   └── setInputValue('')
    │
    ├── [SSE 流式响应] useChat 内部处理
    │   ├── onChunk → 增量更新 messages
    │   └── onDone → status='complete'
    │
    ├── [useChatSync] 监听 messages 变化
    │   ├── updatePreview(activeId, 最后一条消息前 80 字)
    │   └── 首次用户消息 → updateTitle(activeId, 用户输入前 30 字)
    │       └── PUT /chat/sessions/:id { title }
    │
    ├── [停止生成] handleStop()
    │   ├── chatEngine.abortChat() (前端 AbortController)
    │   └── stopGeneration({ sessionId, messageId }) → POST /chat/completions/stop
    │
    └── [历史加载] useEffect(activeId)
        └── getMessages(activeId, undefined, 50, 'before')
            └── convertMessages → setHistoryMessages → useChat defaultMessages
```

### 3.4 Pro 模式 Agent 推理流程（核心算法）

```
[用户发送分析需求] sendMessage({ prompt })
    │
    ├── 1. 中止之前的请求 (abortRef.current?.abort())
    ├── 2. 重置状态: messages=[userMsg], stateMap={}, status='pending'
    ├── 3. 添加占位 assistant 消息
    ├── 4. status='streaming', 发起 fetch /api/agent/completions
    │
    └── 5. SSE 流解析循环 (AG-UI 协议状态机):
        │
        ├── RUN_STARTED → (空操作)
        │
        ├── THINKING_START ─────────────────────┐
        │   ├── stepCounter++                    │
        │   ├── stateMap[step_N] = {             │ 推理
        │   │     type:'thinking',               │ 阶段
        │   │     label: event.title,            │
        │   │     status:'running'               │
        │   │   }                                │
        │   └── currentStateKey = step_N         │
        │                                        │
        ├── THINKING_TEXT_MESSAGE_CONTENT ───────┤
        │   └── thinkingContent += delta         │
        │       stateMap[step_N].content 更新    │
        │                                        │
        ├── THINKING_END ────────────────────────┘
        │   └── stateMap[step_N].status = 'done'
        │
        ├── TOOL_CALL_START ────────────────────┐
        │   ├── stepCounter++                    │
        │   ├── stateMap[step_N] = {             │ 工具
        │   │     type:'tool_call',              │ 调用
        │   │     label:`调用工具 ${toolName}`,  │ 阶段
        │   │     status:'running'               │
        │   │   }                                │
        │   └── currentStateKey = step_N         │
        │                                        │
        ├── TOOL_CALL_ARGS ─────────────────────┤
        │   └── stateMap[step_N].content = delta │
        │                                        │
        ├── TOOL_CALL_END ──────────────────────┤
        │   └── (空操作，等待 RESULT)             │
        │                                        │
        ├── TOOL_CALL_RESULT ───────────────────┘
        │   ├── stateMap[toolCallKey].status='done'
        │   ├── stepCounter++
        │   ├── stateMap[step_N] = {             ┐
        │   │     type:'tool_result',            │ 观察
        │   │     label:`工具结果: ${toolName}`, │ 阶段
        │   │     content: event.content,        │
        │   │     status:'done'                  │
        │   │   }                                ┘
        │   └── currentStateKey = null
        │
        ├── TEXT_MESSAGE_CONTENT ───────────────┐
        │   ├── accumulatedText += delta         │ 最终
        │   └── messages[last].content =         │ 回答
        │       [{ type:'markdown', data: ... }] │ 流式
        │                                        │
        ├── TEXT_MESSAGE_END ───────────────────┘
        │
        ├── RUN_FINISHED → currentStateKey=null
        │
        ├── RUN_ERROR ──────────────────────────
        │   ├── status='error'
        │   ├── 清理所有 running → done
        │   ├── messages[last].content = 错误信息
        │   └── return (退出循环)
        │
        └── [流结束]
            └── status='complete', messages[last].status='complete'
```

### 3.5 主题切换流程

```
AccountPopover / 主题按钮
    │
    ├── setTheme('light' | 'dark' | 'system')
    │   ├── setThemeState(t)
    │   ├── if 'system' → removeAttribute('data-theme') + removeItem('theme')
    │   └── else → setAttribute('data-theme', t) + setItem('theme', t)
    │
    └── CSS 层:
        ├── :root { 浅色变量 }
        ├── [data-theme="dark"] { 深色变量 }
        └── @media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { 深色变量 } }
```

### 3.6 注册流程（密码强度算法）

```typescript
// calcPasswordStrength 算法 — 三维度评分
function calcPasswordStrength(password: string): StrengthLevel {
  let strength = 0;
  if (password.length >= 8) strength++;                              // 维度1: 长度
  if (/[a-z]/.test(password) && /[A-Z]/.test(password)) strength++;  // 维度2: 大小写
  if (/[0-9]/.test(password) && /[^a-zA-Z0-9]/.test(password)) strength++; // 维度3: 数字+特殊字符
  return strength; // 0-3
}
// 映射: 0-1=弱, 2=中, 3=强
```

## 4. 潜在问题排查与优化建议

### 4.1 并发问题

#### 🔴 P0 — Chat 模式发送时序竞态

**位置**：`ChatMode.tsx:74-80`

```typescript
const handleSend = async (text: string) => {
  if (!activeId) {
    await create('chat');   // 异步创建会话
  }
  chatEngine.sendUserMessage({ prompt: text });  // ← activeId 可能尚未更新
  setInputValue('');
};
```

**问题**：`create('chat')` 是异步操作，`activeId` 的更新通过 Zustand `set` 触发，但 `chatEngine.sendUserMessage` 在 `await` 后立即执行时，`onRequest` 回调读取的是 `useConversationStore.getState().activeId`。虽然 Zustand 的 `set` 是同步的，但 `create` 内部先调用 `sessionApi.createSession`（网络请求），`activeId` 在网络请求返回后才设置。因此 `sendUserMessage` 可能在 `activeId` 更新前就触发，导致 `sessionId` 为旧值或 null。

**建议**：`create` 返回 `session.id`，显式使用返回值：

```typescript
const handleSend = async (text: string) => {
  let sessionId = activeId;
  if (!sessionId) {
    sessionId = await create('chat');
  }
  chatEngine.sendUserMessage({ prompt: text });
  setInputValue('');
};
```
但 `onRequest` 仍读 store，需确保 store 已更新。更稳妥的做法是在 `onRequest` 中若 `activeId` 为空则从闭包变量读取。

#### 🟡 P1 — 会话切换时旧 SSE 流未中止

**位置**：`ChatMode.tsx:26-42` + `ProMode.tsx`

**问题**：切换会话（`activeId` 变化）时，`useEffect` 重新加载历史消息，但未中止正在进行的 SSE 流。若上一个会话的流式响应仍在进行，其增量会写入新的 `messages` 状态，导致消息串台。

**建议**：在 `useEffect` 清理函数中调用 `chatEngine.abortChat()`（Chat 模式）或 `abort()`（Pro 模式）。

#### 🟡 P1 — useChatSync 标题更新竞态

**位置**：所有 `useChatSync.ts`

**问题**：`doneRef` 用于确保标题只更新一次，但 `doneRef` 是组件级 ref，切换会话时 `conversationId` 变化但 `doneRef` 不会重置。若用户在会话 A 发了消息（doneRef=true），切到会话 B，B 的标题不会被更新。

**建议**：在 `useEffect` 中监听 `conversationId` 变化时重置 `doneRef.current = false`。

### 4.2 异常处理问题

#### 🔴 P0 — SSE 流解析未处理连接中断

**位置**：`chat.ts:66-100` + `useAgentChat.ts:155-399`

**问题**：当网络中断导致 `reader.read()` 抛出异常时，`streamChat` 的 `.catch` 会调用 `onError`，但 `useAgentChat` 中只在 `try/catch` 中处理。若流在传输过程中断开（非 AbortError），用户可能看到不完整的消息且无错误提示。`useAgentChat` 的 catch 块会将错误信息写入 assistant 消息，但 `streamChat`（Chat 模式使用）的 `onError` 回调未被 `useChat` 正确消费。

**建议**：统一错误处理策略，在 UI 层展示网络中断提示并提供重试按钮。

#### 🟡 P1 — 401 Token 过期无自动刷新

**位置**：`client.ts:62-66`

```typescript
// 401 未授权 — 后续补全认证模块时在此刷新 Token
if (response.status === 401) {
  clearToken();
  throw { code: 401, message: '未认证或 Token 已过期' } as ApiError;
}
```

**问题**：代码注释明确写了"后续补全"，但当前 Token 过期后直接清除并抛错，用户正在编辑的内容会丢失，且无静默刷新机制。`refreshTokenApi` 已定义但未被调用。

**建议**：实现 Token 刷新拦截器——401 时尝试用 `refreshToken` 调用 `/auth/refresh`，成功后重放原请求，失败再跳登录页。

#### 🟡 P1 — useAgentChat 历史消息未加载

**位置**：`ProMode.tsx` + `useAgentChat.ts:69`

**问题**：`useAgentChat` 的 `messages` 初始值为 `[]`，切换会话时不加载历史消息（不像 Chat 模式有 `getMessages` + `convertMessages`）。用户切换到已有对话的 Pro 会话时看到空白。

**建议**：在 `useAgentChat` 中增加 `activeId` 变化时的历史消息加载逻辑。

#### 🟡 P2 — 删除会话失败后状态不一致

**位置**：`conversationStore.ts:124-136`

**问题**：`remove` 方法先调用 `deleteSession` API，成功后才更新本地状态。若 API 失败，本地状态不变（正确），但 `confirmDelete` 的 catch 只显示 Toast，用户无法得知具体原因。

**建议**：展示后端返回的具体错误信息。

### 4.3 安全漏洞

#### 🔴 P0 — XSS 风险：Markdown 内容未消毒

**位置**：`converter.ts:34-38` + `ChatMessageItem.tsx` + `AnalysisMessageList.tsx`

**问题**：assistant 消息内容以 `type: 'markdown'` 传递给 TDesign ChatMessage 渲染。虽然 TDesign 内部使用 markdown 解析器，但如果后端返回的 content 包含恶意 `<script>` 或 `javascript:` 链接，且 TDesign 的 markdown 渲染未做严格消毒（sanitize），则存在 XSS 风险。

**建议**：
1. 确认 TDesign Chat 组件内部是否使用 DOMPurify 等 HTML 消毒库。
2. 在 `converter.ts` 中对 content 做预过滤，移除 `<script>` 标签和 `javascript:` 协议。
3. 后端也应做输出编码。

#### 🟡 P1 — Token 存储于 localStorage

**位置**：`client.ts:9-25`

**问题**：JWT Token 存储在 `localStorage`，可被 XSS 攻击读取。这是常见的前端安全权衡，但对于敏感应用不够安全。

**建议**：考虑将 Token 改为 HttpOnly Cookie（需后端配合 CORS + credentials），或至少将 refreshToken 存储在更安全的位置。

#### 🟡 P1 — 密码强度算法过弱

**位置**：`Register.tsx:21-27`

**问题**：`calcPasswordStrength` 仅检查长度≥8、大小写、数字+特殊字符三个维度，未检测常见弱密码（如 `Password1!`）、连续字符、重复字符等。且 strength=1 也显示"弱"，但 UI 上与 strength=0 相同。

**建议**：引入 zxcvbn 库做真实密码强度评估，或增加黑名单检测。

#### 🟡 P2 — 路由守卫仅检查 Token 存在性

**位置**：`stores/auth.ts:47-52` + `ProtectedRoute.tsx`

**问题**：`init()` 仅检查 `localStorage.getItem('token')` 是否存在，不验证 Token 有效性（过期时间、签名）。过期 Token 也会通过守卫，直到 API 返回 401 才清除。

**建议**：在 `init()` 中解码 JWT 检查 `exp` 字段，过期则主动清除；或调用 `getProfileApi()` 验证。

### 4.4 功能缺陷与边界条件

#### 🔴 P0 — Task 模式 onRequest 闭包过期

**位置**：`TaskMode.tsx:19-32`

```typescript
onRequest: (params) => ({
  ...params,
  body: JSON.stringify({
    sessionId: activeId,  // ← 闭包捕获，切换会话后为旧值
```

**问题**：与 Chat 模式不同，Task 模式的 `onRequest` 直接使用闭包中的 `activeId`，而非 `useConversationStore.getState().activeId`。切换会话后发送消息会使用旧的 sessionId。

**建议**：改为 `useConversationStore.getState().activeId`。

#### 🟡 P1 — Chat 模式 historyMessages 与 useChat 不同步

**位置**：`ChatMode.tsx:22-69`

**问题**：`historyMessages` 作为 `useChat` 的 `defaultMessages` 传入，但 `useChat` 的 `defaultMessages` 通常只在初始化时生效。切换会话时 `historyMessages` 更新，但 `useChat` 内部 messages 可能不会重新初始化。

**建议**：使用 `useChat` 的 `key` 属性或手动重置机制，确保会话切换时消息列表正确更新。

#### 🟡 P1 — 联网查询 / 附件功能未实现

**位置**：`ChatInput.tsx:17, 42-46, 56-66`

**问题**：`webSearch` 状态切换了但未传入 `onRequest` 的 body；附件按钮无 `onClick`。用户以为功能生效但实际未发送。

**建议**：明确标注"功能开发中"或接入后端参数。

#### 🟡 P2 — 会话列表分页 pageSize 硬编码 50

**位置**：`conversationStore.ts:80, 95`

**问题**：`fetchSessions` 和 `fetchMoreSessions` 硬编码 `pageSize=50`，若用户会话数极多，首屏加载 50 条可能偏慢。

**建议**：首屏加载 20 条，滚动加载 20 条/页。

#### 🟡 P2 — ProMainHeader 进度条计算可能为负

**位置**：`AnalysisLayout.tsx:24`

```typescript
style={{ width: `${((stepCount - runningCount) / stepCount) * 100}%` }}
```

**问题**：若 `runningCount > stepCount`（理论上不应该但防御性编程需考虑），宽度为负数。

**建议**：`Math.max(0, Math.min(100, ((stepCount - runningCount) / stepCount) * 100))`。

#### 🟡 P2 — 日期分组时区问题

**位置**：`conversationStore.ts:43-51`

**问题**：`getGroup` 使用 `new Date(dateStr)` 解析后端时间，若后端返回 UTC 时间但前端按本地时区计算"今天/昨天"，跨时区用户可能分组错误。

**建议**：确认后端时间格式（是否带 Z 后缀），统一使用本地时区计算。

### 4.5 性能优化建议

#### 🟡 P1 — messages 变化触发频繁 scrollIntoView

**位置**：`ChatMessageList.tsx:14-16` + `AnalysisMessageList.tsx:24-26` + `TaskMessageList.tsx:24-26`

**问题**：`useEffect` 依赖 `[messages]`，SSE 流式输出时每个 delta 都触发 `scrollIntoView({ behavior: 'smooth' })`，高频调用导致性能问题和滚动抖动。

**建议**：
1. 使用 `behavior: 'auto'`（流式期间）。
2. 或使用 `requestAnimationFrame` 节流。
3. 或仅当用户已滚动到底部时才自动滚动。

#### 🟡 P1 — useAgentChat stateMap 高频更新

**位置**：`useAgentChat.ts:211-227`

**问题**：`THINKING_TEXT_MESSAGE_CONTENT` 每个 delta 都调用 `setStateMap`，触发组件重渲染。长文本思考过程会产生大量渲染。

**建议**：对 `thinkingContent` 更新做节流（如 50ms 一次），或使用 `useRef` 暂存 + `requestAnimationFrame` 批量更新。

#### 🟡 P2 — 会话列表未做虚拟滚动

**位置**：`Sidebar.tsx:412-434`

**问题**：会话列表直接 `map` 渲染，虽然有无限滚动分页，但已加载的所有会话都留在 DOM 中。100+ 会话时会有性能问题。

**建议**：引入虚拟滚动（如 `react-window`）。

#### 🟡 P2 — TopNav 状态演示为原型代码

**位置**：`TopNav.tsx:29-42, 64-91`

**问题**：`state-preview-dropdown` 是原型演示用的状态切换器，在生产环境应移除。

**建议**：通过环境变量 `import.meta.env.DEV` 条件渲染。

#### 🟢 P3 — useChatSync 三份重复代码

**位置**：`modes/chat/hooks/useChatSync.ts`、`modes/pro/hooks/useChatSync.ts`、`modes/task/hooks/useChatSync.ts`
