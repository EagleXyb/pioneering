# 设计概要与细节

## 一、业界标准的「滚动感知头部栏」（scroll-aware header）模式

> Slack、Discord、Notion、Telegram 桌面端等主流产品都在使用这一模式：
> **当内容滚动离开顶部时，会话头部栏才显出一条分隔线/阴影，把"内容已经滚动"这一状态反馈给用户；
> 回到顶部或内容不足一屏时，分隔线消失，头部与内容融为一体。**

本项目的桌面端（`apps/desktop/src/renderer/src/`）完整落地了这一模式，并把业界常见的
"显隐整条边框导致 1px 布局抖动（layout shift）"问题用 CSS 技巧规避掉了。

---

### 1. 模式落地的完整信号链路

滚动感知头部栏在本项目中是一条 **单向数据流（scroll 事件 → atom → 头部栏样式）**：

```
┌─────────────────────────────────────────────────────────────────┐
│ ChatArea.tsx（信号源）                                          │
│   监听 [data-slot="message-scroller-viewport"] 的 scroll 事件    │
│   → container.scrollTop > 0 ? setChatScrolled(true) : false     │
└──────────────────────────┬──────────────────────────────────────┘
                           │ jotai atom 写入
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│ stores/atoms.ts（状态）                                          │
│   export const chatScrolledAtom = atom(false)                    │
└──────────────────────────┬──────────────────────────────────────┘
                           │ jotai atom 读取
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│ layouts/ChatHeader.tsx（消费端）                                 │
│   const isChatScrolled = useAtomValue(chatScrolledAtom)          │
│   className: border-b border-transparent                         │
│              + isChatScrolled && 'border-border/50'              │
└─────────────────────────────────────────────────────────────────┘
```

**关键文件与职责：**

| 文件 | 角色 | 关键代码 |
|------|------|----------|
| `components/chat/ChatArea.tsx` | 信号采集 | `container.addEventListener('scroll', update, { passive: true })`，`update = () => setChatScrolled(container.scrollTop > 0)` |
| `stores/atoms.ts` | 状态中枢 | `chatScrolledAtom = atom(false)` |
| `layouts/ChatHeader.tsx` | 视觉反馈 | `isChatScrolled && 'border-border/50'` |
| `layouts/RootLayout.tsx` | 布局承载 | 把 `ChatHeader` 作为中栏白色圆角卡片的常驻顶部栏渲染 |

### 2. 滚动感知的判定逻辑（细节）

`ChatArea.tsx` 第 107–125 行的 `useEffect` 是模式的核心：

```ts
useEffect(() => {
  const pane = messagesPaneRef.current
  if (!pane) return
  const container = pane.querySelector<HTMLElement>(
    '[data-slot="message-scroller-viewport"]'
  )
  if (!container) {
    setChatScrolled(false)        // 无滚动容器（欢迎页 / 内容不足一屏）时强制收起
    return
  }
  const update = () => setChatScrolled(container.scrollTop > 0)
  update()                        // 初始同步一次（避免首屏状态错乱）
  container.addEventListener('scroll', update, { passive: true })
  window.addEventListener('resize', update)   // 窗口尺寸变化也要重新判定
  return () => {
    container.removeEventListener('scroll', update)
    window.removeEventListener('resize', update)
  }
}, [showWelcome, currentSessionId, currentMessages.length, setChatScrolled])
```

业界实现该模式时普遍遵循的细节，本项目全部命中：

1. **阈值即 0**：判定条件为 `scrollTop > 0`，即"只要离开顶部 1px 就显示分隔线"，
   这是 Slack/Discord 的标准做法（而非用 10px/20px 这类模糊阈值）。
2. **无滚动内容时收起**：当容器不存在（`WelcomeScreen` 欢迎页）或内容不足一屏时，
   显式 `setChatScrolled(false)`，避免空会话出现一条孤零零的分割线。
3. **初始同步（`update()` 立即跑一次）**：切换会话 / 重渲染后，首屏状态不会"丢失旧滚动位置"。
4. **多触发源**：除了 `scroll`，还监听了 `window.resize`，保证窗口缩放后状态正确。
5. **依赖精确**：`useEffect` 依赖 `showWelcome`、`currentSessionId`、`currentMessages.length`，
   在切换会话、消息数量变化时自动重新挂载监听并重置。
6. **性能友好**：`scroll` 监听用 `{ passive: true }`（不阻塞滚动），且 `setChatScrolled`
   只在布尔值真正变化时触发 Jotai 重渲染（Jotai atom 默认按引用/值去重）。

### 3. 防布局抖动的 CSS 技巧（本项目的精华细节）

业界很多实现"滚动后才显示分隔线"的版本，会遇到一个经典 bug：
**边框从无到有的 1px 高差会让下方内容整体下移 1px（layout shift），肉眼可见地抖一下。**

本项目的解决方案（`ChatHeader.tsx` 第 56–59 行）：

```tsx
<div
  className={cn(
    'flex items-center h-[var(--titlebar-h)] shrink-0 px-4 select-none border-b border-transparent',
    isChatScrolled && 'border-border/50'
  )}
>
```

要点：
- **始终保留 `border-b` 的 1px 占位空间**，颜色默认是 `border-transparent`（透明）。
- 滚动时**只切换颜色**（`border-transparent` → `border-border/50`），边框的"物理高度"从不变化。
- 因此头部栏高度恒定，下方消息流永不产生 1px 位移 —— 这正是 Slack/Discord 处理该问题的标准手法。

### 4. 头部栏自身的视觉与布局细节（Slack/Discord 式）

`ChatHeader` 在"滚动感知"之外，还对齐了主流产品的头部栏设计语言：

- **常驻渲染、不随滚动消失**：头部栏本身是 fixed/sticky 语义（始终在卡片顶部，`shrink-0`），
  滚动感知只控制"分隔线"，不控制"头部栏是否存在"。这与 Discord 一致（顶栏常驻，仅加阴影/分割线）。
- **左侧**：侧边栏折叠时显示「展开侧边栏 + 新建任务」入口；macOS 下通过
  `paddingLeft: 'var(--traffic-light-w)'` 避让红绿灯（窗口控制按钮区），这是桌面端特有的平台细节。
- **中间**：会话标题（`truncate` 省略，防止长标题撑破布局）；展开态左侧留 9px 边距对齐卡片。
- **右侧**：搜索 / 分享 / 历史 / 展开右面板，统一用 `HeaderButton`（ghost + 18px 图标 + Tooltip）。
- **小屏覆盖模式**：Win/Linux 走 `TopBarActions`（`TopBarActions.tsx`），同样保持 ghost 图标 + Tooltip 的视觉一致，
  仅高度/间距略小（`h-7 w-7` 对比 `h-8 w-8`）。

### 5. 与滚动系统的整体协同

头部栏的"滚动感知"只是整个消息区滚动系统的一个消费方；上游滚动系统
（`MessageScrollerList.tsx`，基于 `@shadcn/react` 的 Message Scroller）还负责：

- **流式自动跟随**：`autoScroll`，用户上滑后自动停止跟随（多信号融合：滚动/文字选中/键盘/链接点击/搜索）。
- **新 turn 锚定**：`user` 消息标记 `scrollAnchor`，新回合锚定到视口顶部附近（`scrollPreviousItemPeek={80}`）。
- **跳到最新按钮**：`MessageScrollerButton`，距底 `scrollEdgeThreshold={80}` 内自动显隐。
- **重开定位**：`defaultScrollPosition="end"`。

> 注意：头部栏的"下边框显隐"与"跳到最新按钮"是两条**独立的滚动消费链路**——
> 前者读 `chatScrolledAtom`，后者由 MessageScroller 内部状态驱动，互不耦合，符合单一职责。

### 6. 模式对应的实现清单（可对照验收）

若要评估本项目是否"达到业界标准 scroll-aware header"，可逐条核对：

| 业界标准点 | 本项目实现 | 位置 |
|-----------|-----------|------|
| 滚动离开顶部才显示分隔线 | `scrollTop > 0` 驱动 `border-border/50` | `ChatArea.tsx` / `ChatHeader.tsx` |
| 回到顶部/无内容时隐藏 | 显式 `setChatScrolled(false)` + 初始 `update()` | `ChatArea.tsx` |
| 边框显隐不引起 layout shift | 常驻 1px `border-transparent` 仅切色 | `ChatHeader.tsx` |
| 滚动监听性能（passive） | `{ passive: true }` | `ChatArea.tsx` |
| 切换会话/重渲染状态重置 | useEffect 依赖 + 清理 | `ChatArea.tsx` |
| 窗口尺寸变化重判定 | `window.resize` 监听 | `ChatArea.tsx` |
| 头部栏常驻（仅分隔线随滚动） | `shrink-0` 常驻 + 仅切分隔线 | `ChatHeader.tsx` / `RootLayout.tsx` |
| 平台差异（macOS 红绿灯避让） | `--traffic-light-w` padding | `ChatHeader.tsx` |

---

### 7. 小结

本项目对「滚动感知头部栏」的实现**完整对齐了 Slack / Discord 的工业级做法**：
- 用 `scroll` 事件 + `scrollTop > 0` 阈值判定；
- 用 Jotai 原子做单一数据源，头部栏只做纯消费；
- 用"常驻透明边框 + 仅切色"消除 1px layout shift；
- 覆盖了空会话、切换会话、窗口缩放、平台差异等边界情况。

这是一处小而精、符合业界标准的交互细节实现。
