## 跨进程通信（IPC）

### MessagePack 二进制协议

OpenCowork 使用 MessagePack 作为 IPC 序列化格式替代传统的 JSON，原因包括：

- **更小的体积** — 二进制格式减少传输数据量
- **更快的解析** — 二进制解码比 JSON.parse 更高效
- **类型安全** — 与 TypeScript 配合良好
- **流式传输** — 支持 Agent Stream 的增量事件推送

核心 IPC 文件：

- `src/shared/messagepack/binary-ipc.ts` — 约 80+ 个 IPC 频道定义，编码/解码辅助函数
- `src/shared/messagepack/agent-stream-codec.ts` — Agent Stream 信封的编码/解码
- `src/main/lib/native-worker.ts` — Named pipe / Unix domain socket 上的 MessagePack 帧传输

### IPC 通信模式

```
Renderer                    Main Process
   │                            │
   │  ipcClient.invoke(...)     │
   │ ─────────────────────────> │
   │     encodeMessagePack       │
   │  (Uint8Array payload)      │
   │                            │
   │  toMessagePackChannel()    │
   │                            │
   │  decodeMessagePackPayload  │
   │  (typed result)            │
   │ <───────────────────────── │
```

对于 Agent Stream 事件，使用事件监听器模式：

```
Main (Native Worker)         Renderer
   │                            │
   │  agent/stream 事件帧        │
   │ ─────────────────────────> │
   │  通过 ipcRenderer.on()     │
   │  解码 AgentStreamEnvelope   │
   │  分发到各 Store / UI        │
```

## .NET Native Worker 侧车架构

Native Worker 是一个独立的 .NET 10.0 Native AOT 进程，作为 Electron 主进程的"侧车"运行：

```
Electron Main
   │
   │ spawn("OpenCowork.Native.Worker.exe", ["--ipc", pipeName])
   │
   ▼
Named Pipe (Win) / Unix Domain Socket (macOS/Linux)
   │
   │ MessagePack 帧协议 (4字节长度头 + payload)
   ▼
Native Worker (.NET 10, Native AOT)
   │
   ├── Program.cs → WorkerHost → WorkerDispatcher
   │                        └── 20+ 模块
   │
   ├── AgentRuntime 模块（核心，~40+ 文件）
   │   ├── LLM 提供商适配（Anthropic/OpenAI/Gemini）
   │   ├── 工具执行引擎（文件/Shell/SSH/网页/子代理/团队/技能/MCP）
   │   └── 流式响应处理
   │
   ├── System / File / Git / Db / Sync 模块
   ├── Settings / Config / ChannelConfig 模块
   ├── Skill / Extension / McpConfig 模块
   ├── OpenAIImages / OpenAIAudio / Web 模块
   ├── Shell / Terminal / Ssh 模块
   └── UserContent / AgentChange 模块
```

### Native Worker 生命周期

1. **启动**：Electron 主进程启动时通过 `getNativeWorker().ensureStarted()` 启动 Worker
2. **连接**：创建 Named Pipe / Unix Socket，等待 Worker 进程连接
3. **握手**：发送 `worker/ping`，验证连接正常
4. **路由验证**：发送 `worker/routes`，确认必需方法存在
5. **服务**：处理各类 IPC 请求（设置读写、数据库操作、Agent 运行时等）
6. **关闭**：`app.before-quit` 时调用 `stopNativeWorker()` 优雅关闭

## Agent 运行时架构

### 提供商无关设计

Agent 运行时完全与 LLM 提供商解耦，通过统一的抽象层支持：

- **Anthropic Messages API** (Claude)
- **OpenAI Responses API** (GPT)
- **Google Gemini API**
- **Ollama 本地模型**
- **20+ 第三方提供商**（OpenRouter、DeepSeek、Moonshot 等）

### 流式架构

Agent 运行时基于流式事件架构：

```
用户输入 → AgentLoop → LLM API (流式 SSE/WebSocket)
              ↓
         text_delta / thinking_delta / tool_use_args_delta
              ↓
         AgentStreamEnvelope → IPC → Renderer Store → UI 更新
              ↓
         工具调用 → 工具执行 → tool_call_result → 下一轮迭代
```

### 工具调用流程

1. **工具注册** — 渲染进程启动时注册所有可用工具（`registerAllTools()`）
2. **工具发现** — 每个 Agent 请求前动态构建工具目录（`ensureRequestToolCatalogFresh()`）
3. **工具调用** — LLM 输出 `tool_use` 块 → Agent Loop 解析 → 匹配注册的工具
4. **审批机制** — 需要审批的工具进入 `pending_approval` 状态，等待用户确认
5. **工具执行** — 通过后执行，结果作为 `tool_result` 返回给 LLM
6. **循环迭代** — 直到 LLM 输出完整消息或达到最大迭代次数

## 五种会话模式

每个会话（Session）关联一个模式，决定系统提示词、可用工具和 Agent 行为：

| 模式 | 系统提示词 | 可用工具 | 典型用途 |
|------|-----------|---------|---------|
| `chat` | 通用对话 | 基础工具 | 快速问答 |
| `clarify` | 澄清与规划 | 文件浏览、搜索 | 需求分析、计划制定 |
| `cowork` | 全功能协作 | 所有工具 | 日常开发协作 |
| `code` | 代码结对编程 | 文件编辑、Bash、代码工具 | 精准代码生成与修改 |
| `acp` | 架构控制流程 | 子代理、团队工具 | 架构设计、任务分解 |

模式提示词文件：`src/renderer/src/lib/prompts/prompt-loader.ts`

## 数据流：用户消息到 AI 响应

```
1. 用户在 InputArea 输入消息
      ↓
2. ChatStore 创建/更新会话，保存到 SQLite (via IPC → Native Worker)
      ↓
3. AgentStore 启动 Agent Loop
      ↓
4. Agent Loop 构建系统提示词（模式提示 + 记忆文件 + 上下文）
      ↓
5. 调用 Native Worker → `agent/start` 路由
      ↓
6. Native Worker AgentRuntime 模块向 LLM API 发起流式请求
      ↓
7. LLM 流式输出 text_delta / tool_use_delta 等事件
      ↓
8. Native Worker 编码为 AgentStreamEnvelope，通过 Named Pipe 发送
      ↓
9. Main Process 的 NativeWorkerManager 接收帧 → 通过 IPC 转发到 Renderer
      ↓
10. Renderer 的 agentStream 解码信封 → 更新 AgentStore → UI 组件重新渲染
      ↓
11. 遇到工具调用时，渲染进程通过 renderer-tool-bridge 执行工具
      ↓
12. 工具结果通过 IPC 回传 Native Worker → 作为 tool_result 发给 LLM
      ↓
13. Agent Loop 进入下一轮迭代
      ↓
14. 最终 loop_end 事件标记 Agent 完成
```

## 运行时同步机制

为了支持多个窗口同时查看同一会话（主窗口 + 独立会话窗口），OpenCowork 实现了运行时同步：

- `session-runtime:sync` — 会话运行时事件同步（Agent Stream 事件）
- `session-control:sync` — 会话控制同步（开始/停止/审批）
- `agent-runtime:sync` — Agent 运行时状态同步（工具调用、任务变更）
- `agent:session-visibility` — 会话可见性跟踪

同步目标选择：
- 同一会话的可见窗口 + 独立会话窗口
- 全局同步则覆盖主窗口 + 所有独立窗口
