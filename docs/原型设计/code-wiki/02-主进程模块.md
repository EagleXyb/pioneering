# 02 - 主进程模块

主进程是 OpenCowork 的系统层，负责：
- 应用启动和生命周期管理
- 窗口管理（主窗口、SSH 窗口、独立会话窗口）
- 数据库访问
- IPC 处理器注册
- 渠道管理（飞书/钉钉等）
- MCP 客户端管理
- Cron 定时任务调度
- WebDAV 同步
- SSH 连接管理
- 浏览器指纹模拟

### 单实例锁

OpenCowork 只允许一个实例运行：
- 如果获取单实例锁失败，直接退出已存在实例
- 第二个实例启动时触发 `second-instance` 事件，显示已有窗口

### 窗口管理

| 窗口类型 | 用途 |
|----------|------|
| 主窗口 | 默认应用窗口，显示聊天界面 |
| SSH 窗口 | 独立的 SSH 终端窗口 |
| 独立会话窗口 | 分离出的会话，可在多个显示器独立查看 |

主窗口默认尺寸：1280×800，最小 900×600。

支持缩放快捷键：Ctrl/Cmd + Plus/Minus/0，支持触摸板捏合缩放。缩放范围 0.75~2.0。

### IPC 注册模式

所有 IPC 处理器都分离到单独文件，在入口集中注册：

```typescript
// 每个处理器定义 registerXxxHandlers() 函数
// 入口点导入并调用
import { registerFsHandlers } from './ipc/fs-handlers'
registerFsHandlers()
```

二进制 MessagePack 处理器注册模式：

```typescript
function registerMessagePackHandler<TArgs>(
  channel: string,
  handler: (args: TArgs, event: IpcMainEvent) => unknown
): void {
  ipcMain.handle(toMessagePackChannel(channel), async (_event, bytes: Uint8Array) => {
    const args = decodeMessagePackPayload<TArgs>(bytes)
    return encodeMessagePackPayload(handler(args, _event))
  })
}
```

### 关闭顺序

1. 停止所有渠道 `channelManager.stopAll()`
2. 断开所有 MCP 服务器 `mcpManager.disconnectAll()`
3. 杀死所有托管进程 `killAllManagedProcesses()`
4. 杀死所有终端会话 `killAllTerminalSessions()`
5. 关闭所有 SSH 会话 `closeAllSshSessions()`
6. 取消所有 Cron 任务 `cancelAllJobs()`
7. 停止 Native Worker `stopNativeWorker()`
8. 停止 Sidecar `getSidecarManager().stop()`
9. 关闭数据库 `closeDb()`
10. macOS 保留实例，其他平台退出应用

### 增量 Schema 模式

OpenCowork 使用"确保列存在"模式：

```typescript
function ensureColumn(db: Database, table: string, column: string, type: string): void {
  // PRAGMA table_info 获取列信息
  // 如果列不存在，执行 ALTER TABLE ADD COLUMN
  // 如果已存在，不做操作
}
```

特点：
- 无需迁移文件
- 向前兼容，不删除旧列
- 应用启动时自动检查并添加新列
- 永远不会丢失数据

### 通信模式

数据库操作主要通过 Native Worker 执行：

- Electron 主进程启动 Native Worker
- Native Worker (.NET) 直接操作 SQLite 文件
-  Electron 通过 Named Pipe 发送请求 → Native Worker 执行 → 返回结果

## MCP 客户端 (`src/main/mcp/`)

### `McpClientWrapper`

封装单个 MCP 服务器连接：

- 支持三种传输类型：
  1. **stdio** — 本地子进程标准输入输出
  2. **SSE** — 基于 HTTP 的服务器发送事件
  3. **streamable-http** — 可流式 HTTP（最新 MCP 标准）
- 自动回退机制 — 一种传输失败自动尝试下一种
- 连接状态管理、工具列表缓存

### `McpManager`

多服务器注册表：

- 保存多个已配置 MCP 服务器
- 自动连接到启用的服务器
- 工具合并暴露给 Agent
- 连接状态管理

文件：
- `mcp-types.ts` — 类型定义
- `mcp-client.ts` — 客户端封装
- `mcp-manager.ts` — 多服务器管理

## Cron 调度器 (`src/main/cron/`)

### 三种调度模式

| 模式 | 语法 | 示例 |
|------|------|------|
| at | `at YYYY-MM-DD HH:mm` | 一次性定时任务 |
| every | `every X minutes/hours/days` | 周期性任务 |
| cron |标准 cron 表达式 | 复杂定时 |

### 并发控制

- `maxConcurrentRuns` 默认为 2
- 超过并发限制的任务会被跳过
- `markRunning(jobId)` — 标记任务开始，检查并发
- `markFinished(jobId)` — 标记任务完成

### 后台 Agent 运行时

`cron-agent-background.ts` 在后台运行 Agent：

- 会话上下文可用（可选）
- 支持多种投递方式：notify / 会话 / 渠道
- 10 个后台可用工具
- 结果摘要记录到 Cron 运行历史

## 目标管理 (`src/main/goals/`)

### `GoalRuntimeService`

目标生命周期状态机：

- 运行 ID 跟踪
- Token 预算跟踪 (`token_budget` - `tokens_used`)
- 阻塞检测 — 如果相同工具失败超过阈值，触发预算提示
- 状态变更通过 `goal-sync.ts` 广播到渲染器

文件：
- `goal-runtime.ts` — 运行时服务
- `goal-sync.ts` — 事件同步
- 数据库：`goals-dao.ts`

## WebDAV 同步 (`src/main/sync/`)

### `SyncEngine`

三路合并同步：

| 模式 | 操作 |
|------|------|
| push | 本地 → 服务器 |
| pull | 服务器 → 本地 |
| twoway | 双向合并 |

冲突检测：
- 比较文件修改时间
- 两边都修改 → 标记冲突
- 一边修改 → 同步到另一边

文件：
- `sync-engine.ts` — 同步引擎
- `sync-config.ts` — 配置
- `webdav-provider.ts` — WebDAV 客户端
