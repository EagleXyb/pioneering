# 09 - 开发指南

## 前置要求

| 依赖 | 最低版本 | 说明 |
|------|---------|------|
| Node.js | ≥ 18 | JavaScript 运行时 |
| npm | ≥ 9 | 包管理器 |
| Python | ≥ 3 | 部分原生模块构建需要 |
| .NET SDK | 10.0 | Native Worker 开发（可选） |
| Git | — | 版本控制 |

### Windows 额外要求

- Windows 10/11 x64 或 arm64
- Visual Studio 2022 Build Tools（含 C++ 编译器）
- Git for Windows

### macOS 额外要求

- macOS 13+
- Xcode 命令行工具

### Linux 额外要求

- GCC / Clang
- libxtst-dev（robotjs 依赖）

## 快速开始

### 1. 克隆仓库

```bash
git clone https://github.com/OpenCowork/OpenCowork.git
cd OpenCowork
```

### 2. 安装依赖

```bash
npm install
```

### 3. 重建原生模块

```bash
npm run postinstall
```

此步骤会编译 `better-sqlite3`、`robotjs`、`ssh2`、`node-pty` 等原生模块以匹配 Electron 版本。

### 4. 启动开发模式

```bash
npm run dev
```

启动 Electron + Vite 开发服务器，含热重载。

## 关键命令

| 命令 | 用途 |
|------|------|
| `npm run dev` | 启动开发模式（Electron + Vite 热重载） |

| `npm run build:win` | 构建 Windows 安装包 |
| `npm run build:mac` | 构建 macOS .dmg/.zip |
| `npm run build:linux` | 构建 Linux .AppImage/.deb |
| `npm run lint` | ESLint 代码检查（含缓存） |
| `npm run typecheck` | TypeScript 编译检查 |
| `npm run format` | Prettier 格式化 |
| `npm run postinstall` | 重建 Electron 原生模块 |

### 类型检查

```bash
npm run typecheck
```

这会同时检查 `tsconfig.node.json`（主进程）和 `tsconfig.web.json`（渲染进程）的编译。

### 生产构建

```bash
npm run build        # 类型检查 + Vite 构建
npm run build:win    # Windows 安装包
npm run build:mac    # macOS 安装包
npm run build:linux  # Linux 安装包
```

## 编码规范

### 格式化

项目使用 Prettier 强制执行统一格式：

| 规则 | 值 |
|------|-----|
| 引号 | 单引号（single quotes）|
| 分号 | 无（no semicolons）|
| 行宽 | 100 列 |
| 行尾 | LF |
| 尾逗号 | 无（no trailing commas）|
| 缩进 | 2 空格 |

### 命名约定

| 规则 | 约定 | 示例 |
|------|------|------|
| React 组件 | PascalCase | `Layout.tsx` |
| Store/Helper 文件 | kebab-case | `chat-store.ts` |
| 路径别名 | `@renderer/*` | `@renderer/*` → `src/renderer/src/*` |
| i18n 键 | t('key') | `t('settings.title', { defaultValue: 'Settings' })` |

### i18n 规则

- 永远不要在 UI 中硬编码中文文本
- 使用 `t('key', { defaultValue: 'English text' })` 格式
- i18n JSON 文件在 `src/renderer/src/locales/` 目录

### 注释规范

- 在需要解释意图、不变量、边界条件或非显式行为的地方添加注释
- 不要用注释重复代码本身

## TypeScript 配置

项目使用两个 TypeScript 配置文件：

| 文件 | 用途 |
|------|------|
| `tsconfig.node.json` | 主进程 + Preload 层 |
| `tsconfig.web.json` | 渲染进程 |

关键配置点：

- `strict: true` — 启用所有严格类型检查
- `noUncheckedIndexedAccess: true` — 防止未检查的索引访问
- `noUnusedLocals: true` — 禁止未使用的局部变量
- `paths` — `@renderer/*` 和 `@shared/*` 路径别名

## 安全指南

### IPC 安全

- 所有渲染进程到主进程的通信必须通过类型化的 IPC 通道
- 绝不直接将 Node.js API 暴露给渲染进程
- Preload 层使用 `contextBridge` 暴露最小化 API

### contextBridge 隔离

- `contextIsolation: true` 确保渲染进程无法访问 Node.js
- `nodeIntegration: false` 禁止渲染进程加载 Node.js 模块
- 自定义 API 通过 `contextBridge.exposeInMainWorld()` 注册

### 凭据安全

- API 密钥存储在 `~/.open-cowork/.env`
- 敏感配置通过 `secure-key-store.ts` 加密处理
- 绝不提交 `.env` 文件

### 原生模块

- `better-sqlite3` — SQLite 引擎
- `robotjs` — 桌面自动化
- `ssh2` — SSH 连接
- `node-pty` — 虚拟终端

以上模块需要 Electron 兼容构建，依赖变更后运行 `npm run postinstall`。

## 常见开发任务

### 添加新工具

1. 在 `src/renderer/src/lib/tools/` 创建工具文件
2. 在 `src/renderer/src/lib/tools/index.ts` 注册
3. 实现 `ToolDefinition` 接口（name、description、inputSchema、handler）
4. 如果需要审批机制，设置 `requiresApproval: true`

### 添加新模式

1. 在 `src/renderer/src/lib/prompts/` 添加模式提示词加载
2. 在系统提示词构建器中注册新模式
3. 在 `session-runtime-router.ts` 添加路由逻辑

### 添加 IPC 处理器

1. 在 `src/main/ipc/` 创建处理器文件
2. 定义 `registerXxxHandlers()` 函数
3. 在 `src/main/index.ts` 导入并调用
4. 在 Preload 层添加（如需要）

### 添加数据库表

1. 在 DAO 中使用 `ensureColumn` 模式添加列
2. 新增 DAO 文件则注册到数据库初始化流程
3. 在 Native Worker 的 Db 模块中添加对应操作
