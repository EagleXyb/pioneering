## 1. 产品目标

基于用户研究、竞品分析和数据验证，设定三个清晰、正交的产品目标：

| 目标 | 定义 | 衡量标准 |
|------|------|----------|
| **G1：方向聚焦** | 帮助"想创业但不知道做什么"的用户，从迷茫到清晰的创业方向，并完成初步验证 | M3留存率 > 40%；方向锁定完成率 > 60% |
| **G2：情绪破局** | 打破"兴奋→困难→搁置→再想"的情绪死循环，让用户在创业探索中持续获得正向反馈 | 单用户日均对话轮次 > 5轮；情绪正向转化率 > 50% |
| **G3：知识资产沉淀** | 将用户的探索过程转化为可复用的个人知识资产（创意库/思维模型/知识图谱），越用越懂用户 | 创意库使用率 > 30%；知识图谱节点数月均增长 > 15% |

**三目标正交性说明**：
- G1 解决"做什么"——功能价值层
- G2 解决"敢不敢"——情绪价值层
- G3 解决"留下什么"——资产价值层
- 三者独立递进，互不替代，且协同形成飞轮：聚焦→自信→沉淀→更聚焦

## 2. 用户故事

### US-1：李然——困在格子间的梦想家

> "我知道我想做跟内容相关的事，但内容创业有100个方向，我不知道该选哪个，每次研究完更迷茫了。"

**场景**：李然下班后打开创路 Agent，说"我想做内容创业，但不知道选哪个细分方向"。Agent 不是直接给他答案，而是先问他："你过去3年最投入的3件事是什么？"——从李然的记忆库中，Agent 已经知道他做过社群运营、写过10万字笔记、帮朋友策划过线下活动。Agent 基于这些，帮他收敛到"知识型IP孵化"方向，并生成一个7天快速验证计划。李然第一次觉得"方向清晰了"。

### US-2：王芳——被裁后才醒悟的转身者

> "我做了15年传统零售管理，现在说行业不行了，我还能干什么？我连AI都不会用。"

**场景**：王芳被裁后焦虑失眠，抱着试试的心态打开创路 Agent。她不会提问，只输入了"我被裁了，不知道能做什么"。Agent 没有甩给她一堆链接，而是用温和的语气说："先不急，咱们一起看看你这15年积累了哪些别人拿不走的能力。"Agent 引导她一步步梳理，最终发现她的供应链管理和团队协调经验可以迁移到"社区团购运营顾问"方向。王芳第一次感到"我还有用"。

### US-3：陈浩——满腔热血的毕业生

> "我有5个创业想法，每个都觉得能做，但哪个都没开始，因为我不知道先验证哪个。"

**场景**：陈浩把5个想法一股脑输入创路 Agent，Agent 没有逐个分析，而是先用"机会成本矩阵"帮他评估每个想法的"热情度×可行性×市场空间"，快速排序后建议他先验证排名最高的那个。然后 Agent 为他生成一个"周末MVP验证清单"，只需要2天就能验证核心假设。陈浩终于迈出了第一步。

### US-4：跨画像共性场景——情绪低谷时

> "我试了一下，好像行不通，我是不是又选错了……"

**场景**：用户在验证阶段遇到挫折，Agent 检测到情绪变化（对话语气、活跃度下降），主动发起对话："我注意到你最近验证的进展不太顺利，这很正常——咱们一起看看是哪个假设需要调整？"Agent 从该用户的知识图谱中调出他之前的方向选择逻辑，帮他做"假设修正"而非"推倒重来"，避免用户陷入"重新来过"的焦虑。

### US-5：跨画像共性场景——知识资产复用

> "我之前研究过社区团购的方向，现在想看直播带货，这两个能不能结合？"

**场景**：用户提出新方向时，Agent 自动从知识图谱中检索相关节点，展示"你之前在社区团购方向积累的供应链认知、用户运营经验，可以直接迁移到直播带货中"，并在创意库中生成"方向关联图"。用户发现过去的探索不是浪费，而是资产。

## 3. 用户研究洞察（来自瑞思的核心发现）

### 3.1 核心洞察摘要

| # | 洞察 | 对产品设计的影响 |
|---|------|-----------------|
| 1 | "想创业但不知道做什么"的本质是**选择瘫痪**，而非没有想法 | 产品必须提供"收敛"机制，而非"发散"更多选项 |
| 2 | 创业方向选择的焦虑，底层是**身份认同**危机 | 产品需要帮助用户"认识自己"，而非仅"分析市场" |
| 3 | 信息越多越迷茫——"创业知识消费"是一种**拖延行为** | 产品不应堆砌内容，而应提供"刚好够用"的信息 |
| 4 | 恐惧不是怕失败，而是怕"选错"——**机会成本焦虑** | 产品需要降低"试错成本"，让验证快速且低成本 |
| 5 | 他们需要的是**"创业搭子"**，不是"创业导师" | 产品人格应该是平级伙伴，而非居高临下的专家 |
| 6 | 被动创业者的痛点强度是主动创业者的**3倍**，但付费决策更谨慎 | 需要更强的信任建设机制和免费价值前置 |
| 7 | "创业"这个词本身就在制造焦虑——他们真正想要的是"**做自己的事**" | 产品语言应避免"创业"标签，用"探索方向""做自己的事"替代 |

### 3.2 真需求 vs 伪需求

- **真需求（Need）**：方向聚焦 + 快速验证 + 情绪陪伴
- **Want→Need 转化中**：创意库/知识图谱（长期使用后变为 Need）
- **伪需求**：更多内容/更多工具/更多选择

### 3.3 用户旅程关键卡点

70%以上用户卡在"迷茫期→焦虑期→停滞期"之间，形成死循环：
```
想 → 查 → 迷茫 → 焦虑 → 搁置 → 再想（循环）
```
**产品的核心使命：打破这个循环。**

### 3.4 情绪地图关键发现

- **恐惧是暗线**：怕选错方向、怕错过窗口期
- **愉悦→不爽的死循环**：新点子→兴奋→发现困难→不爽→搁置→循环
- 产品必须在"兴奋→困难"的转折点介入，将"不爽"转化为"调整假设"

## 4. 竞品对比（来自竞析的核心发现）

### 4.1 七大竞品定位

| 竞品 | 类别 | 核心能力 | 关键短板 |
|------|------|---------|---------|
| 创业邦 | 创业社区/平台 | 内容+社区+Bangchat AI | AI深度不足，偏资讯 |
| Kimi | AI对话/助手 | 长文本理解，上下文长 | 无创业领域专精，无个性化记忆 |
| 豆包 | AI对话/助手 | 全能型，生态广 | 创业场景无差异化，被动对话 |
| Strategyzer | 商业计划/工具 | 商业模式画布方法论 | 方法论与AI割裂，无对话引导 |
| IdeaBuddy | 商业计划/工具 | AI驱动商业规划 | 偏"已有想法"的人，不帮"不知道做什么"的人 |
| Indie Hackers | 创业社区/平台 | 同伴社区，真实案例 | 社区依赖，无1对1引导，情绪支持非结构化 |
| 混沌学园 | 创新方法论/培训 | 创新教育体系 | 重培训轻实践，方法论与AI脱节 |

### 4.2 五大差异化机会

1. **"创业思维伙伴"而非"创业问答机器"**——主动引导，而非被动回答
2. **"个人创业操作系统"**——知识资产沉淀，而非用完即走
3. **情绪陪伴**——"创业路上不孤独"，刻意设计情绪识别与支持
4. **"从0到1"的结构化引导**——帮"还没有想法"的人，而非"已有想法"的人
5. **中国本土化创业知识体系**——适配中国创业生态的方法论与案例

### 4.3 Battle Card

> **Unlike** 通用AI助手只能被动回答创业问题，**我们主动引导**你从"不知道做什么"到"清晰创业方案"，并**沉淀你专属的创意知识资产**——越用越懂你，你是它唯一的主人。

### 4.4 SWOT 关键点

- **优势**：三层价值融合、AI Agent 主动性、个性化记忆、知识资产化
- **劣势**：冷启动挑战（无初始数据）、信任门槛（用户对AI建议的信任）、场景边界（创业方向聚焦 vs 全流程陪跑）
- **机会**：AI Agent 技术成熟窗口期、创业焦虑市场巨大且未被专用产品覆盖、通用AI在垂直场景的空白
- **威胁**：通用AI降维打击（Kimi/豆包加强创业能力）、社区平台AI化（创业邦加强AI）、用户付费意愿低

## 7. 产品架构设计

### 7.1 产品整体架构图

产品采用**五层架构**，自上而下为：

```
┌─────────────────────────────────────────────────────────────┐
│                     交互层 (Interaction Layer)                │
│   对话界面 │ 方向看板 │ 创意库 │ 知识图谱 │ 验证进度          │
├─────────────────────────────────────────────────────────────┤
│                    体验层 (Experience Layer)                  │
│   情绪引擎 │ 主动引导 │ 个性化语气 │ 渐进式信息披露            │
├─────────────────────────────────────────────────────────────┤
│                    能力层 (Capability Layer)                  │
│  对话引擎 │ 方向聚焦 │ 方法论引擎 │ 验证系统 │ 知识资产管理     │
├─────────────────────────────────────────────────────────────┤
│                    智能层 (Intelligence Layer)                │
│   个性化记忆 │ 意图识别 │ 情绪识别 │ 知识推理 │ 方向推荐        │
├─────────────────────────────────────────────────────────────┤
│                    数据层 (Data Layer)                        │
│   用户数据 │ 对话数据 │ 知识图谱 │ 创意库 │ 方法论库           │
└─────────────────────────────────────────────────────────────┘
```

**分层设计原则**：
- **交互层**面向多端适配（Web/小程序/App），保持轻量
- **体验层**封装所有"用户感知到但不可见"的智能，如情绪响应、主动推送
- **能力层**是产品核心能力的编排层，每个能力模块可独立迭代
- **智能层**是AI能力的抽象层，屏蔽底层模型差异，支持模型替换
- **数据层**统一管理所有持久化数据，向上提供标准化数据服务

### 7.2 核心模块设计

#### 7.2.1 智能对话引擎（创业领域专精）

**功能定义**：
创业方向选择场景的专精对话引擎，能进行深度引导式对话，而非简单的问答。核心能力包括：理解用户模糊表述背后的真实意图、逐步引导用户从发散到收敛、在对话中自然嵌入方法论框架。

**输入**：
- 用户自然语言输入（文本为主）
- 当前对话上下文
- 用户画像与记忆数据
- 当前情绪状态

**输出**：
- 引导式回复（非直接答案）
- 对话中提取的结构化信息（方向、偏好、约束、能力）
- 情绪响应策略

**关键逻辑**：
1. **意图路由**：识别用户当前处于"迷茫/探索/聚焦/验证/复盘"哪个阶段，切换对话策略
2. **渐进式引导**：不直接给答案，而是通过提问引导用户自己发现——Socratic 方法
3. **领域知识注入**：对话中自然嵌入创业方法论（如"你说的这个，其实可以用精益创业的MVP思路快速验证"），而非生硬引用
4. **收敛机制**：当用户发散超过3个方向时，自动触发"方向评估矩阵"帮助收敛
5. **防拖延检测**：识别"信息消费型"对话（只问不行动），引导转向行动

**Prompt 策略**：
- System Prompt 定义 Agent 人格："你是用户的创业搭子，平级伙伴，不是导师"
- 场景 Prompt 模板库：针对不同阶段预设对话策略
- Few-shot 示例库：优质引导对话示例

---

#### 7.2.2 主动引导系统（从被动到主动）

**功能定义**：
Agent 不只是"有问才答"，而是像真正的搭子一样，在关键时刻主动介入。包括：停滞时主动提醒、验证受阻时主动调整、方向偏移时主动拉回、定期复盘主动发起。

**输入**：
- 用户行为数据（最近活跃度、对话频率、验证进度）
- 时间触发器（停滞N天、验证计划到期、周期复盘时间）
- 情绪变化信号

**输出**：
- 主动推送消息（非侵入式，语气自然）
- 引导对话开场白
- 阶段性复盘报告

**关键逻辑**：
1. **停滞检测**：用户3天未登录或7天未推进验证，触发轻度提醒（"最近怎么样？方向探索有新想法吗？"）
2. **验证拦截**：用户在验证阶段连续受挫时，主动发起"假设修正"对话
3. **方向偏移预警**：用户频繁切换方向时，主动提示"我注意到你最近在探索多个方向，要不要先停下来看看它们之间的关联？"
4. **周期复盘**：每周/每月自动生成探索复盘，帮用户看到进展
5. **节奏控制**：防止用户"过度消耗"，适时建议休息

**推送策略**：
- 频率上限：每周最多2次主动推送
- 语气原则：朋友式关心，非任务式催促
- 个性化：基于用户画像调整语气（李然用理性语言，王芳用温暖语言，陈浩用鼓励语言）

#### 7.2.3 个性化记忆系统（越用越懂用户）

**功能定义**：
让 Agent 具备"记忆力"，跨会话记住用户的偏好、能力、探索历史、情绪模式，使对话越来越个性化。这是与通用AI助手的核心差异点。

**输入**：
- 每轮对话内容
- 用户行为数据
- 用户主动更新的个人信息
- 系统推断的用户特征

**输出**：
- 用户画像（动态更新）
- 对话中的个性化引用（"你之前说过你擅长社群运营，这个方向正好可以用上"）
- 个性化推荐（方向、方法论、验证方式）

**关键逻辑**：
1. **三层记忆架构**：
   - **短期记忆**：当前会话上下文（最近10轮对话）
   - **中期记忆**：近期探索摘要（最近30天的方向探索、验证进展）
   - **长期记忆**：用户核心画像（能力、偏好、价值观、思维模式）
2. **记忆提取**：每轮对话结束后，自动提取关键信息存入对应记忆层
3. **记忆召回**：对话时根据当前话题，召回相关记忆并自然引用
4. **记忆衰减**：中期记忆有衰减机制，30天以上未提及的信息降权
5. **记忆整合**：定期将中期记忆中高频出现的信息升级为长期记忆

**数据结构**：
```
UserProfile {
  basic_info: { name, age, background, skills[] }
  preferences: { communication_style, decision_mode, risk_tolerance }
  capabilities: { hard_skills[], soft_skills[], experience[] }
  exploration_history: { directions[], validations[], outcomes[] }
  emotional_patterns: { stress_triggers, motivation_drivers }
  values: { identity_keywords[], life_priorities[] }
}
```

#### 7.2.4 创新方法论引擎

**功能定义**：
将经典创新与创业方法论（设计思维、精益创业、商业模式画布、点线面体等）结构化嵌入产品，在对话中自然引导用户使用方法论，而非要求用户先学方法论。

**输入**：
- 用户当前所处阶段
- 对话中识别到的方法论适用信号
- 用户的方法论使用偏好

**输出**：
- 方法论框架推荐
- 方法论引导对话
- 结构化工具（画布、矩阵等）

**关键逻辑**：
1. **方法论库**：
   - **迷茫期**：设计思维（共情→定义→构思）——帮用户"发现"自己
   - **聚焦期**：点线面体（点→线→面→体的战略选择）——帮用户"判断"方向层级
   - **验证期**：精益创业（假设→MVP→验证→迭代）——帮用户"快速试错"
   - **规划期**：商业模式画布——帮用户"结构化方案"
2. **自然嵌入**：不要求用户"先选方法论"，而是 Agent 在对话中识别到适用场景时自然引入（"你说的这个，有个方法可以帮你看清楚——"）
3. **渐进深化**：首次使用只展示核心框架，后续使用逐步展开细节
4. **方法论推荐逻辑**：基于用户画像和当前阶段自动选择最适合的方法论

#### 7.2.5 知识资产系统

**功能定义**：
将用户的探索过程转化为可复用的个人知识资产，包括创意库、思维模型库和知识图谱。这是产品的"资产价值"层，也是长期留存的核心壁垒。

**子模块**：

**A. 创意库**
- **功能**：用户在对话中产生的所有想法、方向、洞察，一键保存、分类、检索
- **输入**：对话中 Agent 标记的关键创意、用户手动保存的内容
- **输出**：创意列表、创意详情、创意关联图
- **关键逻辑**：
  - Agent 自动标记对话中的"创意点"并建议保存
  - 支持标签分类（方向类/能力类/资源类/灵感类）
  - 创意去重和关联（相似创意合并提示）

**B. 思维模型库**
- **功能**：沉淀用户个人的思维模式，如决策偏好、风险态度、创新风格
- **输入**：长期对话中推断的思维特征
- **输出**：个人思维画像、思维模型卡片
- **关键逻辑**：
  - 从对话中提取思维特征（如"你倾向于先看市场再看自己"→ 市场导向型思维）
  - 思维模型可视化（思维风格卡片）
  - 跨方向复用建议

**C. 知识图谱**
- **功能**：将用户的探索历史构建为个人知识图谱，展示方向、能力、资源之间的关联
- **输入**：创意库数据、对话提取的实体和关系
- **输出**：图谱可视化、关联推荐、方向迁移建议
- **关键逻辑**：
  - 实体：方向、能力、资源、行业、方法论
  - 关系：方向-需要-能力、方向-属于-行业、能力-迁移到-方向
  - 当用户探索新方向时，自动展示"已有资产可迁移"
  - 图谱节点数 > 20 时开启图谱可视化

#### 7.2.6 情绪识别与陪伴系统

**功能定义**：
识别用户在创业探索过程中的情绪变化，在关键情绪转折点提供陪伴和支持，打破"兴奋→困难→搁置"的死循环。

**输入**：
- 对话文本的情感信号
- 用户行为数据（活跃度变化、对话节奏变化）
- 历史情绪模式

**输出**：
- 情绪标签（焦虑/兴奋/挫败/平静/期待）
- 情绪响应策略
- 主动陪伴行为

**关键逻辑**：
1. **情绪识别**：
   - 文本情感分析（基于对话内容）
   - 行为信号推断（如：突然减少对话 = 可能受挫；连续深夜使用 = 可能焦虑）
   - 综合情绪评分（0-100，<30 为低落，>70 为兴奋）
2. **关键转折点介入**：
   - **兴奋→困难转折**：当检测到用户从兴奋转向挫败时，主动说"遇到困难很正常，咱们一起看看是哪个假设需要调整"
   - **持续低落**：情绪评分连续3天 < 30，主动发起鼓励性对话
   - **突破兴奋**：情绪评分突增，强化正向反馈"看来你有新发现了！"
3. **陪伴策略**：
   - 不说"不要焦虑"（否定情绪），而是"焦虑说明你在认真思考"（接纳情绪）
   - 不说"加油"（空洞鼓励），而是"你已经在X方面迈出了第一步"（具体肯定）
   - 不说"再试试"（施压），而是"我们换个角度看看"（降低压力）

#### 7.2.7 方向聚焦与验证系统

**功能定义**：
帮助用户从多个模糊想法收敛到1-2个具体方向，并为每个方向生成快速验证计划。这是产品解决"选择瘫痪"的核心模块。

**输入**：
- 用户的想法/方向列表
- 用户能力评估（来自记忆系统）
- 市场可行性的轻量评估
- 用户的风险偏好

**输出**：
- 方向评估矩阵
- 聚焦后的1-2个方向
- 每个方向的验证计划

**关键逻辑**：
1. **方向收敛流程**：
   - Step 1：收集——让用户列出所有想法（不评判）
   - Step 2：映射——将每个想法映射到"热情度×能力匹配度×市场空间"三维矩阵
   - Step 3：排序——基于矩阵得分排序，展示 Top 3
   - Step 4：决策——引导用户从 Top 3 中选择 1-2 个（用"遗憾最小化框架"辅助决策）
   - Step 5：承诺——锁定方向，设定验证目标
2. **快速验证计划生成**：
   - 识别3-5个核心假设
   - 为每个假设设计最低成本验证方法
   - 设定7天验证周期
   - 定义验证通过/失败的判断标准
3. **验证过程追踪**：
   - 用户每日更新验证进展
   - Agent 跟踪假设验证状态
   - 验证失败时引导"假设修正"而非"推倒重来"
4. **防切换机制**：
   - 用户在验证未完成就想换方向时，提示"你当前方向的验证还没完成，换方向的机会成本是X"
   - 不是阻止切换，而是让用户"有意识地切换"

### 7.3 数据架构

#### 7.3.1 数据分类与组织

```
用户数据 (User Data)
├── 基础信息 (profile): name, age, background, occupation
├── 偏好设置 (preferences): communication_style, notification_frequency
├── 能力标签 (capabilities): hard_skills[], soft_skills[], experience[]
├── 价值观 (values): identity_keywords[], life_priorities[]
└── 订阅状态 (subscription): plan_type, start_date, renewal_date

对话数据 (Conversation Data)
├── 会话元数据 (session): session_id, start_time, end_time, stage
├── 消息记录 (messages): role, content, timestamp, emotion_tag
├── 结构化提取 (extractions): ideas[], directions[], capabilities[], constraints[]
└── 对话摘要 (summaries): key_insights, action_items, next_steps

知识图谱数据 (Knowledge Graph Data)
├── 实体 (entities): {id, type, name, properties}
│   ├── 类型: Direction, Capability, Resource, Industry, Methodology
├── 关系 (relations): {source_id, target_id, relation_type, weight}
│   ├── 关系类型: requires, belongs_to, transfers_to, relates_to
└── 图谱快照 (snapshots): timestamp, entity_count, relation_count

创意库数据 (Idea Library Data)
├── 创意 (ideas): {id, title, description, tags[], source_session_id}
├── 标签体系 (tags): {id, name, category, usage_count}
└── 关联 (associations): {idea_id_1, idea_id_2, similarity_score}

方法论库数据 (Methodology Data)
├── 方法论 (methodologies): {id, name, description, stages[], applicable_phases[]}
├── 应用记录 (applications): {methodology_id, user_id, session_id, effectiveness_score}
└── 模板 (templates): {methodology_id, stage, prompt_template, tool_template}

情绪数据 (Emotion Data)
├── 情绪记录 (emotion_logs): {user_id, timestamp, emotion_type, score, trigger}
├── 情绪模式 (emotion_patterns): {user_id, pattern_type, pattern_data}
└── 陪伴记录 (companion_logs): {user_id, timestamp, trigger, action, outcome}
```

#### 7.3.2 数据流转

```
用户输入 → 对话引擎 → 结构化提取 → 并行写入：
  ├── 用户画像更新（能力标签、偏好调整）
  ├── 创意库（新创意保存）
  ├── 知识图谱（新实体/关系）
  └── 情绪记录（情绪标签、分数）

读取路径：
  对话引擎 ← 用户画像 + 短期记忆 + 情绪状态
  方向推荐 ← 知识图谱 + 能力标签 + 方法论库
  主动引导 ← 行为数据 + 情绪模式 + 验证进度
```

#### 7.3.3 数据隐私与安全

- 所有用户数据加密存储（AES-256）
- 对话数据默认30天归档，用户可自定义保留周期
- 知识图谱和创意库数据归用户所有，支持导出和删除
- 情绪数据仅用于产品内陪伴功能，不共享给第三方
- 符合《个人信息保护法》要求，用户可随时查看、导出、删除个人数据

### 7.5 核心流程设计

#### 流程一：从迷茫到方向聚焦

```
用户进入 → Agent问候（"嗨，最近在想做什么方向？"）
    │
    ├─ 用户有模糊想法 → "说说看，你最感兴趣的是什么？"
    │   │
    │   ├─ 说出1-2个方向 → 进入方向深化
    │   │   └─ Agent引导："这个方向吸引你的核心原因是什么？"
    │   │       └─ 提取：核心动机 → 匹配能力 → 评估可行性
    │   │
    │   └─ 说出3+个方向 → 触发方向收敛
    │       └─ Agent："你说的这几个方向都挺有意思，我们用一个框架帮你理一理——"
    │           └─ 展示"热情×能力×市场"评估矩阵
    │               └─ 引导选择Top 1-2 → 锁定方向
    │
    ├─ 用户完全不知道 → "没关系，咱们从你自己开始——"
    │   └─ 设计思维共情阶段：
    │       1. "你过去3年最投入的3件事是什么？"
    │       2. "别人最常找你帮忙的事是什么？"
    │       3. "如果不用考虑钱，你最想花时间做什么？"
    │       └─ 从回答中提取：能力标签 + 兴趣方向 + 价值观
    │           └─ 生成3-5个候选方向 → 进入方向收敛
    │
    └─ 用户表达焦虑 → 情绪陪伴优先
        └─ "我能感觉到你现在挺焦虑的，这很正常——先不急着找答案，我们慢慢来"
            └─ 情绪稳定后 → 进入上述任一路径

方向锁定后 → 保存至创意库 + 知识图谱 + 生成方向卡片
    └─ 进入"快速验证"流程
```

#### 流程二：快速验证循环

```
方向锁定 → Agent："这个方向听起来不错！我们来快速验证一下——"
    │
    ├─ Step 1：识别核心假设
    │   └─ Agent："如果这个方向能成，最关键的3个前提是什么？"
    │       └─ 帮助用户明确假设（如"目标用户真的有这个痛点""我能触达这些用户"）
    │
    ├─ Step 2：设计验证方法
    │   └─ Agent自动生成验证计划：
    │       ├── 假设1：验证方法 + 预期结果 + 时间
    │       ├── 假设2：验证方法 + 预期结果 + 时间
    │       └── 假设3：验证方法 + 预期结果 + 时间
    │       └─ 7天为一个验证周期
    │
    ├─ Step 3：执行验证
    │   └─ 用户每日更新进展（简单打卡 + 简短描述）
    │       └─ Agent每日跟进："今天验证得怎么样？有什么新发现？"
    │
    ├─ Step 4：验证结果评估
    │   │
    │   ├─ 假设验证通过 → Agent："太好了！这个假设站住了，我们继续验证下一个"
    │   │
    │   ├─ 假设验证失败 → Agent引导"假设修正"而非"推倒重来"
    │   │   └─ "这个假设不成立没关系，看看是哪个变量需要调整——"
    │   │       └─ 修正假设 → 重新验证
    │   │
    │   └─ 用户想放弃 → 情绪介入
    │       └─ "我理解你想换方向，在你做决定之前，我们来看看已经验证了什么——"
    │           └─ 展示已验证的成果（避免用户觉得"全白费了"）
    │               └─ 如果确实需要换 → 有意识切换（记录切换原因）
    │
    └─ Step 5：验证周期复盘
        └─ Agent自动生成7天验证报告：
            ├── 哪些假设通过/失败
            ├── 关键发现
            ├── 下一步建议
            └─ 情绪状态评估
```

#### 流程三：主动引导介入

```
后台监控（持续运行）
    │
    ├─ 触发器：用户3天未登录
    │   └─ 发送轻度提醒："最近没看到你，方向探索有新想法吗？"
    │       └─ 无回复 → 7天后再发一次（降低频率）
    │       └─ 有回复 → 恢复正常对话
    │
    ├─ 触发器：验证计划到期未更新
    │   └─ 发送验证提醒："你的验证计划已经到期了，结果怎么样？"
    │       └─ 用户说验证受阻 → 引导假设修正
    │       └─ 用户说忘了 → 调整验证计划（降低门槛）
    │
    ├─ 触发器：情绪评分持续低落
    │   └─ 主动发起鼓励对话："我注意到你最近状态不太好……"
    │       └─ 不施压、不催促、只陪伴
    │
    ├─ 触发器：方向频繁切换
    │   └─ 主动提示："我注意到你最近在探索多个方向，要不要先看看它们的关联？"
    │       └─ 展示知识图谱中的方向关联
    │
    └─ 触发器：周期复盘（每周/每月）
        └─ 自动生成探索复盘报告，推送至用户
            ├── 本周/月探索了哪些方向
            ├── 验证了哪些假设
            ├── 积累了哪些能力/知识
            └── 下一步建议
```

## 8. Non-goals（明确不做什么）

| # | 不做什么 | 原因 |
|---|---------|------|
| 1 | **不做创业全流程工具**（注册公司、财务、法务） | 超出"方向聚焦"场景，与已有工具竞争，分散核心价值 |
| 2 | **不做创业内容平台**（课程、文章、资讯） | 用户研究已验证"信息消费是拖延行为"，更多内容是伪需求 |
| 3 | **不做投融资对接** | 场景后移，MVP阶段不应涉及，且信任门槛极高 |
| 4 | **不做通用AI助手** | 91%用户只付一个AI产品，必须与通用AI划清界限，聚焦创业方向场景 |
| 5 | **不做"已有明确方向"的用户** | 这类用户需要的是执行工具，与产品定位不匹配 |
| 6 | **不做社交平台** | 社区功能仅轻度集成，不作为核心功能，避免稀释"1对1搭子"体验 |
| 7 | **不做创业导师/咨询** | 产品人格是"搭子"而非"导师"，不给"权威建议"，只帮用户自己找到答案 |
| 8 | **不做MVP之后的产品**（如App原生开发） | MVP阶段Web+小程序足够，App待验证后启动 |

## 10. 待确认问题

| # | 问题 | 影响范围 | 建议决策方向 |
|---|------|---------|-------------|
| 1 | 产品命名最终确定："创路 Agent"还是"创行 Agent"或其他？ | 品牌、域名、商标 | 建议"创路"——"路"更贴合"搭路"的意象，且有"创路=创业之路"的双关 |
| 2 | MVP阶段支持哪些平台？Web先行还是小程序先行？ | 技术架构、开发优先级 | 建议小程序先行（微信生态触达率高，创业焦虑人群手机使用为主） |
| 3 | LLM选型：国产模型为主还是国际模型为主？ | 成本、合规、能力 | 建议国产模型为主（合规+成本），关键场景用强模型兜底 |
| 4 | 免费版对话次数限制：3次/天还是5次/天？ | 用户转化、体验平衡 | 建议MVP阶段5次/天（给足体验空间），后期根据数据调整 |
| 5 | 情绪识别的隐私边界：用户是否知道我们在分析情绪？ | 合规、信任 | 建议明确告知（设置页说明"我会关注你的状态，在需要时主动关心你"），并提供关闭选项 |
| 6 | 知识图谱的冷启动：新用户无历史数据时如何提供价值？ | 新用户体验 | 建议通过首次引导对话快速构建初始图谱（3-5轮对话即可建立10+节点） |
| 7 | 付费定价最终确认：入门版¥49还是¥68？ | 营收、转化率 | 建议¥68/月（对标李然的300-500元预算下限，且有定价空间做促销） |
| 8 | 社区功能的优先级：P1还是P2？ | 产品节奏、差异化 | 建议 P1 轻度集成（仅匿名分享+反馈），重社区为 P2 |
| 9 | "创业"用词策略：产品内是否完全避免"创业"一词？ | 产品语言、定位 | 建议不完全避免，但优先用"做自己的事""探索方向"等低焦虑表达 |
| 10 | 数据归属与导出：用户是否可以导出全部个人数据？ | 信任建设、合规 | 建议支持一键导出（JSON格式），强化"你的数据你做主" |
