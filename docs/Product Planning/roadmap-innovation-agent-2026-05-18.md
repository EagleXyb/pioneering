## 2. 用户反馈摘要——对路线图规划的关键发现

> 基于瑞思（用户研究）的综合分析，以下为对路线图规划有直接影响的关键发现。

### 2.1 核心洞察与路线图影响

| # | 用户研究洞察 | 对路线图的影响 |
|---|-------------|---------------|
| 1 | "想创业但不知道做什么"的本质是**选择瘫痪**，非没有想法 | MVP必须优先做**方向收敛机制**（P0-02），而非发散式推荐 |
| 2 | 创业方向选择的焦虑，底层是**身份认同**危机 | 首次对话引导需从"认识自己"开始，而非"分析市场"；影响P0-04记忆系统的优先级 |
| 3 | 信息越多越迷茫——"创业知识消费"是**拖延行为** | 路线图中**不设内容平台模块**；信息提供遵循"刚好够用"原则 |
| 4 | 恐惧不是怕失败，而是怕"选错"——**机会成本焦虑** | 快速验证计划（P0-03）是MVP核心差异化；验证周期必须短（7天）且成本低 |
| 5 | 需要的是**"创业搭子"**，不是"创业导师" | Agent人格设计贯穿所有Phase；语气/措辞需持续优化 |
| 6 | 被动创业者痛点强度是主动创业者的**3倍**，但付费决策更谨慎 | 免费版需给足体验空间（5次/天）；付费转化在Phase 2而非Phase 1 |
| 7 | "创业"一词本身制造焦虑 | 产品语言体系需在Phase 0即定义；所有Prompt模板需审查用词 |

### 2.2 真需求优先级排序（影响需求落地顺序）

1. **方向聚焦**（真Need）→ P0-02, P0-07 最先开发
2. **快速验证**（真Need）→ P0-03 紧随其后
3. **情绪陪伴**（真Need）→ P0-05 贯穿始终
4. **个性化记忆**（真Need）→ P0-04 从Phase 0开始建设
5. **创意库/知识图谱**（Want→Need转化）→ P0-06 MVP基础版，P1-02/P1-06 增长版

### 2.3 用户旅程卡点与路线图应对

| 卡点 | 阶段 | 路线图应对 |
|------|------|-----------|
| 兴奋→困难的情绪转折 | 验证期 | P0-05情绪识别 + P1-04情绪陪伴增强 |
| 70%用户陷入"迷茫→焦虑→搁置"循环 | 全程 | 主动引导系统（P1-01）是破局关键 |
| 新用户冷启动不知道说什么 | 首次使用 | Phase 1 Sprint 1 必须优化首次引导流程 |
| "信息消费型"拖延 | 迷茫期 | 对话引擎需内置"防拖延检测" |

## 3. 竞品动态——对路线图规划的影响

> 基于竞析（竞品分析）的综合发现，以下为对路线图有影响的竞品动态和市场方向。

### 3.1 竞品威胁时间窗

| 竞品 | 当前状态 | 预计进化方向 | 对我们的时间窗 |
|------|---------|-------------|--------------|
| **Kimi** | 长文本强，无垂直场景 | 可能加强场景化能力 | 6-12个月（需在Kimi切入创业场景前建立壁垒） |
| **豆包** | 全能型，生态广 | 可能推垂直场景包 | 6-9个月（字节速度快，需加速MVP验证） |
| **创业邦** | AI深度不足 | Bangchat AI持续迭代 | 12个月（社区+AI组合威胁更大） |
| **Strategyzer** | 方法论强但AI弱 | 可能加强AI对话引导 | 9-12个月（海外产品，本土化是我们的优势） |
| **IdeaBuddy** | AI商业规划 | 可能向下延伸"方向发现" | 12个月（目前只做"已有想法"的人） |

### 3.2 差异化壁垒建设节奏

| 壁垒维度 | 建设时机 | 路线图落点 |
|---------|---------|-----------|
| **创业领域专精对话** | Phase 0-1 | P0-01 对话引擎 + Prompt持续优化 |
| **个性化记忆系统** | Phase 1-2 | P0-04→P1-06 数据飞轮 |
| **情绪陪伴能力** | Phase 1-2 | P0-05→P1-04 深化 |
| **知识资产沉淀** | Phase 2-3 | P0-06→P1-02→P2-01 长期壁垒 |
| **创业方法论嵌入** | Phase 2 | P1-03 差异化内容壁垒 |

### 3.3 市场趋势对路线图的影响

| 趋势 | 影响 | 路线图调整 |
|------|------|-----------|
| AI Agent技术成熟期窗口 | 必须快速验证PMF，建立先发优势 | Phase 1 压缩至8周，加速内测 |
| 91%用户只付一个AI产品 | 必须与通用AI划清界限 | 品牌差异化在Phase 0即启动 |
| 政策鼓励灵活就业/创业 | 市场需求持续增长 | Phase 2 公测时机与政策窗口对齐 |
| 通用AI降维打击风险 | 需要深度>广度的策略 | 聚焦"方向聚焦"场景，不做通用 |

## 5. 迭代计划详细设计

### Phase 0：基础建设（2个Sprint）

---

#### Sprint 0-1：基座搭建（W1-W2）

**Sprint目标**：完成技术架构搭建和LLM Gateway原型，验证核心对话链路可用性。

**具体需求**：
| 需求 | 来源 | 优先级 |
|------|------|--------|
| LLM Gateway原型（支持多模型路由） | 技术基建 | 必须 |
| PostgreSQL + MongoDB数据库Schema | 技术基建 | 必须 |
| CI/CD流水线搭建 | 技术基建 | 必须 |
| 前端项目脚手架（Next.js） | 技术基建 | 必须 |
| 基础对话界面（输入框+消息列表） | P0-07前置 | 必须 |
| System Prompt v1（Agent人格定义） | P0-01前置 | 必须 |

**技术任务**：
- 搭建LLM Gateway：模型路由、降级策略、流式输出
- 数据库设计：用户表、会话表、消息表的Schema定义
- 前端脚手架：Next.js + WebSocket客户端
- DevOps：GitHub Actions + Docker + Staging环境
- Prompt工程：Agent人格System Prompt初版

**验收标准**：
- [ ] LLM Gateway可成功调用至少2个模型（国产+国际各1）
- [ ] 流式输出在前端渲染正常（打字机效果）
- [ ] 数据库Schema通过评审并冻结
- [ ] 基础对话界面可输入文本并收到AI回复

**依赖关系**：
- 前置：LLM选型决策（待确认问题#3）需在Sprint 0-1开始前完成
- 前置：产品命名确定（待确认问题#1）影响品牌资产和Prompt人格

### Phase 1：MVP（4个Sprint）

---

#### Sprint 1-1：核心引擎（W5-W6）

**Sprint目标**：创业领域专精对话引擎v1上线，核心对话流程设计完成，首次引导流程可用。

**具体需求**：
| 编号 | 需求 | 估算 |
|------|------|------|
| P0-01 | 创业领域专精对话引擎v1 | 6人周 |
| P0-07 | 核心对话流程设计 | 2人周 |
| — | 首次引导流程 | 1人周 |

**技术任务**：
- 对话引擎开发：意图路由（迷茫/探索/聚焦/验证/复盘）、渐进式引导逻辑
- 场景Prompt模板完善：覆盖全部5个阶段
- 收敛机制：当用户发散>3个方向时自动触发"方向评估矩阵"
- 防拖延检测：识别"信息消费型"对话，引导转向行动
- 首次引导流程：新用户3步引导（我是谁→我能帮你什么→开始探索）
- Few-shot示例库：20+优质引导对话示例

**验收标准**：
- [ ] 对话引擎可正确识别5个阶段并切换策略，准确率>70%
- [ ] 5轮深度对话用户满意度>70%
- [ ] 首次引导流程3步完成率>80%
- [ ] 防拖延检测在内部测试中有效触发

**依赖关系**：
- 依赖Phase 0的LLM Gateway和基础对话能力
- P0-07是所有P0需求的前置——定义了对话流程框架

---

#### Sprint 1-2：聚焦+记忆（W7-W8）

**Sprint目标**：方向聚焦引导流程上线，用户画像与记忆系统基础可用，创意可自动标记。

**具体需求**：
| 编号 | 需求 | 估算 |
|------|------|------|
| P0-02 | 方向聚焦引导流程 | 4人周 |
| P0-04 | 用户画像与记忆基础 | 4人周 |
| — | 创意自动标记 | 1人周 |

**技术任务**：
- 方向收敛流程：想法收集→三维矩阵映射→Top3排序→决策引导→锁定承诺
- "热情×能力×市场"评估矩阵前端组件
- 遗憾最小化框架辅助决策逻辑
- 用户画像数据模型实现（UserProfile结构）
- 三层记忆架构：短期（Redis）、中期（MongoDB摘要）、长期（用户画像）
- 记忆提取：对话结束后自动提取关键信息
- 记忆召回：对话时根据话题召回相关记忆
- 创意自动标记：对话中识别"创意点"并高亮提示保存

**验收标准**：
- [ ] 用户可在3-5轮对话内从"模糊想法"收敛到"1-2个具体方向"
- [ ] 方向锁定后自动保存至创意库和知识图谱（基础结构）
- [ ] 跨会话记忆引用准确率>80%
- [ ] 创意自动标记提示出现在>60%的创意点

**依赖关系**：
- P0-02依赖P0-01（对话引擎需支持聚焦期策略）
- P0-04依赖Sprint 0-2的数据模型定义
- 创意标记是P0-06的前置能力

**核心信息**：创路 Agent 切入"创业方向选择"这一被忽视的高价值场景，在AI Agent窗口期快速建立壁垒。

### 6.2 工程版本

**核心信息**：五层架构清晰，AI层抽象良好支持模型替换，数据层多引擎各有分工。

| 关注点 | 关键信息 |
|--------|---------|
| **架构** | 五层架构：交互层(Next.js/Taro)→体验层→能力层→智能层→数据层 |
| **后端** | FastAPI(Python) + NestJS(Node.js) 双栈；AI生态友好 + 前端BFF友好 |
| **AI层** | LLM Gateway统一管理多模型；Prompt版本化+A/B测试；上下文管理+Token优化 |
| **数据层** | PostgreSQL(用户/会话) + MongoDB(对话/非结构化) + Neo4j(知识图谱) + Milvus(向量检索) + Redis(缓存/状态) |
| **接口定义** | BFF层提供统一API，Phase 0-2冻结核心接口；Phase 3开放API |
| **数据模型** | UserProfile/Session/Message/Entity/Relation/Idea 六大核心模型，Phase 0冻结 |
| **关键技术挑战** | ①Prompt工程效果稳定性 ②Neo4j+Milvus运维复杂度 ③私有模型微调成本 ④10万级并发性能 |

### 6.3 设计版本

**核心信息**：产品人格是"创业搭子"——温暖、平等、懂你，不是冰冷的工具。

| 关注点 | 关键信息 |
|--------|---------|
| **产品人格** | "创业搭子"——平级伙伴、温暖鼓励、主动关心；不是导师、不是工具 |
| **语言体系** | 优先用"做自己的事""探索方向"替代"创业"；不说"加油"说"你已经迈出了第一步" |

## 7. 关键里程碑与决策点

### 7.1 里程碑时间线

```
W0 ─── W4 ─── W12 ─── W24 ─── W40
 │       │       │        │        │
 │    M1:基础    M2:MVP   M3:增长   M4:规模
 │    能力验证   内测上线  公测+收费  10万用户
 │                │        │        │
 │            ★D1      ★D2      ★D3
```

### 7.2 关键决策点

#### ★ D1：MVP内测数据评估（W12）

**决策内容**：MVP内测数据是否支持继续进入Phase 2？

| 判断标准 | GO（继续） | PIVOT（调整） | STOP（暂停） |
|---------|-----------|-------------|-------------|
| M3留存率（内测） | >35% | 25-35% | <25% |
| 日均对话轮次 | >4轮 | 2-4轮 | <2轮 |
| 方向锁定完成率 | >50% | 30-50% | <30% |
| 内测NPS | >30 | 0-30 | <0 |

**备选方案**：
- **GO**：按原计划进入Phase 2
- **PIVOT-对话优化**：对话质量不够→增加Prompt工程投入，Phase 2前2周专注优化
- **PIVOT-场景调整**：方向聚焦不够→调整目标用户或缩小场景范围
- **STOP**：核心假设不成立→复盘数据，决定是否重新定位或暂停项目

#### ★ D2：付费验证评估（W24）

**决策内容**：公测数据是否验证付费模式可行？

| 判断标准 | GO（扩大投入） | PIVOT（调整定价） | STOP（重新思考商业模式） |
|---------|-------------|---------------|----------------------|
| 付费转化率 | >5% | 2-5% | <2% |
| DAU/MAU | >20% | 15-20% | <15% |
| 用户LTV估算 | >3×CAC | 1.5-3×CAC | <1.5×CAC |
| M3留存率 | >45% | 35-45% | <35% |

**备选方案**：
- **GO**：按原计划进入Phase 3，扩大运营投入
- **PIVOT-降价**：转化率低但留存好→降价/延长试用期/增加免费版权益
- **PIVOT-提价**：转化率可但ARPU低→提升专业版价值（加知识图谱/深度分析）
- **PIVOT-免费增值**：付费意愿极低→转免费增值模式，通过API/企业版收费
- **STOP**：商业模式不成立→探索B端或To VC模式

#### ★ D3：规模化评估（W36）

**决策内容**：是否继续投入Phase 3后半段（协作/API/语音/国际化）？

| 判断标准 | GO | PIVOT | STOP |
|---------|-----|-------|------|
| MAU | >5万 | 2-5万 | <2万 |
| 付费用户数 | >3000 | 1000-3000 | <1000 |
| M3留存率 | >50% | 40-50% | <40% |
| 用户增长趋势 | 稳定增长 | 增长放缓 | 负增长 |

**备选方案**：
- **GO**：继续生态扩展
- **PIVOT-聚焦**：增长放缓→收缩战线，聚焦核心功能优化而非扩展
- **PIVOT-转型**：用户规模不够→考虑B端转型或被收购
- **STOP**：核心指标不达标→有序收缩

### 7.3 Phase内决策点

| 时间点 | 决策内容 | 判断标准 | 影响 |
|--------|---------|---------|------|
| W4 | LLM选型确认 | 国产模型在创业场景的表现是否达标 | 影响Phase 1的Prompt工程策略和成本 |

| R3 | **用户付费意愿低**——91%用户只付一个AI产品 | 高 | 高 | Phase 2 | ①免费版给足体验（5次/天）建立信任 ②付费版提供不可替代价值（知识图谱+专属模型） ③"这不是AI工具，是你的创业伙伴"定位 ④年度版降低月均成本 |

| R9 | **知识图谱冷启动失败** | 中 | 中 | Phase 2 | ①首次引导对话专门设计为图谱构建 ②图谱节点门槛降低至5个即可展示 ③未达到阈值时用列表视图替代 |
| R10 | **规模化后对话质量下降** | 中 | 高 | Phase 3 | ①持续Prompt优化和A/B测试 ②用户反馈闭环机制 ③质量监控系统 ④AI+人工审核 |
